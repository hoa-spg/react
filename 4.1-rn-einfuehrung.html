1 — Was ist React Native?

React Native ist ein Framework von Meta (ehemals Facebook), mit dem man native mobile Apps für iOS und Android mit JavaScript und React schreiben kann. Im Gegensatz zu WebViews oder Hybrid-Lösungen rendert React Native echte, native Platform-Komponenten: auf iOS wird eine View-Komponente zu einem UIView, auf Android zu einem android.view.View. Das Ergebnis ist eine App, die sich wie eine „echte“ App anfühlt – keine Browser-Emulation.

Das Entscheidende: Dein gesamtes React-Wissen überträgt sich direkt. JSX, Props, State, Hooks, Context – alles identisch. Was sich ändert, sind ausschließlich die primitiven Bausteine (die Komponenten) und das Styling-System.

React (Web) vs. React Native – Vergleich

Konzept React (Web) React Native
Container-Element div View
Text anzeigen p, span, h1 Text
Bild anzeigen img Image
Texteingabe input TextInput
Lange Listen ul + .map() FlatList
Styling CSS (Klassen, Kaskade) StyleSheet.create() (kein CSS)
Navigation/Routing React Router React Navigation
ℹ
JSX, Props, State und Hooks sind identisch

Alles, was du in Lektion 1–15 gelernt hast, funktioniert in React Native genauso. useState, useEffect, useContext, Custom Hooks – kein einziges Konzept musst du neu lernen. Du tauschst nur div gegen View und CSS gegen StyleSheet.

Wie funktioniert React Native intern?

React Native verwendet eine sogenannte „Bridge“ (oder in neueren Versionen die JSI – JavaScript Interface), um zwischen dem JavaScript-Thread und dem nativen UI-Thread zu kommunizieren. Dein JavaScript-Code beschreibt den gewünschten UI-Zustand, und React Native übersetzt diesen in native Aufrufe. Das Ergebnis: flotte, nativ wirkende Animationen und Gesten ohne Kompromisse.

2 — Expo einrichten

Für den Einstieg in React Native ist Expo die empfohlene Wahl. Expo ist ein Framework und eine Plattform rund um React Native, das die Einrichtung dramatisch vereinfacht: kein Xcode (außer für native Builds), kein Android Studio, keine komplexe Build-Konfiguration. Du schreibst TypeScript, speicherst die Datei – und die App auf deinem Smartphone aktualisiert sich sofort.

ℹ
Expo Go – Dein Entwicklungs-Companion

Installiere Expo Go aus dem iOS App Store oder dem Google Play Store auf deinem Smartphone. Scanns dann einfach den QR-Code, der beim Start des Entwicklungsservers erscheint – und deine App läuft direkt auf deinem echten Gerät. Kein Kabel, kein Emulator nötig.

4 — Core Components: View, Text, StyleSheet

Die drei wichtigsten Grundbausteine in React Native sind View, Text und StyleSheet. Jede React-Native-App besteht im Kern aus diesen Bausteinen.

View — Der universelle Container

View ist das Äquivalent zu div im Web. Es ist ein rechteckiger Container, der andere Views und Komponenten aufnehmen kann. Views unterstützen Flexbox-Layout, Styling und Touch-Events.

Text — Pflicht für jeden String

Anders als im Web muss jeder angezeigte Text in einer Text-Komponente stehen. Strings direkt in einer View zu platzieren führt zu einem Laufzeitfehler. Text-Komponenten können verschachtelt werden und erben dann den Stil der äußeren Text-Komponente.

StyleSheet.create() — Styling in React Native

In React Native gibt es kein CSS. Styling erfolgt über JavaScript-Objekte. Dabei gelten wichtige Unterschiede zum Web:

  • Alle Zahlenwerte sind einheitenlos – fontSize: 16 statt '16px'
  • Eigenschaftsnamen sind camelCase – backgroundColor statt background-color
  • Es gibt keine Kaskade oder Vererbung (außer bei verschachtelten Text-Komponenten)
  • flexDirection ist standardmäßig 'column', nicht 'row'
  • Maße werden in „density-independent pixels“ (dp/pt) angegeben, nicht in physischen Pixeln
App.tsx TypeScript 
import { View, Text, StyleSheet, StatusBar } from 'react-native';

export default function App() {
  return (
    // View mit flex: 1 = nimmt den gesamten verfügbaren Platz ein
    <View style={styles.container}>
      {/*
        StatusBar steuert die Systemleiste (Uhrzeit, Akku etc.)
        barStyle="light-content" = weißer Text auf dunklem Hintergrund
      */}
      <StatusBar barStyle="light-content" backgroundColor="#0d1117" />

      <Text style={styles.title}>✈ FlugBoard</Text>
      <Text style={styles.subtitle}>Flughafen Wien-Schwechat</Text>
      <Text style={styles.version}>Version 1.0.0</Text>
    </View>
  );
}

// StyleSheet.create() validiert die Styles zur Laufzeit und
// optimiert die Performance durch Caching der Style-Objekte.
// WICHTIG: StyleSheet.create() außerhalb der Komponente definieren!
const styles = StyleSheet.create({
  container: {
    flex: 1,                      // nimmt die gesamte Bildschirmhöhe ein
    backgroundColor: '#0d1117',   // dunkles Hintergrundthema
    alignItems: 'center',         // horizontal zentrieren (Hauptachse = column)
    justifyContent: 'center',     // vertikal zentrieren
    paddingHorizontal: 24,
  },
  title: {
    fontSize: 28,                 // Zahlenwert ohne Einheit!
    fontWeight: 'bold',
    color: '#61dafb',             // React-Blau
    marginBottom: 8,
    letterSpacing: 1,
  },
  subtitle: {
    fontSize: 16,
    color: '#8b949e',
    marginBottom: 4,
  },
  version: {
    fontSize: 12,
    color: '#484f58',
    marginTop: 32,
  },
});
ℹ
flex: 1 – Die häufigste Falle

Ohne flex: 1 auf dem Wurzel-View hat die App keine definierte Höhe und zeigt möglicherweise gar nichts an. Immer sicherstellen, dass der Root-Container flex: 1 hat.

Styling-Regeln auf einen Blick

styling-vergleich.ts TypeScript 
// ❌ Falsch – CSS-Syntax funktioniert NICHT in React Native
const wrongStyle = {
  'font-size': '16px',          // Bindestriche verboten
  'background-color': '#fff',   // camelCase erforderlich
  width: '100%',                // Prozentwerte teilweise nicht unterstützt
  border: '1px solid red',      // Shorthand-Properties existieren nicht
};

// ✅ Richtig – React Native StyleSheet-Syntax
const correctStyle = StyleSheet.create({
  box: {
    fontSize: 16,               // Zahl, keine Einheit
    backgroundColor: '#fff',    // camelCase
    width: '100%',              // Prozent funktioniert für width/height
    borderWidth: 1,             // Kein Shorthand, einzelne Properties
    borderColor: 'red',
    borderStyle: 'solid',
  },
});

5 — TouchableOpacity – Buttons in React Native

In React Native gibt es keinen button-Tag. Für tippbare Elemente verwendet man TouchableOpacity, das beim Drücken die Deckkraft reduziert und so visuelles Feedback gibt. Für komplexere Gesten-Szenarien steht auch Pressable zur Verfügung (ab React Native 0.63).

components/RefreshButton.tsx TypeScript 
import {
  TouchableOpacity,
  Text,
  StyleSheet,
  Alert,
  View,
} from 'react-native';

interface RefreshButtonProps {
  onRefresh: () => void;
  isLoading: boolean;
}

export function RefreshButton({ onRefresh, isLoading }: RefreshButtonProps) {
  const handlePress = () => {
    // Alert.alert() zeigt einen nativen Dialog an
    Alert.alert(
      'Aktualisieren',                        // Titel
      'Flugdaten wirklich neu laden?',        // Nachricht
      [
        {
          text: 'Abbrechen',
          style: 'cancel',                    // iOS: blaue Schrift
        },
        {
          text: 'Aktualisieren',
          style: 'default',
          onPress: onRefresh,                 // Callback bei Bestätigung
        },
      ],
      { cancelable: true }                    // Android: Tippen außerhalb schließt Dialog
    );
  };

  return (
    <View style={styles.wrapper}>
      {/* activeOpacity: Wert zwischen 0 (unsichtbar) und 1 (kein Feedback) */}
      <TouchableOpacity
        style={[
          styles.button,
          isLoading && styles.buttonDisabled,  // Bedingtes Styling via Array
        ]}
        onPress={handlePress}
        activeOpacity={0.7}
        disabled={isLoading}                  // Deaktiviert Touch-Events
        accessibilityLabel="Flugdaten aktualisieren"
        accessibilityRole="button"
      >
        <Text style={[styles.label, isLoading && styles.labelDisabled]}>
          {isLoading ? 'Lädt...' : '↻ Aktualisieren'}
        </Text>
      </TouchableOpacity>
    </View>
  );
}

const styles = StyleSheet.create({
  wrapper: {
    paddingHorizontal: 16,
    paddingVertical: 8,
  },
  button: {
    backgroundColor: '#21262d',
    borderWidth: 1,
    borderColor: '#30363d',
    borderRadius: 8,
    paddingVertical: 12,
    paddingHorizontal: 20,
    alignItems: 'center',
  },
  buttonDisabled: {
    opacity: 0.5,
  },
  label: {
    color: '#61dafb',
    fontSize: 15,
    fontWeight: '600',
  },
  labelDisabled: {
    color: '#8b949e',
  },
});

Bedingtes Styling – Style-Arrays

In React Native kann man mehrere Styles als Array übergeben. Spätere Einträge im Array überschreiben frühere (wie CSS-Spezifizität, aber einfacher). false, null und undefined werden ignoriert – ideal für bedingtes Styling.

bedingtes-styling.tsx TypeScript 
// Style-Array: Basis-Style + optionaler Override-Style
<View style={[styles.card, isSelected && styles.cardSelected]}>

// Mehrere bedingte Styles kombinieren
<Text
  style={[
    styles.statusText,
    status === 'delayed' && styles.statusDelayed,
    status === 'cancelled' && styles.statusCancelled,
    status === 'boarding' && styles.statusBoarding,
  ]}
>
  {statusLabel}
</Text>

6 — Platform.OS – Plattformspezifisches Verhalten

React Native läuft auf iOS und Android, und beide Plattformen haben unterschiedliche Design-Konventionen und APIs. Das Platform-Modul erlaubt es, plattformspezifischen Code zu schreiben.

components/Card.tsx TypeScript 
import { Platform, StyleSheet, View } from 'react-native';

// Platform.OS gibt 'ios', 'android' oder 'web' zurück
const isIOS = Platform.OS === 'ios';
const isAndroid = Platform.OS === 'android';

export function Card({ children }: { children: React.ReactNode }) {
  return <View style={styles.card}>{children}</View>;
}

const styles = StyleSheet.create({
  card: {
    backgroundColor: '#161b22',
    borderRadius: 12,
    padding: 16,
    // Platform.select() – eleganter als If/Else
    // iOS: box-shadow über shadow*-Properties
    // Android: Schatten über elevation
    ...Platform.select({
      ios: {
        shadowColor: '#000',
        shadowOffset: { width: 0, height: 2 },
        shadowOpacity: 0.3,
        shadowRadius: 4,
      },
      android: {
        elevation: 4,       // Android-Schatten (0–24)
      },
      default: {},          // Web / andere Plattformen
    }),
  },
});

// Platform.OS für bedingte Werte direkt im StyleSheet
const statusBarHeight = StyleSheet.create({
  header: {
    paddingTop: Platform.OS === 'ios' ? 44 : 24,  // iOS Notch / Android Status Bar
  },
});
ℹ
Plattformspezifische Dateien

Für größere Unterschiede kann man Dateien mit dem Suffix .ios.tsx oder .android.tsx anlegen. React Native lädt automatisch die richtige Datei: Button.ios.tsx auf iOS, Button.android.tsx auf Android, Button.tsx als Fallback. Ideal für komplett unterschiedliche UI-Muster auf den Plattformen.

useColorScheme – Systemthema erkennen

App.tsx (Dark Mode) TypeScript 
import { useColorScheme } from 'react-native';

export default function App() {
  // Gibt 'dark', 'light' oder null zurück
  const colorScheme = useColorScheme();
  const isDark = colorScheme === 'dark';

  return (
    <View
      style={[
        styles.container,
        { backgroundColor: isDark ? '#0d1117' : '#ffffff' },
      ]}
    >
      <Text style={{ color: isDark ? '#e6edf3' : '#24292f' }}>
        Flughafen Wien-Schwechat
      </Text>
    </View>
  );
}

Häufige Fehler

Fehler: HTML-Elemente in React Native verwendet

Der Fehler „div is not a valid React Native component“ tritt auf, wenn man HTML-Tags wie div, p, button, span oder ul in React Native verwendet. Diese existieren im nativen Kontext schlicht nicht.

Fix: Alle HTML-Elemente durch ihre React-Native-Äquivalente ersetzen: div → View, p/span → Text, button → TouchableOpacity, ul/li + .map() → FlatList, img → Image.

Fehler: Text-String außerhalb einer Text-Komponente

„Text strings must be rendered within a <Text> component“ – dieser Fehler erscheint, wenn ein String direkt in einem View oder einer anderen Nicht-Text-Komponente steht, z.B. <View>{'Hallo'}</View>. React Native erzwingt konsequent, dass jeder anzuzeigende Text in einer Text-Komponente gekapselt ist.

Fix: Jeden anzuzeigenden String in <Text>...</Text> einschließen. Auch JSX-Ausdrücke wie {condition && 'Text'} müssen innerhalb von Text stehen.

Fehler: Einheitenwerte in StyleSheet-Properties

„fontSize value must be a number, not a string“ oder ähnliche Fehlermeldungen entstehen, wenn man CSS-Einheiten wie px, em, rem oder % verwendet: fontSize: '16px' ist in React Native ungültig.

Fix: Alle numerischen Style-Werte als reine Zahlen angeben: fontSize: 16, marginTop: 8, borderRadius: 4. Ausnahme: width und height akzeptieren auch Prozentstrings wie '100%' oder '50%'.

Fehler: flex: 1 auf dem Root-Container vergessen

Die App zeigt einen weißen Bildschirm oder nur einen winzigen Inhaltstreifen, obwohl der Code korrekt aussieht. Das passiert, wenn der Wurzel-Container keinen definierten Platz einnimmt. Ohne flex: 1 (oder eine explizite height) hat das Root-View keine Höhe, weil React Native – anders als der Browser – keine automatische Blockhöhe berechnet.

Fix: Den Root-Container immer mit flex: 1 versehen: style={{ flex: 1, backgroundColor: '#0d1117' }}. Zusätzlich sollten auch NavigationContainer und Screen-Wrapper flex: 1 haben.
