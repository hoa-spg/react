React Native ca. 90 min

Lernziele

  • React Native als Technologie für mobile Apps verstehen

  • Expo einrichten und ein erstes Projekt erstellen

1 — Was ist React Native?

React Native ist ein Framework von Meta (ehemals Facebook), mit dem man native mobile Apps für iOS und Android mit JavaScript und React schreiben kann. Im Gegensatz zu WebViews oder Hybrid-Lösungen rendert React Native echte, native Platform-Komponenten: auf iOS wird eine View-Komponente zu einem UIView, auf Android zu einem android.view.View. Das Ergebnis ist eine App, die sich wie eine „echte“ App anfühlt – keine Browser-Emulation.

Das Entscheidende: Dein gesamtes React-Wissen überträgt sich direkt. JSX, Props, State, Hooks, Context – alles identisch. Was sich ändert, sind ausschließlich die primitiven Bausteine (die Komponenten) und das Styling-System.

React (Web) vs. React Native – Vergleich

Konzept React (Web) React Native
Container-Element div View
Text anzeigen p, span, h1 Text
Bild anzeigen img Image
Texteingabe input TextInput
Lange Listen ul + .map() FlatList
Styling CSS (Klassen, Kaskade) StyleSheet.create() (kein CSS)
Navigation/Routing React Router React Navigation
ℹ
JSX, Props, State und Hooks sind identisch

Alles, was du in den Teilen 1–3 gelernt hast, funktioniert in React Native genauso. useState, useEffect, useContext, Custom Hooks – kein einziges Konzept musst du neu lernen. Du tauschst nur div gegen View und CSS gegen StyleSheet.

Wie funktioniert React Native intern?

Dein JavaScript-Code beschreibt wie gewohnt, wie die Oberfläche aussehen soll. React Native übersetzt das in Aufrufe der nativen UI von iOS bzw. Android. Seit Version 0.76 geschieht das über die neue Architektur: JavaScript ruft nativen Code über das JSI (JavaScript Interface) direkt auf – die frühere, langsamere „Bridge“ ist weggefallen.

2 — Expo einrichten

Für den Einstieg in React Native ist Expo die empfohlene Wahl. Expo ist ein Framework rund um React Native, das die Einrichtung stark vereinfacht: kein Xcode, kein Android Studio, keine Build-Konfiguration. Du schreibst TypeScript, speicherst die Datei – und die App auf deinem Smartphone aktualisiert sich sofort.

ℹ
Expo Go – die App zum Testen

Installiere Expo Go aus dem App Store bzw. Google Play Store. Expo Go öffnet Projekte der jeweils aktuellen Expo-Version (dieser Kurs: SDK 58). Deshalb das Projekt immer mit create-expo-app@latest anlegen.

Projekt anlegen

Terminal Bash 
# Neues Expo-Projekt mit TypeScript-Vorlage erstellen
npx create-expo-app@latest flugboard-mobile --template blank-typescript

cd flugboard-mobile

# Entwicklungsserver starten
npx expo start
# › QR-Code mit Expo Go (Android) bzw. der Kamera-App (iOS) scannen
# › w = im Browser öffnen
# › a / i = Android-Emulator / iOS-Simulator (falls installiert)

Nach npx expo start erscheint ein QR-Code im Terminal. Scanne ihn mit dem Smartphone – die App öffnet sich in Expo Go. Jede Änderung im Code lädt die App automatisch neu (Fast Refresh). Smartphone und Computer müssen dazu im selben WLAN sein.

4 — Core Components: View, Text, StyleSheet

Die drei wichtigsten Grundbausteine in React Native sind View, Text und StyleSheet.

View — der universelle Container

View entspricht div im Web: ein rechteckiger Container für andere Komponenten, mit Flexbox-Layout und Styling.

Text — Pflicht für jeden String

Anders als im Web muss jeder angezeigte Text in einer Text-Komponente stehen. Ein String direkt in einer View führt zu einem Laufzeitfehler.

StyleSheet.create() — Styling ohne CSS

In React Native gibt es kein CSS. Styles sind JavaScript-Objekte, mit einigen Unterschieden zum Web:

  • Zahlen ohne Einheit – fontSize: 16 statt '16px'
  • Namen in camelCase – backgroundColor statt background-color
  • Keine Kaskade und keine Vererbung (außer bei verschachtelten Text-Komponenten)
  • Jede View ist ein Flex-Container, flexDirection ist standardmäßig 'column'

Die Vorlagen-App.tsx im FlugBoard-Design:

App.tsx TypeScript 
import { StatusBar } from 'expo-status-bar';
import { StyleSheet, Text, View } from 'react-native';

export default function App() {
  return (
    // View mit flex: 1 nimmt den ganzen Bildschirm ein
    <View style={styles.container}>
      {/* style="light": helle Uhrzeit und Akku-Anzeige auf dunklem Hintergrund */}
      <StatusBar style="light" />
      <Text style={styles.title}>✈ FlugBoard</Text>
      <Text style={styles.subtitle}>Flughafen Wien-Schwechat</Text>
    </View>
  );
}

// StyleSheet.create() außerhalb der Komponente: wird nur einmal erzeugt
const styles = StyleSheet.create({
  container: {
    flex: 1,                    // gesamte Bildschirmhöhe
    backgroundColor: '#0d1117',
    alignItems: 'center',       // horizontal zentrieren
    justifyContent: 'center',   // vertikal zentrieren
  },
  title: {
    fontSize: 28,               // Zahl ohne Einheit!
    fontWeight: 'bold',
    color: '#61dafb',
  },
  subtitle: {
    fontSize: 16,
    color: '#8b949e',
  },
});
ℹ
flex: 1 – die häufigste Falle

Ohne flex: 1 ist der äußerste View nur so hoch wie sein Inhalt – der dunkle Hintergrund füllt dann nicht den Bildschirm.

Styling-Regeln im Vergleich TypeScript 
// ❌ Falsch – CSS-Syntax funktioniert in React Native nicht
const wrongStyle = {
  'font-size': '16px',          // Bindestriche und Einheiten verboten
  border: '1px solid red',      // Kurzschreibweisen wie border gibt es nicht
};

// ✅ Richtig – React-Native-Syntax
const styles = StyleSheet.create({
  box: {
    fontSize: 16,               // camelCase, Zahl ohne Einheit
    borderWidth: 1,             // jede Eigenschaft einzeln
    borderColor: 'red',
    width: '100%',              // Prozent geht als String
  },
});

SafeAreaView — Abstand zu Notch und Statusleiste

Moderne Smartphones haben Bereiche, in denen Inhalt verdeckt wäre: Notch, Kamera-Loch, Statusleiste, Home-Balken. SafeAreaView aus dem Paket react-native-safe-area-context funktioniert wie View, fügt aber automatisch den nötigen Innenabstand hinzu.

Terminal Bash 
npx expo install react-native-safe-area-context

npx expo install funktioniert wie npm install, wählt aber die Version, die zur Expo-Version des Projekts passt.

Verwendung TypeScript 
import { SafeAreaProvider, SafeAreaView } from 'react-native-safe-area-context';

export default function App() {
  return (
    // einmal ganz außen: stellt die Maße der sicheren Bereiche bereit
    <SafeAreaProvider>
      {/* wie View, hält aber Abstand zu Notch und Statusleiste */}
      <SafeAreaView style={{ flex: 1, backgroundColor: '#0d1117' }}>
        {/* ... Inhalt ... */}
      </SafeAreaView>
    </SafeAreaProvider>
  );
}

ScrollView — scrollbarer Inhalt

Im Browser scrollt eine Seite automatisch. In React Native nicht: Inhalt, der nicht auf den Bildschirm passt, ist einfach abgeschnitten. ScrollView ist ein View, dessen Inhalt man scrollen kann. Für ein paar Dutzend Elemente reicht das; für lange Listen gibt es FlatList (Lektion 4.2).

5 — TouchableOpacity – Buttons in React Native

Ein button-Element gibt es nicht. Für tippbare Elemente verwendet man TouchableOpacity: Beim Drücken wird der Inhalt durchsichtiger und gibt so sichtbares Feedback. Statt onClick heißt das Ereignis onPress.

Button mit Dialog TypeScript 
import { Alert, Text, TouchableOpacity } from 'react-native';

const handleRefresh = () => {
  // Alert.alert(Titel, Nachricht) zeigt einen nativen Dialog
  Alert.alert('FlugBoard', 'Daten werden aktualisiert...');
};

// in der Komponente:
<TouchableOpacity style={styles.refreshButton} onPress={handleRefresh} activeOpacity={0.7}>
  <Text style={styles.refreshButtonText}>Aktualisieren</Text>
</TouchableOpacity>
  • activeOpacity: Deckkraft beim Drücken, zwischen 0 (unsichtbar) und 1 (keine Änderung).
  • Alert.alert() ist das Gegenstück zu alert() im Browser, aber mit dem nativen Dialog von iOS bzw. Android.
  • Moderner und flexibler ist Pressable; für einfache Buttons reicht TouchableOpacity.

Bedingtes Styling mit Style-Arrays

Statt eines Objekts kann man style ein Array übergeben. Spätere Einträge überschreiben frühere; false, null und undefined werden ignoriert. So lässt sich ein Style mit && nur unter einer Bedingung hinzufügen:

Style-Array TypeScript 
// Basis-Style plus Zusatz-Style, wenn die Bedingung erfüllt ist
<Text style={[styles.time, flight.status === 'cancelled' && styles.cancelled]}>
  {flight.scheduledTime}
</Text>

6 — Platform – Unterschiede zwischen iOS und Android

iOS und Android unterscheiden sich in manchen Details — zum Beispiel bei Schatten. Das Modul Platform erlaubt plattformspezifischen Code.

Schatten je nach Plattform TypeScript 
import { Platform, StyleSheet } from 'react-native';

// Platform.OS ist 'ios', 'android' oder 'web'
const isIOS = Platform.OS === 'ios';

// Platform.select() wählt den passenden Wert für die aktuelle Plattform
const shadowStyle = Platform.select({
  ios: { shadowColor: '#000', shadowOffset: { width: 0, height: 2 }, shadowOpacity: 0.3, shadowRadius: 4 },
  android: { elevation: 4 },   // Android kennt nur elevation
  default: {},                  // Web und andere
});

const styles = StyleSheet.create({
  card: {
    backgroundColor: '#1c2128',
    ...shadowStyle,             // Spread: Schatten-Eigenschaften einfügen
  },
});

...shadowStyle ist der Spread-Operator für Objekte: Er fügt alle Eigenschaften von shadowStyle in das card-Objekt ein.

Häufige Fehler

4 Fehler · zum Aufklappen klicken
Fehler: HTML-Elemente in React Native verwendet

Der Fehler „div is not a valid React Native component“ tritt auf, wenn man HTML-Tags wie div, p, button, span oder ul in React Native verwendet. Diese existieren im nativen Kontext schlicht nicht.

Fix: Alle HTML-Elemente durch ihre React-Native-Äquivalente ersetzen: div → View, p/span → Text, button → TouchableOpacity, ul/li + .map() → FlatList, img → Image.

Fehler: Text-String außerhalb einer Text-Komponente

„Text strings must be rendered within a <Text> component“ – dieser Fehler erscheint, wenn ein String direkt in einem View oder einer anderen Nicht-Text-Komponente steht, z.B. <View>{'Hallo'}</View>. React Native erzwingt konsequent, dass jeder anzuzeigende Text in einer Text-Komponente gekapselt ist.

Fix: Jeden anzuzeigenden String in <Text>...</Text> einschließen. Auch JSX-Ausdrücke wie {condition && 'Text'} müssen innerhalb von Text stehen.

Fehler: Einheitenwerte in StyleSheet-Properties

„fontSize value must be a number, not a string“ oder ähnliche Fehlermeldungen entstehen, wenn man CSS-Einheiten wie px, em, rem oder % verwendet: fontSize: '16px' ist in React Native ungültig.

Fix: Alle numerischen Style-Werte als reine Zahlen angeben: fontSize: 16, marginTop: 8, borderRadius: 4. Ausnahme: width und height akzeptieren auch Prozentstrings wie '100%' oder '50%'.

Fehler: flex: 1 auf dem Root-Container vergessen

Die App zeigt einen weißen Bildschirm oder nur einen winzigen Inhaltstreifen, obwohl der Code korrekt aussieht. Das passiert, wenn der Wurzel-Container keinen definierten Platz einnimmt. Ohne flex: 1 (oder eine explizite height) hat das Root-View keine Höhe, weil React Native – anders als der Browser – keine automatische Blockhöhe berechnet.

Fix: Den Root-Container immer mit flex: 1 versehen: style={{ flex: 1, backgroundColor: '#0d1117' }}.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was unterscheidet React Native von einer Web-App in einer mobilen Hülle?

Erklärung: Der JavaScript-Code beschreibt die Oberfläche; React Native erzeugt daraus native Bedienelemente.

Frage 2 Welche Konzepte aus den Teilen 1–3 funktionieren in React Native unverändert?

Mehrere Antworten sind richtig.

Erklärung: Neu sind nur die Basiselemente (View, Text, Image …) und das Styling mit StyleSheet-Objekten.

Frage 3 Was ersetzt in React Native das <div>?

Erklärung: Weitere Entsprechungen: p/span → Text, button → TouchableOpacity, img → Image.

Frage 4 Was löst den Fehler „Text strings must be rendered within a <Text> component“ aus?

Erklärung: React Native verlangt, dass jeder angezeigte Text in einer Text-Komponente steht.

Frage 5 Wozu dient Expo Go?

Erklärung: Mit Expo braucht man für den Einstieg weder Xcode noch Android Studio. Die Expo-Version des Projekts muss zur installierten Expo Go passen.
