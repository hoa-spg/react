1 — React Navigation installieren

React Native hat keine eingebaute Navigation – anders als React Router im Web muss man sie separat installieren. React Navigation ist die Standardlösung: battle-tested, aktiv gepflegt, vollständig typisiert und von Expo offiziell unterstützt.

Terminal Bash 
# Kern-Bibliothek von React Navigation
npx expo install @react-navigation/native

# Bottom-Tab-Navigator (die Tab-Leiste am unteren Bildschirmrand)
npx expo install @react-navigation/bottom-tabs

# Stack-Navigator (Push/Pop zwischen Screens wie im Browser)
npx expo install @react-navigation/native-stack

# Pflicht-Abhängigkeiten für native Animationen und Safe-Area-Handling
npx expo install react-native-screens react-native-safe-area-context
ℹ
npx expo install statt npm install

Für Expo-Projekte immer npx expo install (nicht npm install) verwenden. Der Expo-Paketmanager wählt automatisch die Versionen, die mit der installierten Expo-Version kompatibel sind. npm install kann zu Versions-Konflikten führen, die schwer zu debuggen sind.

React Router vs. React Navigation – Vergleich

Die Konzepte sind ähnlich, die API jedoch unterschiedlich. Diese Tabelle hilft beim Transfer des Wissens aus Lektion 2.7 (React Router):

React Router (Web, L10) React Navigation (Mobile)
BrowserRouter NavigationContainer
Routes + Route Stack.Navigator + Stack.Screen
<Link to="/detail"> navigation.navigate('Detail')
useParams() route.params (via useRoute())
useNavigate() useNavigation()
navigate(-1) (zurück) navigation.goBack()
Browser-History (URL-basiert) Stack (in-memory, keine URL)

2 — Tab-Navigator einrichten

Der Tab-Navigator rendert eine Leiste am unteren Bildschirmrand (iOS) oder oben (Android, konfigurierbar). Jeder Tab hat einen eigenen Navigations-Stack. Das Umschalten zwischen Tabs ist sofort – der State jedes Tabs bleibt erhalten, selbst wenn der Nutzer zwischen Tabs wechselt.

App.tsx TypeScript 
import { NavigationContainer } from '@react-navigation/native';
import { createBottomTabNavigator } from '@react-navigation/bottom-tabs';
import { Text } from 'react-native';

// Platzhalter-Screens (werden in Abschnitt 3 durch echte Stack-Navigatoren ersetzt)
import { DepartureStackNavigator } from './src/navigation/DepartureStack';
import { ArrivalStackNavigator } from './src/navigation/ArrivalStack';

// Tab-Navigator-Typ: Name → Props des jeweiligen Screens
// Leere {} bedeutet: kein Param für diesen Tab-Screen
type TabParamList = {
  DepartureTab: undefined;
  ArrivalTab: undefined;
};

const Tab = createBottomTabNavigator<TabParamList>();

export default function App() {
  return (
    // NavigationContainer MUSS die gesamte App umschließen (einmalig!)
    <NavigationContainer>
      <Tab.Navigator
        screenOptions={{
          // Allgemeines Dark-Theme für alle Tabs
          headerStyle: {
            backgroundColor: '#161b22',
          },
          headerTintColor: '#e6edf3',
          headerTitleStyle: {
            fontWeight: '600',
          },
          // Tab-Leiste styling
          tabBarStyle: {
            backgroundColor: '#161b22',
            borderTopColor: '#21262d',
            borderTopWidth: 1,
            height: 60,
            paddingBottom: 8,
            paddingTop: 4,
          },
          tabBarActiveTintColor: '#61dafb',
          tabBarInactiveTintColor: '#8b949e',
          tabBarLabelStyle: {
            fontSize: 12,
            fontWeight: '500',
          },
        }}
      >
        <Tab.Screen
          name="DepartureTab"
          component={DepartureStackNavigator}
          options={{
            title: 'Abflüge',
            headerShown: false,       // Stack-Navigator hat seinen eigenen Header
            tabBarIcon: ({ color, size }) => (
              <Text style={{ color, fontSize: size }}>✈</Text>
            ),
          }}
        />
        <Tab.Screen
          name="ArrivalTab"
          component={ArrivalStackNavigator}
          options={{
            title: 'Ankünfte',
            headerShown: false,
            tabBarIcon: ({ color, size }) => (
              <Text style={{ color, fontSize: size }}>↘</Text>
            ),
          }}
        />
      </Tab.Navigator>
    </NavigationContainer>
  );
}

3 — Stack-Navigator mit TypeScript

Der Stack-Navigator funktioniert wie der Browser-Verlauf: Screens werden „gestapelt“ (gepusht), und der Zurück-Button poppt den obersten Screen vom Stack. Mit TypeScript definieren wir die erlaubten Screen-Namen und ihre Parameter als Typ – das verhindert Tippfehler beim Navigieren und gibt vollständige Autovervollständigung.

navigation/DepartureStack.tsx TypeScript 
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { Flight } from '../types/flight';
import { DepartureListScreen } from '../screens/DepartureListScreen';
import { FlightDetailScreen } from '../screens/FlightDetailScreen';

// ParamList-Typ: definiert alle Screens und ihre erwarteten Parameter.
// undefined = Screen erwartet keine Parameter.
// { flight: Flight } = Screen erwartet ein Flight-Objekt.
export type DepartureStackParamList = {
  DepartureList: undefined;
  FlightDetail: { flight: Flight };
};

const Stack = createNativeStackNavigator<DepartureStackParamList>();

export function DepartureStackNavigator() {
  return (
    <Stack.Navigator
      // Standard-Options gelten für alle Screens in diesem Stack
      screenOptions={{
        headerStyle: {
          backgroundColor: '#161b22',
        },
        headerTintColor: '#e6edf3',
        headerTitleStyle: {
          fontWeight: '600',
          fontSize: 17,
        },
        headerBackTitle: 'Zurück',        // iOS: Text des Zurück-Buttons
        contentStyle: {
          backgroundColor: '#0d1117',    // Hintergrundfarbe der Screen-Animation
        },
        // Animations-Stil: 'default' (iOS: slide), 'fade', 'slide_from_right', etc.
        animation: 'slide_from_right',
      }}
    >
      <Stack.Screen
        name="DepartureList"
        component={DepartureListScreen}
        options={{ title: '✈ Abflüge' }}
      />
      <Stack.Screen
        name="FlightDetail"
        component={FlightDetailScreen}
        // options als Funktion: Zugriff auf route.params für dynamischen Header-Titel
        options={({ route }) => ({
          title: route.params.flight.flightNumber,
          headerBackTitle: 'Abflüge',
        })}
      />
    </Stack.Navigator>
  );
}

// Analog: ArrivalStack (gleiche Struktur, anderer ParamList-Name)
export type ArrivalStackParamList = {
  ArrivalList: undefined;
  FlightDetail: { flight: Flight };
};

// navigation/ArrivalStack.tsx (analog zu DepartureStack, nur Title-Anpassungen)

4 — Navigieren und Parameter übergeben

Mit useNavigation und useRoute greift man in jeder Komponente auf Navigation und Parameter zu – ohne Props „durchreichen“ zu müssen. Der TypeScript-Generic sorgt dabei für typsichere Autovervollständigung.

Von der Liste zum Detail navigieren

screens/DepartureListScreen.tsx TypeScript 
import { useState, useMemo } from 'react';
import { SafeAreaView, StyleSheet } from 'react-native';
import { useNavigation } from '@react-navigation/native';
import { NativeStackNavigationProp } from '@react-navigation/native-stack';

import { DepartureStackParamList } from '../navigation/DepartureStack';
import { FlightList } from '../components/FlightList';
import { SearchBar } from '../components/SearchBar';
import { useFlights } from '../context/FlightContext';

// Typ: Navigationsfunktion für diesen Stack – gibt Typsicherheit bei navigate()
type DepartureListNavProp = NativeStackNavigationProp<
  DepartureStackParamList,
  'DepartureList'   // aktueller Screen-Name
>;

export function DepartureListScreen() {
  // useNavigation mit dem korrekten Typ → navigate() ist typsicher
  const navigation = useNavigation<DepartureListNavProp>();

  // Flüge aus dem Context (Lektion 8-Muster – funktioniert identisch in RN)
  const { departures, isLoading, refetch } = useFlights();

  const [searchQuery, setSearchQuery] = useState('');
  const [refreshing, setRefreshing] = useState(false);

  const filteredFlights = useMemo(
    () =>
      departures.filter(
        (f) =>
          f.flightNumber.toLowerCase().includes(searchQuery.toLowerCase()) ||
          f.destination.toLowerCase().includes(searchQuery.toLowerCase())
      ),
    [departures, searchQuery]
  );

  const handleFlightPress = (flight: Flight) => {
    // TypeScript prüft: 'FlightDetail' ist ein gültiger Screen-Name,
    // und { flight } ist der korrekte Parameter-Typ
    navigation.navigate('FlightDetail', { flight });
  };

  const handleRefresh = async () => {
    setRefreshing(true);
    refetch();
    await new Promise((r) => setTimeout(r, 800));
    setRefreshing(false);
  };

  return (
    <SafeAreaView style={styles.container}>
      <SearchBar
        value={searchQuery}
        onChangeText={setSearchQuery}
        resultCount={filteredFlights.length}
      />
      <FlightList
        flights={filteredFlights}
        onFlightPress={handleFlightPress}
        isLoading={isLoading}
        onRefresh={handleRefresh}
        refreshing={refreshing}
      />
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#0d1117',
  },
});

5 — Verschachtelte Navigation: Tabs + Stacks

Das endgültige Navigations-Setup kombiniert Tab-Navigator (untere Leiste) und Stack-Navigator (Push/Pop) zu einer typischen mobilen App-Struktur. Jeder Tab hat seinen eigenen Stack, sodass der Navigations-Verlauf pro Tab unabhängig ist.

Navigationsbaum der FlugBoard App

Navigationsstruktur (ASCII) Bash 
App
└── FlightProvider (Context)
    └── NavigationContainer
        └── Tab.Navigator (Bottom Tabs)
            ├── DepartureTab
            │   └── DepartureStack (Stack.Navigator)
            │       ├── DepartureList    ← initiale Route
            │       └── FlightDetail     ← nach navigate('FlightDetail', { flight })
            └── ArrivalTab
                └── ArrivalStack (Stack.Navigator)
                    ├── ArrivalList      ← initiale Route
                    └── FlightDetail     ← eigene Instanz! Kein geteilter Stack
ℹ
Separate Stacks für separate Tabs

Beide Tabs haben ihre eigene Instanz des FlightDetailScreen. Das ist kein Fehler, sondern Absicht: Wenn der Nutzer in Tab 1 in ein Flug-Detail navigiert und dann zu Tab 2 wechselt, ist Tab 2 noch auf seiner eigenen Listenansicht. Die Navigations-Historys sind komplett unabhängig voneinander.

6 — FlightContext – Geteilter State

Context in React Native funktioniert exakt genauso wie im Web (Lektion 2.4). Wir erstellen einen FlightContext, der Abflug- und Ankunftsdaten bereitstellt, und beide List-Screens greifen darüber auf dieselbe Datenquelle zu. Der Context wird außerhalb des NavigationContainer platziert, damit alle Screens darauf zugreifen können.

context/FlightContext.tsx TypeScript 
import {
  createContext,
  useContext,
  useState,
  useEffect,
  useCallback,
  ReactNode,
} from 'react';
import { Flight } from '../types/flight';

// Context-Typ: was der Context nach außen anbietet
interface FlightContextValue {
  departures: Flight[];
  arrivals: Flight[];
  isLoading: boolean;
  error: string | null;
  refetch: () => void;
  lastUpdated: Date | null;
}

// 1. Context erstellen (identisch zu Lektion 2.4)
const FlightContext = createContext<FlightContextValue | null>(null);

// 2. Provider-Komponente: verwaltet den State und stellt ihn bereit
export function FlightProvider({ children }: { children: ReactNode }) {
  const [departures, setDepartures] = useState<Flight[]>([]);
  const [arrivals, setArrivals] = useState<Flight[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);
  const [lastUpdated, setLastUpdated] = useState<Date | null>(null);
  const [fetchKey, setFetchKey] = useState(0);

  const refetch = useCallback(() => setFetchKey((k) => k + 1), []);

  useEffect(() => {
    const controller = new AbortController();
    setIsLoading(true);
    setError(null);

    const fetchAll = async () => {
      try {
        // Beide API-Calls parallel mit Promise.all
        const [depResponse, arrResponse] = await Promise.all([
          fetch('http://192.168.1.42:3000/api/flights?type=departures', {
            signal: controller.signal,
          }),
          fetch('http://192.168.1.42:3000/api/flights?type=arrivals', {
            signal: controller.signal,
          }),
        ]);

        if (!depResponse.ok || !arrResponse.ok) {
          throw new Error('Fehler beim Laden der Flugdaten');
        }

        const [depData, arrData] = await Promise.all([
          depResponse.json() as Promise<Flight[]>,
          arrResponse.json() as Promise<Flight[]>,
        ]);

        setDepartures(depData);
        setArrivals(arrData);
        setLastUpdated(new Date());
      } catch (err) {
        if (err instanceof Error && err.name === 'AbortError') return;
        setError(err instanceof Error ? err.message : 'Unbekannter Fehler');
      } finally {
        setIsLoading(false);
      }
    };

    fetchAll();
    return () => controller.abort();
  }, [fetchKey]);

  return (
    <FlightContext.Provider
      value={{ departures, arrivals, isLoading, error, refetch, lastUpdated }}
    >
      {children}
    </FlightContext.Provider>
  );
}

// 3. Custom Hook für bequemen Zugriff (identisch zu Lektion 8+9)
export function useFlights(): FlightContextValue {
  const context = useContext(FlightContext);
  if (!context) {
    throw new Error(
      'useFlights muss innerhalb eines <FlightProvider> verwendet werden'
    );
  }
  return context;
}

Context in den List-Screens verwenden

screens/ArrivalListScreen.tsx TypeScript 
import { useMemo } from 'react';
import { SafeAreaView, StyleSheet } from 'react-native';
import { useNavigation } from '@react-navigation/native';
import { NativeStackNavigationProp } from '@react-navigation/native-stack';
import { useFlights } from '../context/FlightContext';
import { ArrivalStackParamList } from '../navigation/ArrivalStack';
import { FlightList } from '../components/FlightList';
import { SearchBar } from '../components/SearchBar';

type ArrivalListNavProp = NativeStackNavigationProp<
  ArrivalStackParamList,
  'ArrivalList'
>;

export function ArrivalListScreen() {
  const navigation = useNavigation<ArrivalListNavProp>();

  // Greift auf DENSELBEN Context zu wie DepartureListScreen –
  // kein doppelter API-Call, da die Daten im Context gecacht sind!
  const {
    arrivals,
    isLoading,
    isRefreshing,
    refetch,
    searchQuery,
    setSearchQuery,
  } = useFlights();

  const filteredArrivals = useMemo(
    () =>
      arrivals.filter(
        (f) =>
          f.flightNumber.toLowerCase().includes(searchQuery.toLowerCase()) ||
          f.destination.toLowerCase().includes(searchQuery.toLowerCase())
      ),
    [arrivals, searchQuery]
  );

  return (
    <SafeAreaView style={styles.container}>
      <SearchBar value={searchQuery} onChangeText={setSearchQuery} />
      <FlightList
        flights={filteredArrivals}
        isLoading={isLoading}
        onFlightPress={(flight) => navigation.navigate('FlightDetail', { flight })}
        onRefresh={refetch}
        refreshing={isRefreshing}
      />
    </SafeAreaView>
  );
}

Häufige Fehler

Fehler: NavigationContainer vergessen oder falsch platziert

Wenn man useNavigation() oder useRoute() in einer Komponente aufruft, die nicht innerhalb eines NavigationContainer gerendert wird, wirft React Navigation einen Fehler: „Couldn't find a navigation object. Is your component inside a screen in a navigator?“. Das passiert häufig, wenn der NavigationContainer vergessen wurde oder eine Komponente außerhalb davon verwendet wird.

Fix: Sicherstellen, dass NavigationContainer in App.tsx die gesamte App umschließt und genau einmal vorkommt. Alle Screens und Navigatoren müssen Kinder des NavigationContainer sein. Context-Provider wie FlightProvider gehören außerhalb des NavigationContainer.

Fehler: Falscher Screen-Name in navigation.navigate()

navigation.navigate('FlghtDetail', { flight }) (Tippfehler!) wirft zur Laufzeit einen Fehler. Ohne TypeScript-Typen sieht man diesen Fehler erst beim Ausführen, nicht beim Schreiben des Codes.

Fix: Den useNavigation-Hook immer mit dem korrekten Generic-Typ versehen: useNavigation<NativeStackNavigationProp<DepartureStackParamList, 'DepartureList'>>(). TypeScript erkennt dann Tippfehler im Screen-Namen sofort beim Schreiben. Zusätzlich: Screen-Namen als Konstanten auslagern um Duplikate zu vermeiden.

Fehler: Denselben Stack in beiden Tabs verwendet

Wenn Departure-Tab und Arrival-Tab denselben Stack.Navigator teilen (also dieselbe Komponenteninstanz), teilen sie auch den Navigations-State. Navigiert man in Tab 1 in ein Detail, ist Tab 2 plötzlich auch auf der Detail-Ansicht. Das ist ein subtiler Fehler, der sich manchmal erst nach längerem Testen zeigt.

Fix: Jeder Tab bekommt seinen eigenen Stack-Navigator: DepartureStackNavigator und ArrivalStackNavigator als separate Komponenten mit jeweils eigenem createNativeStackNavigator()-Aufruf. Auch wenn beide denselben FlightDetailScreen rendern – es sind zwei unabhängige Instanzen mit unabhängigem State.

Fehler: headerShown: false vergessen → doppelter Header

Wenn der Tab-Navigator headerShown nicht auf false setzt, und der Stack-Navigator ebenfalls einen Header rendert, erscheint ein doppelter Header auf dem Bildschirm: einmal der Tab-Header (mit dem Tab-Namen) und einmal der Stack-Header (mit dem Screen-Titel). Das sieht unfertig aus und verschwendet kostbaren Bildschirmplatz.

Fix: Im Tab-Navigator headerShown: false in den screenOptions setzen (gilt dann für alle Tabs), oder in den options jedes einzelnen Tab-Screens: <Tab.Screen options={{ headerShown: false }} />. Der Stack-Navigator bringt dann seinen eigenen, korrekt konfigurierten Header für jeden Screen mit.
