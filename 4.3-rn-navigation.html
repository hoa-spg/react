Lektion 4.3 — Teil 4: React Native

Navigation & State

React Native ca. 105 min

Lernziele

  • React Navigation installieren und konfigurieren
  • Einen Tab-Navigator für Abflüge und Ankünfte einrichten
  • Einen Stack-Navigator für Detailseiten mit TypeScript-Typen verwenden
  • Mit useNavigation und useRoute zwischen Screens navigieren
  • Parameter (z.B. ein Flight-Objekt) sicher zwischen Screens übergeben
  • Tab- und Stack-Navigatoren ineinander verschachteln
  • Geteilten State mit dem Context API über alle Screens teilen

1 — React Navigation installieren

React Native hat keine eingebaute Navigation – anders als im Web gibt es keine URLs und keine Browser-Historie. Die Standardlösung ist React Navigation (Version 7). react-native-safe-area-context ist seit Lektion 4.1 schon installiert.

Terminal Bash 
# Kern-Bibliothek und die beiden Navigatoren
npx expo install @react-navigation/native @react-navigation/bottom-tabs @react-navigation/native-stack

# native Grundlage für die Bildschirmwechsel
npx expo install react-native-screens

React Router vs. React Navigation – Vergleich

Die Konzepte sind ähnlich, die API jedoch unterschiedlich. Diese Tabelle hilft beim Transfer des Wissens aus Lektion 2.7 (React Router):

React Router (Web) React Navigation (Mobile)
BrowserRouter NavigationContainer
Routes + Route Stack.Navigator + Stack.Screen
<Link to="/detail"> navigation.navigate('Detail')
useParams() route.params (via useRoute())
useNavigate() useNavigation()
navigate(-1) (zurück) navigation.goBack()
Browser-History (URL-basiert) Stack (in-memory, keine URL)

2 — Tabs und Stacks

Mobile Apps kombinieren meist zwei Arten von Navigation:

  • Tab-Navigator: eine Leiste am unteren Rand, zwischen deren Bereichen man jederzeit wechseln kann.
  • Stack-Navigator: ein Stapel von Bildschirmen. navigate legt einen neuen Bildschirm oben drauf, der Zurück-Pfeil im Header (oder die Zurück-Geste) nimmt ihn wieder herunter.

Im FlugBoard bekommt jeder Tab seinen eigenen Stack – so merkt sich jeder Tab, welche Seite gerade offen ist:

Navigationsstruktur Text 
NavigationContainer
└── Tab.Navigator                 (Tab-Leiste unten)
    ├── Tab „Abflüge"   → DepartureStack
    │   ├── DepartureList         (Startseite des Tabs)
    │   └── FlightDetail          (wird darübergeschoben)
    └── Tab „Ankünfte"  → ArrivalStack
        ├── ArrivalList
        └── FlightDetail

Was in Lektion 4.2 in App.tsx stand, verteilt sich jetzt: Die Reiter „Alle / Abflüge / Ankünfte“ werden zu echten Tabs, die Auswahl einer Karte zu einem eigenen Detail-Bildschirm, und Suche und Daten wandern in einen Context, den alle Bildschirme nutzen. Wir bauen die Teile von unten nach oben auf.

3 — Routen typisieren

Für jeden Stack legen wir fest, welche Bildschirme er hat und welche Parameter sie bekommen. undefined heißt: keine Parameter. Mit diesen Typen prüft TypeScript später jeden navigate-Aufruf.

src/navigation/types.ts TypeScript 
import { Flight } from '../types/flight';

export type DepartureStackParamList = {
  DepartureList: undefined;
  FlightDetail: { flight: Flight };
};

export type ArrivalStackParamList = {
  ArrivalList: undefined;
  FlightDetail: { flight: Flight };
};

4 — FlightContext – gemeinsamer State

Beide Tabs brauchen dieselben Flüge und dieselbe Suche. Statt den State in App.tsx zu halten und durch die Navigatoren zu reichen, legen wir ihn wie in Lektion 2.4 in einen Context. Laden und Aktualisieren werden genauso simuliert wie in Lektion 4.2; departures und arrivals sind die gefilterten und sortierten Listen.

src/context/FlightContext.tsx TypeScript 
import { createContext, useContext, useState, useMemo, useEffect, ReactNode } from 'react';
import { Flight } from '../types/flight';
import { sampleFlights } from '../data/flights';

interface FlightContextType {
  isLoading: boolean;
  isRefreshing: boolean;
  refetch: () => void;
  searchQuery: string;
  setSearchQuery: (q: string) => void;
  departures: Flight[];
  arrivals: Flight[];
}

const FlightContext = createContext<FlightContextType | null>(null);

export const FlightProvider = ({ children }: { children: ReactNode }) => {
  const [flights, setFlights]             = useState<Flight[]>([]);
  const [isLoading, setIsLoading]         = useState(true);
  const [isRefreshing, setIsRefreshing]   = useState(false);
  const [searchQuery, setSearchQuery]     = useState('');

  // Ladezeit simulieren wie in Lektion 4.2
  useEffect(() => {
    const timeoutId = setTimeout(() => {
      setFlights(sampleFlights);
      setIsLoading(false);
    }, 1000);
    return () => clearTimeout(timeoutId);
  }, []);

  // Pull-to-Refresh: Spinner für 1 Sekunde anzeigen
  const refetch = () => {
    setIsRefreshing(true);
    setTimeout(() => setIsRefreshing(false), 1000);
  };

  const filtered = useMemo(() => {
    const q = searchQuery.toLowerCase();
    if (!q) return flights;
    return flights.filter(f =>
      f.flightNumber.toLowerCase().includes(q) ||
      f.airline.toLowerCase().includes(q) ||
      f.airport.toLowerCase().includes(q)
    );
  }, [flights, searchQuery]);

  const departures = useMemo(() =>
    [...filtered]
      .filter(f => f.type === 'departure')
      .sort((a, b) => a.scheduledTime.localeCompare(b.scheduledTime)),
    [filtered]
  );

  const arrivals = useMemo(() =>
    [...filtered]
      .filter(f => f.type === 'arrival')
      .sort((a, b) => a.scheduledTime.localeCompare(b.scheduledTime)),
    [filtered]
  );

  return (
    <FlightContext.Provider
      value={{
        isLoading,
        isRefreshing,
        refetch,
        searchQuery,
        setSearchQuery,
        departures,
        arrivals,
      }}
    >
      {children}
    </FlightContext.Provider>
  );
};

export const useFlightContext = () => {
  const ctx = useContext(FlightContext);
  if (!ctx) throw new Error('useFlightContext außerhalb von FlightProvider verwendet');
  return ctx;
};

5 — Listen-Screens: useNavigation

Ein Screen ist eine ganz normale Komponente, die ein Navigator als Bildschirm anzeigt. Der Abflug-Screen holt die Daten aus dem Context und verwendet die Komponenten aus Lektion 4.2. Neu ist useNavigation: Der Hook liefert das navigation-Objekt, mit dem man zu einem anderen Screen wechselt – hier mit dem angetippten Flug als Parameter.

src/screens/DepartureListScreen.tsx TypeScript 
import { useNavigation } from '@react-navigation/native';
import { NativeStackNavigationProp } from '@react-navigation/native-stack';
import { View, StyleSheet } from 'react-native';
import { useFlightContext } from '../context/FlightContext';
import { DepartureStackParamList } from '../navigation/types';
import { Flight } from '../types/flight';
import FlightList from '../components/FlightList';
import SearchBar from '../components/SearchBar';

type Nav = NativeStackNavigationProp<DepartureStackParamList, 'DepartureList'>;

const DepartureListScreen = () => {
  const navigation = useNavigation<Nav>();
  const {
    departures,
    isLoading,
    isRefreshing,
    refetch,
    searchQuery,
    setSearchQuery,
  } = useFlightContext();

  const handlePress = (flight: Flight) =>
    navigation.navigate('FlightDetail', { flight });

  return (
    <View style={styles.container}>
      <SearchBar value={searchQuery} onChangeText={setSearchQuery} />
      <FlightList
        flights={departures}
        title="Abflüge"
        onFlightPress={handlePress}
        isLoading={isLoading}
        onRefresh={refetch}
        refreshing={isRefreshing}
      />
    </View>
  );
};

const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: '#0d1117' },
});

export default DepartureListScreen;
  • Der Typ Nav sagt TypeScript, in welchem Stack der Screen liegt. Damit sind nur 'DepartureList' und 'FlightDetail' als Ziel erlaubt, und für 'FlightDetail' muss { flight } mitgegeben werden.
  • ArrivalListScreen.tsx ist gleich aufgebaut, nur mit ArrivalStackParamList, 'ArrivalList', arrivals und dem Titel „Ankünfte“.

6 — Detail-Screen: useRoute

Das Gegenstück zu useNavigation ist useRoute: Es liefert die aktuelle Route und darin unter params die übergebenen Parameter – vergleichbar mit useParams() aus React Router. RouteProp gibt der Route ihren Typ, damit route.params.flight ein Flight ist.

src/screens/FlightDetailScreen.tsx TypeScript 
import { RouteProp, useRoute } from '@react-navigation/native';
import { ScrollView, View, Text, StyleSheet } from 'react-native';
import { DepartureStackParamList } from '../navigation/types';
import StatusBadge from '../components/StatusBadge';

type Route = RouteProp<DepartureStackParamList, 'FlightDetail'>;

const DetailRow = ({ label, value }: { label: string; value: string }) => (
  <View style={styles.row}>
    <Text style={styles.label}>{label}</Text>
    <Text style={styles.value}>{value}</Text>
  </View>
);

const FlightDetailScreen = () => {
  const route = useRoute<Route>();
  const { flight } = route.params;

  return (
    <ScrollView style={styles.container}>
      {/* Header card */}
      <View style={styles.headerCard}>
        <Text style={styles.flightNumber}>{flight.flightNumber}</Text>
        <Text style={styles.airline}>{flight.airline}</Text>
        <View style={styles.headerBadgeWrap}>
          <StatusBadge status={flight.status} />
        </View>
      </View>

      {/* Details */}
      <View style={styles.detailsCard}>
        <DetailRow
          label="Richtung"
          value={flight.type === 'departure' ? '↑ Abflug' : '↓ Ankunft'}
        />
        <DetailRow
          label={flight.type === 'departure' ? 'Ziel' : 'Herkunft'}
          value={flight.airport}
        />
        <DetailRow label="Geplante Zeit" value={flight.scheduledTime} />
        {flight.expectedTime && (
          <DetailRow label="Erwartete Zeit" value={flight.expectedTime} />
        )}
        <DetailRow label="Terminal" value={flight.terminal} />
        {flight.gate && <DetailRow label="Gate" value={flight.gate} />}
      </View>
    </ScrollView>
  );
};

const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: '#0d1117' },
  headerCard: {
    backgroundColor: '#161b22',
    padding: 24,
    alignItems: 'center',
    borderBottomWidth: 1,
    borderBottomColor: '#30363d',
  },
  flightNumber: { fontSize: 36, fontWeight: 'bold', color: '#61dafb' },
  airline: { fontSize: 16, color: '#8b949e', marginTop: 4 },
  headerBadgeWrap: { marginTop: 12 },
  detailsCard: {
    backgroundColor: '#1c2128',
    margin: 16,
    borderRadius: 8,
    borderWidth: 1,
    borderColor: '#30363d',
    overflow: 'hidden',
  },
  row: {
    flexDirection: 'row',
    justifyContent: 'space-between',
    alignItems: 'center',
    padding: 14,
    borderBottomWidth: 1,
    borderBottomColor: '#30363d',
  },
  label: { color: '#8b949e', fontSize: 14 },
  value: {
    color: '#e6edf3',
    fontSize: 14,
    fontWeight: '500',
    maxWidth: '60%',
    textAlign: 'right',
  },
});

export default FlightDetailScreen;

DetailRow ist eine kleine Hilfskomponente in derselben Datei, damit die sechs Zeilen nicht jeweils dasselbe Markup wiederholen.

7 — Stack-Navigator

createNativeStackNavigator erzeugt einen Stack, der die nativen Bildschirmwechsel von iOS und Android verwendet. Der Typ aus Abschnitt 3 kommt als Generic dazu. Jeder Stack.Screen verbindet einen Namen mit einer Komponente; der erste ist die Startseite.

src/navigation/DepartureStack.tsx TypeScript 
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { DepartureStackParamList } from './types';
import DepartureListScreen from '../screens/DepartureListScreen';
import FlightDetailScreen from '../screens/FlightDetailScreen';

const Stack = createNativeStackNavigator<DepartureStackParamList>();

const DepartureStack = () => (
  <Stack.Navigator
    screenOptions={{
      headerStyle: { backgroundColor: '#161b22' },
      headerTintColor: '#e6edf3',
      contentStyle: { backgroundColor: '#0d1117' },
    }}
  >
    <Stack.Screen
      name="DepartureList"
      component={DepartureListScreen}
      options={{ title: '✈ Abflüge' }}
    />
    <Stack.Screen
      name="FlightDetail"
      component={FlightDetailScreen}
      options={({ route }) => ({ title: route.params.flight.flightNumber })}
    />
  </Stack.Navigator>
);

export default DepartureStack;
  • screenOptions gelten für alle Screens des Stacks: dunkler Header, helle Schrift und Pfeile, dunkler Hintergrund.
  • options kann auch eine Funktion sein: Der Titel des Detail-Screens ist die Flugnummer aus den Parametern.
  • ArrivalStack.tsx ist gleich aufgebaut, mit ArrivalListScreen und dem Titel „🛬 Ankünfte“.

8 — Tab-Navigator in App.tsx

App.tsx setzt alles zusammen. NavigationContainer umschließt die gesamte Navigation – wie BrowserRouter im Web – und kommt genau einmal vor. Der FlightProvider liegt außen herum, damit alle Screens den Context sehen.

App.tsx TypeScript 
import { NavigationContainer } from '@react-navigation/native';
import { createBottomTabNavigator } from '@react-navigation/bottom-tabs';
import { Text } from 'react-native';
import { StatusBar } from 'expo-status-bar';
import { FlightProvider } from './src/context/FlightContext';
import DepartureStack from './src/navigation/DepartureStack';
import ArrivalStack from './src/navigation/ArrivalStack';

const Tab = createBottomTabNavigator();

export default function App() {
  return (
    <FlightProvider>
      <NavigationContainer>
        <StatusBar style="light" />
        <Tab.Navigator
          screenOptions={{
            headerShown: false,
            tabBarStyle: {
              backgroundColor: '#161b22',
              borderTopColor: '#30363d',
              borderTopWidth: 1,
            },
            tabBarActiveTintColor: '#61dafb',
            tabBarInactiveTintColor: '#8b949e',
            tabBarLabelStyle: { fontSize: 12, fontWeight: '600' },
          }}
        >
          <Tab.Screen
            name="DepartureTab"
            component={DepartureStack}
            options={{
              title: 'Abflüge',
              tabBarIcon: ({ color, size }) => (
                <Text style={{ color, fontSize: size - 4 }}>✈</Text>
              ),
            }}
          />
          <Tab.Screen
            name="ArrivalTab"
            component={ArrivalStack}
            options={{
              title: 'Ankünfte',
              tabBarIcon: ({ color, size }) => (
                <Text style={{ color, fontSize: size - 4 }}>🛬</Text>
              ),
            }}
          />
        </Tab.Navigator>
      </NavigationContainer>
    </FlightProvider>
  );
}
  • headerShown: false: Die Tabs zeigen keinen eigenen Header – den bringen die Stacks mit.
  • tabBarIcon ist eine Funktion, die Farbe und Größe bekommt; hier zeichnet sie ein Emoji.
  • Die SafeAreaView aus Lektion 4.2 entfällt: Header und Tab-Leiste halten selbst Abstand zu Notch und Home-Balken.

Projektschritt

Projektschritt 4.3

FlugBoard Mobile – Navigation

Ausgangspunkt ist das Projekt aus Lektion 4.2. Die Komponenten in src/components/ bleiben unverändert.

  1. Installieren: React Navigation und react-native-screens (Abschnitt 1).
  2. Typen und Context: src/navigation/types.ts und src/context/FlightContext.tsx anlegen.
  3. Screens: DepartureListScreen, ArrivalListScreen und FlightDetailScreen in src/screens/.
  4. Stacks: DepartureStack und ArrivalStack in src/navigation/.
  5. App.tsx ersetzen: FlightProvider, NavigationContainer und Tab-Navigator statt Suche, Reitern und Liste.
  6. Testen: Zwischen den Tabs wechseln, einen Flug öffnen, zurück navigieren. Die Suche gilt in beiden Tabs.

Häufige Fehler

4 Fehler · zum Aufklappen klicken
Fehler: NavigationContainer vergessen oder falsch platziert

Wenn man useNavigation() oder useRoute() in einer Komponente aufruft, die nicht innerhalb eines NavigationContainer gerendert wird, wirft React Navigation einen Fehler: „Couldn't find a navigation object. Is your component inside a screen in a navigator?“. Das passiert häufig, wenn der NavigationContainer vergessen wurde oder eine Komponente außerhalb davon verwendet wird.

Fix: Sicherstellen, dass NavigationContainer in App.tsx die gesamte App umschließt und genau einmal vorkommt. Alle Screens und Navigatoren müssen Kinder des NavigationContainer sein. Context-Provider wie FlightProvider gehören außerhalb des NavigationContainer.

Fehler: Falscher Screen-Name in navigation.navigate()

navigation.navigate('FlghtDetail', { flight }) (Tippfehler!) wirft zur Laufzeit einen Fehler. Ohne TypeScript-Typen sieht man diesen Fehler erst beim Ausführen, nicht beim Schreiben des Codes.

Fix: Den useNavigation-Hook immer mit dem korrekten Generic-Typ versehen: useNavigation<NativeStackNavigationProp<DepartureStackParamList, 'DepartureList'>>(). TypeScript erkennt dann Tippfehler im Screen-Namen sofort beim Schreiben. Zusätzlich: Screen-Namen als Konstanten auslagern um Duplikate zu vermeiden.

Fehler: Denselben Stack in beiden Tabs verwendet

Wenn Departure-Tab und Arrival-Tab denselben Stack.Navigator teilen (also dieselbe Komponenteninstanz), teilen sie auch den Navigations-State. Navigiert man in Tab 1 in ein Detail, ist Tab 2 plötzlich auch auf der Detail-Ansicht. Das ist ein subtiler Fehler, der sich manchmal erst nach längerem Testen zeigt.

Fix: Jeder Tab bekommt seinen eigenen Stack-Navigator: DepartureStackNavigator und ArrivalStackNavigator als separate Komponenten mit jeweils eigenem createNativeStackNavigator()-Aufruf. Auch wenn beide denselben FlightDetailScreen rendern – es sind zwei unabhängige Instanzen mit unabhängigem State.

Fehler: headerShown: false vergessen → doppelter Header

Wenn der Tab-Navigator headerShown nicht auf false setzt, und der Stack-Navigator ebenfalls einen Header rendert, erscheint ein doppelter Header auf dem Bildschirm: einmal der Tab-Header (mit dem Tab-Namen) und einmal der Stack-Header (mit dem Screen-Titel). Das sieht unfertig aus und verschwendet kostbaren Bildschirmplatz.

Fix: Im Tab-Navigator headerShown: false in den screenOptions setzen (gilt dann für alle Tabs), oder in den options jedes einzelnen Tab-Screens: <Tab.Screen options={{ headerShown: false }} />. Der Stack-Navigator bringt dann seinen eigenen, korrekt konfigurierten Header für jeden Screen mit.

Aufgaben

3 Aufgaben + Bonus · zum Aufklappen klicken
Aufgabe 1 Button im Header
  • Gib dem Detail-Screen über options einen Button rechts im Header: headerRight: () => ( … ).
  • Ein Tipp darauf zeigt mit Alert.alert Flugnummer, Ziel und Zeit an.
Aufgabe 2 Status im Detail-Screen ändern
  • Ergänze im Context eine Funktion updateStatus(id, status), die einen Flug im State ändert.
  • Im Detail-Screen setzen zwei Buttons den Status auf „Boarding“ bzw. „Gestartet“.
  • Nach dem Zurückgehen soll die Liste den neuen Status zeigen. Warum reicht es dafür nicht, route.params.flight anzuzeigen? Tipp: Übergib nur die ID und hole den Flug im Detail-Screen aus dem Context.
Aufgabe 3 Dritter Tab „Info“
  • Lege einen InfoScreen mit Adresse und Anreise-Infos zum Flughafen an.
  • Hänge ihn als dritten Tab direkt an den Tab-Navigator – ohne eigenen Stack. Was fällt beim Header auf, und wie löst du es?
Aufgabe 4 — Bonus Suche im nativen Header
  • Der Stack-Navigator kann ein Suchfeld direkt im Header anzeigen: headerSearchBarOptions in den options der Listen-Screens.
  • Ersetze damit die SearchBar-Komponente; onChangeText bekommt ein Event, der Text steht in event.nativeEvent.text.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Warum braucht React Native eine eigene Navigationsbibliothek wie React Navigation?

Erklärung: Die Konzepte ähneln React Router, die API ist aber auf Bildschirme (Screens) und Gesten ausgelegt.

Frage 2 Was unterscheidet einen Tab-Navigator von einem Stack-Navigator?

Erklärung: Im FlugBoard hat jeder Tab (Abflüge, Ankünfte) seinen eigenen Stack – so merkt sich jeder Tab, welche Seite offen ist.

Frage 3 Was bringt es, die Routen eines Stacks mit TypeScript zu typisieren?

Erklärung: Ohne Typen fällt der falsche Name erst zur Laufzeit auf.

Frage 4 Wie liest ein Detail-Screen die übergebenen Parameter (z. B. den Flug)?

Erklärung: Navigiert wird mit useNavigation() und navigation.navigate('FlightDetail', { flight }).

Frage 5 Was löst den Fehler „Couldn't find a navigation object“ aus?

Erklärung: Der NavigationContainer umschließt in App.tsx genau einmal die ganze App; Context-Provider wie FlightProvider liegen außerhalb davon.
