React Router

React ca. 105 min

Lernziele

  • Client-Side Routing verstehen (vs. Multi-Page-App)
  • React Router v6 installieren und einrichten
  • <BrowserRouter>, <Routes>, <Route> korrekt verwenden
  • Mit <Link> und <NavLink> navigieren
  • URL-Parameter mit useParams auslesen
  • Programmatisch navigieren mit useNavigate
  • Eine 404-Seite einrichten

1. Was ist Client-Side Routing?

In einer klassischen Multi-Page-App (MPA) führt jeder Klick auf einen Link dazu, dass der Browser eine neue HTTP-Anfrage schickt, der Server eine neue HTML-Datei ausliefert und die Seite komplett neu geladen wird. State geht verloren, der Nutzer sieht einen kurzen Ladevorgang.

In einer Single Page Application (SPA) mit Client-Side Routing passiert das nicht. JavaScript fängt den Klick auf <a>-Tags ab, aktualisiert die URL in der Browser-History – ohne eine neue Seite zu laden – und rendert die passende Komponente. Die React-App läuft durch, der State bleibt erhalten, das Erlebnis wirkt wie eine native App.

  Multi-Page-App SPA (React Router)
Navigation Voller Seitenneuladen Nur URL + Komponente wechseln
State Geht bei Navigation verloren Bleibt erhalten
URL Jede Seite eigene Datei Immer index.html, Router rendert Komponente
Server Liefert jede Seite einzeln Muss alle Pfade auf index.html weiterleiten
ℹ
URLs sehen normal aus

Obwohl die SPA technisch immer dieselbe index.html ausliefert, sehen die URLs ganz normal aus: /departures, /flight/3, /arrivals. Die Browser-History funktioniert wie gewohnt (Vor/Zurück-Tasten). Bookmarks funktionieren – solange der Server korrekt konfiguriert ist (dazu später mehr).

2. Installation und Einrichtung

React Router ist keine eingebaute React-Funktion, sondern eine externe Bibliothek. Für Browser-Apps verwenden wir das Paket react-router-dom (v6).

Terminal Bash 
npm install react-router-dom

Der BrowserRouter muss die gesamte App umschließen, damit alle Komponenten auf Routing-Hooks und -Komponenten zugreifen können. Der ideale Ort ist main.tsx:

src/main.tsx TypeScript 
import React from 'react';
import ReactDOM from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';
import { ThemeProvider } from './context/ThemeContext';
import App from './App';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <BrowserRouter
      future={{
        v7_startTransition: true,
        v7_relativeSplatPath: true,
      }}
    >
      <ThemeProvider>
        <App />
      </ThemeProvider>
    </BrowserRouter>
  </React.StrictMode>
);
ℹ
React Router Future Flag

In React Router v6 erscheinen oft Warnungen zum kommenden v7-Verhalten (v7_startTransition und v7_relativeSplatPath). Mit den Future-Flags aktivierst du beide Verhaltensänderungen bereits jetzt und hältst die Konsole sauber.

💡
BrowserRouter vs. HashRouter

BrowserRouter verwendet die echte URL-History-API: /flight/3. HashRouter verwendet das Hash-Fragment: /#/flight/3. BrowserRouter ist die bevorzugte Wahl für moderne Apps, erfordert aber eine korrekte Server-Konfiguration. HashRouter funktioniert auch ohne Server-Anpassung, sieht aber weniger professionell aus.

3. Routes definieren

In React Router v6 werden Routen mit den Komponenten <Routes> und <Route> deklarativ beschrieben. Verschachtelte Routen ermöglichen ein gemeinsames Layout für mehrere Seiten.

src/App.tsx (mit Routing) TypeScript 
import { Routes, Route } from 'react-router-dom';

import Layout          from './components/Layout';
import DeparturePage   from './pages/DeparturePage';
import ArrivalPage     from './pages/ArrivalPage';
import FlightDetailPage from './pages/FlightDetailPage';
import NotFoundPage    from './pages/NotFoundPage';

function App() {
  return (
    <Routes>
      {/* Layout umschließt alle Seiten: gemeinsamer Header, Navbar */}
      <Route path="/" element={<Layout />}>

        {/* index-Route: wird bei "/" gerendert */}
        <Route index element={<DeparturePage />} />

        {/* Normale Routen */}
        <Route path="arrivals" element={<ArrivalPage />} />

        {/* Route mit URL-Parameter (:id) */}
        <Route path="flight/:id" element={<FlightDetailPage />} />

        {/* Catch-all: alle anderen Pfade → 404 */}
        <Route path="*" element={<NotFoundPage />} />

      </Route>
    </Routes>
  );
}

Das Layout-Muster funktioniert über die <Outlet />-Komponente. Outlet ist ein Platzhalter in der Layout-Komponente, an dem React Router die jeweilige Kind-Seite einfügt:

src/components/Layout.tsx TypeScript 
import { Link, NavLink, Outlet } from 'react-router-dom';
import { CSSProperties } from 'react';
import { useTheme } from '../context/ThemeContext';
import './Layout.css';

/**
 * Layout-Komponente: Gemeinsamer Rahmen für alle Seiten.
 * CSS-Variablen werden einmalig am Root injiziert; alle Kind-Elemente
 * verwenden sie via var(--...). <Outlet /> wird durch die jeweilige Seite ersetzt.
 */
const Layout = () => {
  const { colors, theme, toggleTheme } = useTheme();

  // Inline style ist hier bewusst: CSS-Variablen können nur per JS gesetzt
  // werden – keine hardcodierten Farben, nur Token-Zuweisung.
  const themeVars = {
    '--bg': colors.bg,
    '--bg-sidebar': colors.bgSidebar,
    '--text': colors.text,
    '--text-muted': colors.textMuted,
    '--border': colors.border,
    '--accent': colors.accent,
  } as CSSProperties;

  return (
    <div className="app-root" style={themeVars}>
      <header className="top-nav">
        <Link to="/" className="brand-link">✈ FlugBoard</Link>

        {/* NavLink setzt die CSS-Klasse „active“ über den className-Callback */}
        <NavLink
          to="/departures"
          className={({ isActive }) => `nav-link${isActive ? ' active' : ''}`}
        >
          Abflüge
        </NavLink>
        <NavLink
          to="/arrivals"
          className={({ isActive }) => `nav-link${isActive ? ' active' : ''}`}
        >
          Ankünfte
        </NavLink>

        <div className="top-nav-actions">
          <button onClick={toggleTheme} className="theme-toggle">
            {theme === 'dark' ? '☀️' : '🌙'}
          </button>
        </div>
      </header>
      <main className="page-content">
        {/* Hier wird die aktive Seite gerendert */}
        <Outlet />
      </main>
    </div>
  );
};
ℹ
pages/ vs. components/

Seitenkomponenten in src/pages/ abzulegen ist eine verbreitete Konvention. Seiten sind Komponenten, die direkt einer Route zugeordnet sind – sie laden Daten und koordinieren andere Komponenten. src/components/ enthält kleinere, wiederverwendbare Bausteine ohne direkte Route-Bindung.

4. Navigation mit Link und NavLink

In einer SPA niemals gewöhnliche <a href="...">-Tags für interne Links verwenden – das würde einen vollen Seitenneuladen auslösen und den gesamten State zerstören. React Router stellt stattdessen <Link> und <NavLink> bereit.

src/components/Layout.tsx – NavLink-Auszug TypeScript 
{/* NavLink: className-Callback liefert isActive → CSS-Klasse "active" */}
<NavLink
  to="/departures"
  className={({ isActive }) => `nav-link${isActive ? ' active' : ''}`}
>
  Abflüge
</NavLink>

{/* end-Prop: "/" nur aktiv wenn Pfad exakt "/" ist, nicht bei "/arrivals" */}
<NavLink
  to="/"
  end
  className={({ isActive }) => `nav-link${isActive ? ' active' : ''}`}
>
  Startseite
</NavLink>

{/* Einfacher Link: kein aktiver Status benötigt */}

  ✈ FlugBoard
</Link>

💡
Das end-Prop bei NavLink

Ohne end würde der Link zu / auch bei /arrivals und /flight/3 als aktiv markiert, weil alle Pfade mit / beginnen. Das end-Prop sorgt dafür, dass der Link nur dann aktiv ist, wenn der Pfad exakt übereinstimmt.

5. URL-Parameter mit useParams

URL-Parameter erlauben es, dynamische Werte in der URL zu kodieren. Die Route path="flight/:id" wird bei /flight/3 aktiviert, und useParams gibt { id: "3" } zurück.

⚠
URL-Parameter sind immer strings

useParams gibt immer string | undefined zurück, niemals eine Zahl. Für numerische IDs muss explizit konvertiert werden: const numId = Number(id) oder parseInt(id, 10). Vor der Konvertierung immer prüfen, ob id definiert und gültig ist.

src/pages/FlightDetailPage.tsx TypeScript 
import { useParams, useNavigate } from 'react-router-dom';
import { useEffect, useState } from 'react';
import { Flight } from '../types/flight';
import FlightDetail from '../components/FlightDetail';

const FlightDetailPage = () => {
  // useParams liefert die URL-Parameter als Record<string, string | undefined>
  const { id } = useParams<{ id: string }>();
  const navigate = useNavigate();

  const [flight, setFlight]     = useState<Flight | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError]         = useState<string | null>(null);

  useEffect(() => {
    if (!id) {
      setError('Keine Flug-ID in der URL');
      setIsLoading(false);
      return;
    }

    const fetchFlight = async () => {
      try {
        setIsLoading(true);
        setError(null);

        const response = await fetch(`http://localhost:8000/api/flights/${id}`);

        if (response.status === 404) {
          throw new Error(`Flug mit ID ${id} wurde nicht gefunden.`);
        }
        if (!response.ok) {
          throw new Error(`Server-Fehler: ${response.status}`);
        }

        const data: Flight = await response.json();
        setFlight(data);
      } catch (err) {
        setError(err instanceof Error ? err.message : 'Unbekannter Fehler');
      } finally {
        setIsLoading(false);
      }
    };

    fetchFlight();
  }, [id]); // Effekt läuft neu, wenn sich die ID in der URL ändert

  return (
    <div style={{ padding: '2rem' }}>
      {isLoading ? (
        <div className="board-loading board-loading--muted" style={{ textAlign: 'center' }}>
          Flugdaten werden geladen...
        </div>
      ) : error || !flight ? (
        <>
          <p style={{ color: '#f85149' }}>{error ?? 'Flug nicht gefunden.'}</p>
          <button onClick={() => navigate(-1)}>← Zurück</button>
        </>
      ) : (
        <FlightDetail
          flight={flight}
          onClose={() => navigate(-1)}
        />
      )}
    </div>
  );
};

6. Programmatisch navigieren mit useNavigate

Während <Link> für deklarative Navigation im JSX zuständig ist, erlaubt useNavigate das programmatische Navigieren als Reaktion auf Events – z.B. nach dem Absenden eines Formulars, nach einem API-Call oder beim Klick auf eine Tabellenzeile.

src/components/FlightCard.tsx (mit Navigation) TypeScript 
import { useNavigate } from 'react-router-dom';
import { Flight } from '../types/flight';
import FlightStatusBadge from './FlightStatusBadge';

interface FlightCardProps {
  flight: Flight;
  isSelected?: boolean;
}

const FlightCard = ({ flight, isSelected }: FlightCardProps) => {
  const navigate = useNavigate();

  const handleClick = () => {
    // Navigiert zu /flight/3 (oder welche ID der Flug hat)
    navigate(`/flight/${flight.id}`);
  };

  return (
    <tr
      onClick={handleClick}
      style={{
        cursor: 'pointer',
        background: isSelected ? '#1f3a4a' : 'transparent',
      }}
    >
      <td><strong>{flight.flightNumber}</strong></td>
      <td>{flight.airline}</td>
      <td>{flight.airport}</td>
      <td>{flight.scheduledTime}</td>
      <td><FlightStatusBadge status={flight.status} /></td>
    </tr>
  );
};

useNavigate gibt eine Funktion zurück, die verschiedene Argumente akzeptiert:

useNavigate – Möglichkeiten TypeScript 
const navigate = useNavigate();

// Zu einer bestimmten URL navigieren
navigate('/arrivals');
navigate(`/flight/${id}`);

// Relative Navigation in der Browser-History
navigate(-1);   // Einen Schritt zurück (wie Browser-Zurück-Taste)
navigate(1);    // Einen Schritt vor (wie Browser-Vor-Taste)
navigate(-2);   // Zwei Schritte zurück

// Mit Options: replace statt push (kein History-Eintrag)
navigate('/departures', { replace: true });
// Kein Zurück-Button möglich nach dem Navigieren – gut für Loginseiten

// Mit State (wird NICHT in der URL sichtbar)
navigate('/flight/3', { state: { from: 'departures' } });
// In der Zielseite lesen:
const location = useLocation();
console.log(location.state?.from); // 'departures'

useLocation gibt Informationen über die aktuelle URL zurück:

useLocation – aktuelle URL lesen TypeScript 
import { useLocation } from 'react-router-dom';

const NotFoundPage = () => {
  const location = useLocation();

  // location.pathname: '/flight/999'
  // location.search:   '?status=delayed'
  // location.hash:     '#details'
  // location.state:    Daten aus navigate(url, { state })

  return (
    <div>
      <h1>404 – Seite nicht gefunden</h1>
      <p>
        Der Pfad <code>{location.pathname}</code> existiert nicht.
      </p>
    </div>
  );
};

FlugBoard zu einer Multi-Seiten-App migrieren

Wir verwandeln FlugBoard von einer Single-View-App in eine vollwertige Multi-Seiten-App mit eigenen URLs für Abflüge, Ankünfte und Flugdetails. Da Abflüge und Ankünfte jetzt getrennte Seiten sind, entfällt der Typ-Filter (Abflug/Ankunft) in der Toolbar.

Schritt 1: Installation und BrowserRouter

Terminal Bash

Schritt 2: pages/-Ordner mit Seitenkomponenten

src/pages/DeparturePage.tsx TypeScript 
import { useState } from 'react';
import { Flight } from '../types/flight';
import useFlights from '../hooks/useFlights';
import useFlightFilters from '../hooks/useFlightFilters';
import FlightBoard from '../components/FlightBoard';
import SearchBar from '../components/SearchBar';
import FilterBar from '../components/FilterBar';

const DeparturePage = () => {
  const { flights, isLoading, error } = useFlights();
  const {
    searchQuery,
    setSearchQuery,
    statusFilter,
    setStatusFilter,
    resetFilters,
    hasActiveFilters,
    filteredDepartures,
  } =
    useFlightFilters(flights);

  if (error)     return <p style={{ color: '#f85149' }}>{error}</p>;

  return (
    <div>
      <h2>Abflüge</h2>
      <SearchBar value={searchQuery} onChange={setSearchQuery} />
      <FilterBar
        statusFilter={statusFilter}
        onStatusChange={setStatusFilter}
        onReset={resetFilters}
        hasActiveFilters={hasActiveFilters}
      />
      {isLoading ? (
        <div className="board-loading board-loading--muted">
          <div className="loading-spinner" aria-hidden="true" />
          Flugdaten werden geladen...
        </div>
      ) : (
        <FlightBoard
          title="Abflüge"
          flights={filteredDepartures}
        />
      )}
    </div>
  );
};

Schritt 3: Routing in App.tsx zusammenführen

src/App.tsx (finale Version mit Routing) TypeScript 
import { Routes, Route } from 'react-router-dom';

import Layout           from './components/Layout';
import DeparturePage    from './pages/DeparturePage';
import ArrivalPage      from './pages/ArrivalPage';
import FlightDetailPage from './pages/FlightDetailPage';
import NotFoundPage     from './pages/NotFoundPage';

// App.tsx ist jetzt nur noch die Routing-Konfiguration.
// Alle Logik lebt in Pages, Hooks und Komponenten.
function App() {
  return (
    <Routes>
      <Route path="/" element={<Layout />}>
        <Route index          element={<DeparturePage />}    />
        <Route path="arrivals"  element={<ArrivalPage />}      />
        <Route path="flight/:id" element={<FlightDetailPage />} />
        <Route path="*"         element={<NotFoundPage />}     />
      </Route>
    </Routes>
  );
}
💡
Vite-Dev-Server und Client-Side Routing

Im Entwicklungsmodus leitet Vite alle Anfragen automatisch an index.html weiter, sodass direktes Aufrufen von localhost:5173/flight/3 funktioniert. Im Production-Build muss der Webserver (Nginx, Apache, Caddy...) entsprechend konfiguriert werden. Details dazu in Lektion 3.6 (Deployment).

Häufige Fehler

Fehler: <BrowserRouter> vergessen

useNavigate(), useParams() und alle anderen Routing-Hooks werfen einen Fehler, wenn sie außerhalb eines Routers aufgerufen werden: „useNavigate() may be used only in the context of a Router component“.

Fix: Sicherstellen, dass <BrowserRouter> in main.tsx die gesamte App umschließt – insbesondere auch alle Komponenten, die Routing-Hooks verwenden.

Fehler: <Outlet /> in der Layout-Komponente vergessen

Bei verschachtelten Routen (Route innerhalb eines anderen Route) muss die Eltern-Komponente <Outlet /> rendern. Fehlt es, werden die Kind-Routen überhaupt nicht angezeigt – ohne Fehlermeldung, nur leerer Inhalt.

Fix: In der Layout-Komponente <Outlet /> an der Stelle einfügen, wo der Seiteninhalt erscheinen soll. import { Outlet } from 'react-router-dom'; nicht vergessen.

Fehler: URL-Parameter als number erwartet, aber string erhalten

const { id } = useParams(); liefert id: string | undefined. Wird id direkt an eine API-Funktion übergeben, die eine number erwartet, entsteht ein TypeScript-Fehler oder ein „NaN“-Problem zur Laufzeit.

Fix: Explizit konvertieren und validieren: const numId = id ? parseInt(id, 10) : NaN; if (isNaN(numId)) return navigate('*'); Dann numId statt id verwenden.

Fehler: 404 bei direktem URL-Aufruf auf dem Produktionsserver

Nach dem Deployment liefert der Server einen echten HTTP-404-Fehler, wenn ein Nutzer direkt https://meinedomain.de/flight/3 aufruft oder die Seite neu lädt. Der Server kennt keine Datei unter diesem Pfad.

Fix: Den Webserver so konfigurieren, dass alle Anfragen auf index.html weitergeleitet werden.
Nginx: try_files $uri $uri/ /index.html;
Apache: RewriteRule ^ index.html [L] in .htaccess
Vercel/Netlify: automatisch konfiguriert für SPAs.

Aufgabe 1 Routing einrichten

Migriere FlugBoard zur Multi-Seiten-Struktur mit React Router.

  • Installiere react-router-dom
  • Wickle die App in main.tsx in <BrowserRouter>
  • Erstelle src/pages/DeparturePage.tsx und src/pages/ArrivalPage.tsx – beide nutzen useFlights() und rendern je ein FlightBoard

Aufgabe 2 FlightDetailPage mit useParams

Erstelle eine Detailseite für einzelne Flüge, die über die URL angesteuert wird.

  • Erstelle src/pages/FlightDetailPage.tsx, die mit useParams die Flug-ID aus der URL liest
  • Die Seite lädt den Flug einzeln vom Backend: GET http://localhost:8000/api/flights/:id
  • Zeige während des Ladens einen Ladezustand an, und bei einem Fehler eine Fehlermeldung
  • Implementiere einen „Zurück“-Button mit navigate(-1)
  • Klick auf eine FlightCard-Zeile soll per navigate(`/flight/${flight.id}`) zur Detailseite führen
Aufgabe 3 404-Seite

Erstelle eine ansprechende Fehlerseite für unbekannte Pfade.

  • Erstelle src/pages/NotFoundPage.tsx
  • Zeige den eingegebenen Pfad an, der nicht gefunden wurde – verwende useLocation() für location.pathname
  • Füge einen <Link to="/">-Button zur Startseite hinzu
  • Registriere die Route in App.tsx: <Route path="*" element={<NotFoundPage />} />
  • Teste: localhost:5173/irgendein-pfad soll die 404-Seite zeigen
Bonus Query-Parameter mit useSearchParams

Implementiere URL-basierte Filter, sodass Filterzustände in der URL gespeichert und per Bookmark/Link geteilt werden können.

  • Ersetze in DeparturePage den useLocalStorage-basierten Filter durch useSearchParams aus React Router
  • Die URL /?status=delayed&q=LH soll den Statusfilter „Verspätet“ und die Suche „LH“ vorbelegen
  • Verwende setSearchParams({ status, q }) beim Ändern der Filter, um die URL zu aktualisieren
  • Lese Werte mit: const [searchParams] = useSearchParams(); const status = searchParams.get('status') ?? 'all';
  • Teste: Filtere nach „delayed“, kopiere die URL und öffne sie in einem neuen Tab – der Filter soll direkt aktiv sein
