React Router

React ca. 105 min

Lernziele

  • Mit <Link> und <NavLink> navigieren
  • URL-Parameter mit useParams auslesen
  • Programmatisch navigieren mit useNavigate
  • Eine 404-Seite einrichten

1. Was ist Client-Side Routing?

In einer klassischen Multi-Page-App (MPA) führt jeder Klick auf einen Link dazu, dass der Browser eine neue HTTP-Anfrage schickt, der Server eine neue HTML-Datei ausliefert und die Seite komplett neu geladen wird. State geht verloren, der Nutzer sieht einen kurzen Ladevorgang.

In einer Single Page Application (SPA) mit Client-Side Routing passiert das nicht. JavaScript fängt den Klick auf <a>-Tags ab, aktualisiert die URL in der Browser-History – ohne eine neue Seite zu laden – und rendert die passende Komponente. Die React-App läuft durch, der State bleibt erhalten, das Erlebnis wirkt wie eine native App.

  Multi-Page-App SPA (React Router)
Navigation Voller Seitenneuladen Nur URL + Komponente wechseln
State Geht bei Navigation verloren Bleibt erhalten
URL Jede Seite eigene Datei Immer index.html, Router rendert Komponente
Server Liefert jede Seite einzeln Muss alle Pfade auf index.html weiterleiten
ℹ
URLs sehen normal aus

Obwohl die SPA technisch immer dieselbe index.html ausliefert, sehen die URLs ganz normal aus: /departures, /flight/3, /arrivals. Die Browser-History funktioniert wie gewohnt (Vor/Zurück-Tasten). Bookmarks funktionieren – solange der Server korrekt konfiguriert ist (dazu später mehr).

2. Installation und Einrichtung

React Router ist keine eingebaute React-Funktion, sondern eine externe Bibliothek. Für Browser-Apps verwenden wir das Paket react-router-dom (v6).

Terminal Bash 
npm install react-router-dom

Der BrowserRouter muss die gesamte App umschließen, damit alle Komponenten auf Routing-Hooks und -Komponenten zugreifen können. Der ideale Ort ist main.tsx:

src/main.tsx TypeScript 
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';
import { ThemeProvider } from './context/ThemeContext';
import App from './App';
import './styles.css';

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <BrowserRouter
      future={{
        v7_startTransition: true,
        v7_relativeSplatPath: true,
      }}
    >
      <ThemeProvider>
        <App />
      </ThemeProvider>
    </BrowserRouter>
  </StrictMode>
);
ℹ
React Router Future Flag

In React Router v6 erscheinen oft Warnungen zum kommenden v7-Verhalten (v7_startTransition und v7_relativeSplatPath). Mit den Future-Flags aktivierst du beide Verhaltensänderungen bereits jetzt und hältst die Konsole sauber.

💡
BrowserRouter vs. HashRouter

BrowserRouter verwendet die echte URL-History-API: /flight/3. HashRouter verwendet das Hash-Fragment: /#/flight/3. BrowserRouter ist die bevorzugte Wahl für moderne Apps, erfordert aber eine korrekte Server-Konfiguration. HashRouter funktioniert auch ohne Server-Anpassung, sieht aber weniger professionell aus.

3. Routes definieren

In React Router v6 werden Routen mit den Komponenten <Routes> und <Route> deklarativ beschrieben. Verschachtelte Routen ermöglichen ein gemeinsames Layout für mehrere Seiten.

src/App.tsx (mit Routing) TypeScript 
import { Routes, Route, Navigate } from 'react-router-dom';
import Layout from './components/Layout';
import FlightListPage from './pages/FlightListPage';
import FlightDetailPage from './pages/FlightDetailPage';
import NotFoundPage from './pages/NotFoundPage';

/**
 * Root component for lesson 2.7.
 * Defines the client-side route structure with React Router v6.
 */
function App() {
  return (
    <Routes>
      <Route path="/" element={<Layout />}>
        <Route index element={<Navigate to="/departures" replace />} />
        {/* Eine Seitenkomponente für beide Listen; key sorgt dafür, dass React
            beim Wechsel eine neue Instanz erzeugt (z.B. Formular wieder zu) */}
        <Route path="departures" element={<FlightListPage key="departure" type="departure" />} />
        <Route path="arrivals" element={<FlightListPage key="arrival" type="arrival" />} />
        <Route path="flight/:id" element={<FlightDetailPage />} />
        <Route path="*" element={<NotFoundPage />} />
      </Route>
    </Routes>
  );
}

export default App;

Die index-Route greift bei genau /. Sie leitet mit <Navigate> auf /departures weiter – so hat jede Seite eine eindeutige URL, und der Navigationslink „Abflüge“ wird auch auf der Startseite als aktiv markiert. replace verhindert, dass / in der History bleibt.

Das Layout-Muster funktioniert über die <Outlet />-Komponente. Outlet ist ein Platzhalter in der Layout-Komponente, an dem React Router die jeweilige Kind-Seite einfügt. (Wozu useFlights und context hier dienen, zeigt der Projektschritt.)

src/components/Layout.tsx TypeScript 
import { Link, NavLink, Outlet } from 'react-router-dom';
import { CSSProperties } from 'react';
import { useTheme } from '../context/ThemeContext';
import useFlights from '../hooks/useFlights';
import './Layout.css';

/**
 * Shared layout with top navigation bar.
 * NavLinks highlight the active route; theme toggle is always visible.
 * Loads the flights once and passes them to every page via the Outlet context,
 * so switching between pages does not trigger a new request.
 */
const Layout = () => {
  const { colors, theme, toggleTheme } = useTheme();
  const flightData = useFlights();
  const themeVars = {
    '--app-bg': colors.bg,
    '--app-card-bg': colors.bgCard,
    '--app-sidebar-bg': colors.bgSidebar,
    '--app-text': colors.text,
    '--app-muted': colors.textMuted,
    '--app-border': colors.border,
    '--app-accent': colors.accent,
  } as CSSProperties;

  return (
    // Inline style remains for runtime theme token injection into CSS variables.
    <div className="app-root" style={themeVars}>
      <header className="top-nav">
        <Link to="/" className="brand-link">
          ✈ FlugBoard 2.7
        </Link>

        <NavLink
          to="/departures"
          className={({ isActive }) => `nav-link${isActive ? ' active' : ''}`}
        >
          Abflüge
        </NavLink>

        <NavLink
          to="/arrivals"
          className={({ isActive }) => `nav-link${isActive ? ' active' : ''}`}
        >
          Ankünfte
        </NavLink>

        <div className="top-nav-actions">
          <button onClick={toggleTheme} className="theme-toggle">
            {theme === 'dark' ? '☀️' : '🌙'}
          </button>
        </div>
      </header>

      <main className="page-content">
        <Outlet context={flightData} />
      </main>
    </div>
  );
};

export default Layout;
ℹ
pages/ vs. components/

Seitenkomponenten in src/pages/ abzulegen ist eine verbreitete Konvention. Seiten sind Komponenten, die direkt einer Route zugeordnet sind – sie laden Daten und koordinieren andere Komponenten. src/components/ enthält kleinere, wiederverwendbare Bausteine ohne direkte Route-Bindung.

5. URL-Parameter mit useParams

URL-Parameter erlauben es, dynamische Werte in der URL zu kodieren. Die Route path="flight/:id" wird bei /flight/3 aktiviert, und useParams gibt { id: "3" } zurück.

⚠
URL-Parameter sind immer strings

useParams gibt immer string | undefined zurück, niemals eine Zahl. Für numerische IDs muss explizit konvertiert werden: const numId = Number(id) oder parseInt(id, 10). Vor der Konvertierung immer prüfen, ob id definiert und gültig ist.

src/pages/FlightDetailPage.tsx TypeScript 
import { useParams, useNavigate } from 'react-router-dom';
import { useState, useEffect } from 'react';
import { Flight } from '../types/flight';
import FlightDetail from '../components/FlightDetail';

const API_URL = 'http://localhost:8000';

/**
 * Detail page for a single flight, loaded by ID from the URL parameter.
 * Uses useParams to get the flight ID and fetches from the backend.
 */
const FlightDetailPage = () => {
  const { id } = useParams<{ id: string }>();
  const navigate = useNavigate();

  const [flight, setFlight]     = useState<Flight | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError]       = useState<string | null>(null);

  useEffect(() => {
    if (!id) return;
    const controller = new AbortController();

    const load = async () => {
      let isAborted = false;

      try {
        setIsLoading(true);
        setError(null);
        const res = await fetch(`${API_URL}/api/flights/${id}`, {
          signal: controller.signal,
        });
        if (!res.ok) throw new Error(`Flug ${id} nicht gefunden`);
        const data: Flight = await res.json();
        setFlight(data);
      } catch (err) {
        if (err instanceof Error && err.name === 'AbortError') {
          isAborted = true;
        } else if (err instanceof Error) {
          setError(err.message);
        }
      } finally {
        if (!isAborted) {
          setIsLoading(false);
        }
      }
    };

    load();
    return () => controller.abort();
  }, [id]);

  if (isLoading) {
    return <p className="state-block state-block--muted">Laden...</p>;
  }

  if (error || !flight) {
    return (
      <div>
        <p className="error-text">{error ?? 'Flug nicht gefunden'}</p>
        <button
          onClick={() => navigate(-1)}
          className="action-btn action-btn--neutral action-btn--small"
        >
          ← Zurück
        </button>
      </div>
    );
  }

  return (
    <div>
      <button
        onClick={() => navigate(-1)}
        className="action-btn action-btn--neutral action-btn--small back-link"
      >
        ← Zurück
      </button>
      <FlightDetail flight={flight} onClose={() => navigate(-1)} />
    </div>
  );
};

export default FlightDetailPage;

6. Programmatisch navigieren mit useNavigate

Während <Link> für deklarative Navigation im JSX zuständig ist, erlaubt useNavigate das programmatische Navigieren als Reaktion auf Events – z.B. nach dem Absenden eines Formulars, nach einem API-Call oder beim Klick auf eine Tabellenzeile.

Bei uns löst der Klick auf eine Zeile wie bisher den Callback onFlightSelect aus (seit Lektion 1.5). Neu ist nur, was die Seite damit macht: Statt ein Detail-Panel zu öffnen, navigiert sie zur Detailseite. FlightCard selbst bleibt unverändert und weiß nichts vom Router – deshalb funktionieren auch die Tests aus Lektion 2.6 ohne Router weiter.

src/pages/FlightListPage.tsx (Ausschnitt) TypeScript 
import { useNavigate } from 'react-router-dom';
// ...

const FlightListPage = ({ type }: FlightListPageProps) => {
  const navigate = useNavigate();
  // ...

        <FlightBoard
          // ...
          onFlightSelect={(flight: Flight) => navigate(`/flight/${flight.id}`)}
        />

useNavigate gibt eine Funktion zurück, die verschiedene Argumente akzeptiert:

useNavigate – Möglichkeiten TypeScript 
const navigate = useNavigate();

// Zu einer bestimmten URL navigieren
navigate('/arrivals');
navigate(`/flight/${id}`);

// Relative Navigation in der Browser-History
navigate(-1);   // Einen Schritt zurück (wie Browser-Zurück-Taste)
navigate(1);    // Einen Schritt vor (wie Browser-Vor-Taste)
navigate(-2);   // Zwei Schritte zurück

// Mit Options: replace statt push (kein History-Eintrag)
navigate('/departures', { replace: true });
// Kein Zurück-Button möglich nach dem Navigieren – gut für Loginseiten

// Mit State (wird NICHT in der URL sichtbar)
navigate('/flight/3', { state: { from: 'departures' } });
// In der Zielseite lesen:
const location = useLocation();
console.log(location.state?.from); // 'departures'

useLocation gibt Informationen über die aktuelle URL zurück:

useLocation – aktuelle URL lesen TypeScript 
import { useLocation } from 'react-router-dom';

const NotFoundPage = () => {
  const location = useLocation();

  // location.pathname: '/flight/999'
  // location.search:   '?status=delayed'
  // location.hash:     '#details'

    <div>
      <h1>404 – Seite nicht gefunden</h1>
      <p>
        Der Pfad <code>{location.pathname}</code> existiert nicht.
      </p>
    </div>
  );
};

Projektschritt

Projektschritt 2.7

FlugBoard zu einer Multi-Seiten-App migrieren

Wir verwandeln FlugBoard in eine Multi-Seiten-App mit eigenen URLs für Abflüge, Ankünfte und Flugdetails. Dabei ändert sich die Aufteilung der Oberfläche:

  • Layout übernimmt, was auf jeder Seite gleich ist: Logo, Navigation und Theme-Umschalter. Die Theme-Variablen (--app-bg usw. aus Lektion 2.4) setzt jetzt Layout statt App.
  • Der Seitenkopf (Titel, „Aktualisiert“, Buttons) gehört zur jeweiligen Seite. AirportHeader geht damit in Layout und Seitenkopf auf und entfällt.
  • Der Typ-Filter (Abflug/Ankunft) entfällt – das erledigen jetzt die Routen. FilterBar und useFlightFilters verlieren typeFilter.
  • Das Detail-Panel wird zur eigenen Seite /flight/:id.
  • Globale Stile wandern von App.css nach src/styles.css (Import in main.tsx), weil App nur noch Routen definiert.

Schritt 1: Installation und BrowserRouter

Terminal Bash 
npm install react-router-dom

Danach main.tsx wie in Abschnitt 2 gezeigt anpassen.

Schritt 2: Daten einmal im Layout laden

Würde jede Seite useFlights() selbst aufrufen, hätte jede ihren eigenen State: Bei jedem Wechsel zwischen Abflügen und Ankünften würde neu geladen (siehe „Geteilter State aus Custom Hook“ in Lektion 2.5). Deshalb ruft Layout den Hook einmal auf und gibt das Ergebnis über <Outlet context={flightData} /> an die aktive Seite weiter (siehe Layout in Abschnitt 3). Die Seiten lesen es mit useOutletContext – verpackt in einen kleinen, typisierten Hook:

src/hooks/useFlightData.ts TypeScript 
import { useOutletContext } from 'react-router-dom';
import { UseFlightsReturn } from './useFlights';

/**
 * Returns the flight data that Layout loads once and passes down
 * via <Outlet context={...} />.
 */
const useFlightData = () => useOutletContext<UseFlightsReturn>();

export default useFlightData;

Damit der Typ dort verfügbar ist, wird in useFlights.ts das Interface exportiert: export interface UseFlightsReturn { ... }.

Schritt 3: Eine Seite für Abflüge und Ankünfte

Abflüge und Ankünfte sehen gleich aus und unterscheiden sich nur in Titel und Liste. Statt zwei fast identischer Dateien schreiben wir eine Komponente mit dem Prop type:

src/pages/FlightListPage.tsx TypeScript 
import { useState } from 'react';
import { useNavigate } from 'react-router-dom';
import { Flight, FlightType } from '../types/flight';
import useFlightData from '../hooks/useFlightData';
import useFlightFilters from '../hooks/useFlightFilters';
import FlightBoard from '../components/FlightBoard';
import SearchBar from '../components/SearchBar';
import FilterBar from '../components/FilterBar';
import AddFlightForm from '../components/AddFlightForm';

interface FlightListPageProps {
  type: FlightType;
}

/**
 * Page showing either departures or arrivals – one component for both routes.
 * The data comes from Layout (useFlightData); clicking a row opens the detail page.
 */
const FlightListPage = ({ type }: FlightListPageProps) => {
  const navigate = useNavigate();
  const {
    flights,
    isLoading,
    error,
    lastUpdated,
    isRefreshing,
    refetch,
    addFlight,
    deleteFlight,
    updateStatus,
  } = useFlightData();

  const {
    searchQuery,
    setSearchQuery,
    statusFilter,
    setStatusFilter,
    resetFilters,
    hasActiveFilters,
    filteredDepartures,
    filteredArrivals,
  } = useFlightFilters(flights);

  const visibleFlights = type === 'departure' ? filteredDepartures : filteredArrivals;
  const title = type === 'departure' ? 'Abflüge' : 'Ankünfte';

  const [showAddForm, setShowAddForm] = useState(false);

  const formatTime = (d: Date) =>
    d.toLocaleTimeString('de-AT', { hour: '2-digit', minute: '2-digit', second: '2-digit' });

  if (error) {
    return (
      <div className="state-block state-block--error">
        <p className="error-title">Fehler: {error}</p>
        <p className="error-hint">
          Ist das Backend gestartet?{' '}
          <code className="inline-code">
            deno task dev
          </code>{' '}
          im backend/-Ordner ausführen.
        </p>
        <button onClick={refetch} className="action-btn action-btn--neutral">
          Neu laden
        </button>
      </div>
    );
  }

  return (
    <div>
      <div className="page-head">
        <div>
          <h2 className="page-title">{title}</h2>
          {lastUpdated && (
            <span className="page-meta">
              Aktualisiert: {formatTime(lastUpdated)}
              {isRefreshing && ' (wird aktualisiert...)'}
            </span>
          )}
        </div>
        <div className="head-actions">
          <button
            onClick={refetch}
            disabled={isRefreshing}
            className="action-btn action-btn--neutral"
          >
            {isRefreshing ? 'Lädt...' : 'Aktualisieren'}
          </button>
          <button
            className="action-btn action-btn--primary"
            onClick={() => setShowAddForm((v) => !v)}
          >
            {showAddForm ? 'Abbrechen' : '+ Flug hinzufügen'}
          </button>
        </div>
      </div>

      {showAddForm && (
        <AddFlightForm
          onAdd={async (f) => {
            try {
              await addFlight(f);
              setShowAddForm(false);
            } catch (err) {
              console.error('Fehler beim Hinzufügen:', err);
            }
          }}
          onCancel={() => setShowAddForm(false)}
        />
      )}

      <div className="toolbar">
        <SearchBar value={searchQuery} onChange={setSearchQuery} placeholder="Suche nach Flug, Airline, Ziel…" />
        <FilterBar
          statusFilter={statusFilter}
          onStatusChange={setStatusFilter}
          onReset={resetFilters}
          hasActiveFilters={hasActiveFilters}
        />
      </div>

      {isLoading ? (
        <div className="board-loading board-loading--muted">
          <div className="loading-spinner" aria-hidden="true"></div>
          <p>Flugdaten werden geladen...</p>
        </div>
      ) : (
        <FlightBoard
          flights={visibleFlights}
          title=""
          count={visibleFlights.length}
          onFlightSelect={(flight: Flight) => navigate(`/flight/${flight.id}`)}
          onFlightDelete={deleteFlight}
          onStatusChange={updateStatus}
          onResetFilters={hasActiveFilters ? resetFilters : undefined}
        />
      )}
    </div>
  );
};

export default FlightListPage;

Schritt 5: Routing in App.tsx

src/App.tsx TypeScript 
import { Routes, Route, Navigate } from 'react-router-dom';
import Layout from './components/Layout';
import FlightListPage from './pages/FlightListPage';
import FlightDetailPage from './pages/FlightDetailPage';
import NotFoundPage from './pages/NotFoundPage';

/**
 * Root component for lesson 2.7.
 * Defines the client-side route structure with React Router v6.
 */
function App() {
  return (
    <Routes>
      <Route path="/" element={<Layout />}>
        <Route index element={<Navigate to="/departures" replace />} />
        {/* Eine Seitenkomponente für beide Listen; key sorgt dafür, dass React
            beim Wechsel eine neue Instanz erzeugt (z.B. Formular wieder zu) */}
        <Route path="departures" element={<FlightListPage key="departure" type="departure" />} />
        <Route path="arrivals" element={<FlightListPage key="arrival" type="arrival" />} />
        <Route path="flight/:id" element={<FlightDetailPage />} />
        <Route path="*" element={<NotFoundPage />} />
      </Route>
    </Routes>

Beide Listen-Routen verwenden dieselbe Komponente. Der key sorgt dafür, dass React beim Wechsel eine neue Instanz erzeugt – sonst bliebe z.B. ein geöffnetes Formular beim Wechsel offen.

💡
Vite-Dev-Server und Client-Side Routing

Im Entwicklungsmodus leitet Vite alle Anfragen automatisch an index.html weiter, sodass direktes Aufrufen von localhost:5173/flight/3 funktioniert. Im Production-Build muss der Webserver (Nginx, Apache, Caddy...) entsprechend konfiguriert werden. Details dazu in Lektion 3.6 (Deployment).

Häufige Fehler

Fehler: <BrowserRouter> vergessen

useNavigate(), useParams() und alle anderen Routing-Hooks werfen einen Fehler, wenn sie außerhalb eines Routers aufgerufen werden: „useNavigate() may be used only in the context of a Router component“.

Fix: Sicherstellen, dass <BrowserRouter> in main.tsx die gesamte App umschließt – insbesondere auch alle Komponenten, die Routing-Hooks verwenden.

Fehler: <Outlet /> in der Layout-Komponente vergessen

Bei verschachtelten Routen (Route innerhalb eines anderen Route) muss die Eltern-Komponente <Outlet /> rendern. Fehlt es, werden die Kind-Routen überhaupt nicht angezeigt – ohne Fehlermeldung, nur leerer Inhalt.

Fix: In der Layout-Komponente <Outlet /> an der Stelle einfügen, wo der Seiteninhalt erscheinen soll. import { Outlet } from 'react-router-dom'; nicht vergessen.

Fehler: URL-Parameter als number erwartet, aber string erhalten

const { id } = useParams(); liefert id: string | undefined. Wird id direkt an eine API-Funktion übergeben, die eine number erwartet, entsteht ein TypeScript-Fehler oder ein „NaN“-Problem zur Laufzeit.

Fix: Explizit konvertieren und validieren: const numId = Number(id); if (!id || Number.isNaN(numId)) return <NotFoundPage />; Dann numId statt id verwenden. (navigate() darf nicht während des Renderns aufgerufen werden – zum Umleiten gibt es <Navigate to="..." />.)

Fehler: 404 bei direktem URL-Aufruf auf dem Produktionsserver

Nach dem Deployment liefert der Server einen echten HTTP-404-Fehler, wenn ein Nutzer direkt https://meinedomain.de/flight/3 aufruft oder die Seite neu lädt. Der Server kennt keine Datei unter diesem Pfad.

Fix: Den Webserver so konfigurieren, dass alle Anfragen auf index.html weitergeleitet werden.
Nginx: try_files $uri $uri/ /index.html;
Apache: RewriteRule ^ index.html [L] in .htaccess
Vercel/Netlify: automatisch konfiguriert für SPAs.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was passiert bei Client-Side Routing, wenn man auf einen Link klickt?

Erklärung: Die URLs sehen trotzdem normal aus (z. B. /flight/3), und Zurück/Vor funktionieren.

Frage 2 Wofür steht <Outlet /> in einer Layout-Komponente?

Erklärung: So teilen sich mehrere Seiten Header und Navigation, nur der Inhalt im Outlet wechselt.

Frage 3 Wie liest man in der Route /flight/:id den Wert von id aus?

Erklärung: URL-Parameter sind immer Strings; für eine Zahl wandelt man mit Number(id) um.

Frage 4 Was unterscheidet <NavLink> von <Link>?

Erklärung: Ideal für Navigationsleisten, in denen der aktuelle Menüpunkt markiert sein soll.

Frage 5 Warum verwendet man für Links innerhalb der App <Link to="/arrivals"> statt <a href="/arrivals">?

Erklärung: Link rendert zwar ein <a>, verhindert aber das Neuladen und navigiert über React Router.
