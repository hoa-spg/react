Lektion 1.3 — Teil 1: React Einführung

Komponenten & Props (einfach)

React ca. 60 min Zwischenschritt

Lernziele

  • Komponenten als wiederverwendbare UI-Bausteine verstehen
  • Einfache Props zwischen Eltern- und Kindkomponenten weitergeben
  • Ohne komplizierte Typ-Tricks eine kleine Struktur aufbauen
  • Erste Aufteilung von App.tsx in mehrere Dateien umsetzen
  • Erklären, warum Komponenten-CSS global wirkt und was CSS Modules daran ändern

1 — Idee: Eine große App in kleine Teile zerlegen

In Lektion 1.2 war alles in einer Datei. Das war für den Start gut, wird aber schnell unübersichtlich. Deshalb teilen wir die Oberfläche jetzt in kleine Komponenten auf.

Eine Komponente ist einfach eine Funktion, die JSX zurückgibt. Eine andere Komponente kann sie dann wie ein eigenes HTML-Element verwenden.

Sehr einfache Komponente TypeScript 
const HelloBox = () => {
  return <div>Hallo vom FlugBoard</div>;
};

function App() {
  return (
    <main>
      <HelloBox />
    </main>
  );
}

2 — Props ohne Ballast

Props sind Eingabewerte für Komponenten.

Mini-Beispiel: ein String-Prop TypeScript 
const Welcome = (props: { name: string }) => {
  return <p>Hallo {props.name}!</p>;
};

function App() {
  return <Welcome name="Max" />;
}
src/components/FlightRow.tsx TypeScript 
import './FlightRow.css';

type FlightRowProps = {
  flightNumber: string;
  airline: string;
  destination: string;
  time: string;
};

const FlightRow = (props: FlightRowProps) => {
  return (
    <tr>
      <td className="flight-row-cell">{props.flightNumber}</td>
      <td className="flight-row-cell">{props.airline}</td>
      <td className="flight-row-cell">{props.destination}</td>
      <td className="flight-row-cell">{props.time}</td>
    </tr>
  );
};

export default FlightRow;
💡
Bewusst einfacher Schritt

Diese Lektion ist als sanfter Einstieg gedacht. Die erweiterten TypeScript-Muster (Union-Typen, Record, Destructuring, Spread) kommen erst in der Lektion 1.4.

3 — Exkurs: Ist Komponenten-CSS gekapselt?

Jede Komponente bekommt bei uns eine eigene CSS-Datei, die sie mit import './FlightRow.css'; einbindet. Das sieht so aus, als würden die Regeln nur für diese Komponente gelten. Das stimmt aber nicht: Vite sammelt alle importierten CSS-Dateien in einem gemeinsamen Stylesheet. Jede Regel gilt also für die ganze Seite.

Solange jede Klasse einen eindeutigen Namen hat, ist das kein Problem. Gibt es aber in FlightRow.css und in AirportHeader.css je eine Klasse .title, dann wirken beide Regeln auf beide Komponenten – und bei Widersprüchen gewinnt wie immer die später geladene Regel (Cascade aus dem HTML-&-CSS-Kurs).

Die Alternative: CSS Modules

Endet der Dateiname auf .module.css, behandelt Vite die Datei als CSS Module: Jede Klasse bekommt beim Bauen einen eindeutigen Namen, z. B. wird aus .cell die Klasse ._cell_1mp39_1. Eine gleichnamige Klasse in einer anderen Komponente stört dann nicht mehr.

src/components/FlightRow.module.css CSS 
.cell {
  border-bottom: 1px solid #30363d;
  padding: 0.7rem 1rem;
}

Weil der echte Klassenname erst beim Bauen entsteht, kann man ihn nicht als Text in className schreiben. Stattdessen liefert der Import ein Objekt (hier styles genannt), das jeden Klassennamen aus der Datei auf den erzeugten Namen abbildet: styles.cell enthält "_cell_1mp39_1".

src/components/FlightRow.tsx (als CSS Module) TypeScript 
import styles from './FlightRow.module.css';

// ... FlightRowProps wie oben

const FlightRow = (props: FlightRowProps) => {
  return (
    <tr>
      <td className={styles.cell}>{props.flightNumber}</td>
      <td className={styles.cell}>{props.airline}</td>
      <td className={styles.cell}>{props.destination}</td>
      <td className={styles.cell}>{props.time}</td>
    </tr>
  );
};
Normales CSS (FlightRow.css) CSS Module (FlightRow.module.css)
Import import './FlightRow.css'; import styles from './FlightRow.module.css';
Klasse verwenden className="flight-row-cell" className={styles.cell}
Gültigkeit ganze Seite – Namen müssen eindeutig sein nur die Komponente, die das Modul importiert
In den DevTools lesbar: flight-row-cell erzeugt: _cell_1mp39_1
ℹ
Warum der Kurs bei normalem CSS bleibt

Im FlugBoard beginnt jede Klasse mit dem Namen ihrer Komponente (flight-row-cell, später z. B. status-pill). So entstehen keine Kollisionen, die Klassennamen bleiben in den Entwicklertools lesbar, und du kannst alles anwenden, was du im HTML-&-CSS-Kurs gelernt hast. In größeren Projekten mit vielen Komponenten sind CSS Modules eine gute Wahl – Vite und Next.js unterstützen sie ohne zusätzliche Einrichtung. Probiere es in der Bonus-Aufgabe aus.

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Komponentenname klein geschrieben

<flightrow /> wird als HTML-Tag interpretiert, nicht als React-Komponente.

Komponenten immer in PascalCase schreiben: <FlightRow />.

Fehler: Props-Name passt nicht

Du übergibst destination, die Komponente liest aber props.airport.

Prop-Namen beim Aufruf und in der Komponente identisch halten.

Fehler: Datei nicht exportiert

Ohne export default kann die Komponente nicht importiert werden.

Jede Komponenten-Datei mit export default ...; abschließen.

Bonus FlightRow als CSS Module

Schreibe zuerst testweise in AirportHeader.css die Regel .flight-row-cell { color: red; }. Obwohl sie in der Datei einer anderen Komponente steht, werden die Tabellenzellen rot – ein Beweis, dass normales Komponenten-CSS global wirkt.

Stelle dann FlightRow wie im Exkurs auf FlightRow.module.css mit der Klasse .cell und className={styles.cell} um. Sieh dir im Tab Elements der Entwicklertools den Klassennamen der Zellen an. Sind sie noch rot? Warum nicht? Entferne zum Schluss die Test-Regel wieder.

Quiz

6 Fragen · zum Aufklappen klicken

Frage 1 Was ist eine React-Komponente technisch?

Erklärung: Andere Komponenten verwenden sie dann wie ein eigenes HTML-Element, z. B. <FlightRow />.

Frage 2 Was passiert bei <flightrow /> (klein geschrieben)?

Erklärung: Komponentennamen immer in PascalCase schreiben: <FlightRow />.

Frage 3 Was sind Props?

Erklärung: Props funktionieren wie Funktionsargumente, z. B. <FlightRow destination="Wien" />.

Frage 4 Du übergibst destination="Wien", die Komponente liest aber props.airport. Was passiert?

Erklärung: Mit einem TypeScript-Interface für die Props meldet der Editor solche Tippfehler sofort.

Frage 5 Warum lässt sich eine Komponente aus einer anderen Datei nicht importieren?

Erklärung: Jede Komponenten-Datei endet mit einem Export, z. B. export default FlightRow;.

Frage 6 Gelten die Regeln aus import './FlightRow.css'; nur für die Komponente FlightRow?

Erklärung: Vite fasst alle importierten CSS-Dateien zu einem Stylesheet zusammen. Erst bei .module.css bekommt jede Klasse einen eindeutigen Namen, und man verwendet sie über das importierte Objekt, z. B. className={styles.cell}.
