Lektion 3.5 — Teil 3: Next.js

Playwright End-to-End Tests

Next.js ca. 75 min

Lernziele

  • E2E-Tests von Unit- und Integrationstests abgrenzen
  • Playwright in einem Next.js-Projekt einrichten
  • Wichtige User-Flows als stabile E2E-Szenarien formulieren
  • Locators und Assertions robust verwenden
  • Headless/Headed-Modus und Debugging-Tools nutzen
  • Tests in CI-Umgebungen einbinden

1. Was ist E2E-Testen?

End-to-End-Tests validieren komplette Benutzerflüsse im Browser. Anders als Komponententests prüfen sie nicht einzelne Bausteine, sondern die reale Integration aus Routing, Formularen, Netzwerk, Rendering und Navigation.

Gute E2E-Tests sind wenige, aber zentral: Login, Hauptnavigation, Kern-CRUD-Aktionen und kritische Fehlerpfade.

2. Playwright Setup

Terminal Bash 
npm init playwright@latest

# empfohlen im Kurs:
# - TypeScript
# - tests/ als Ordner
# - GitHub Actions optional
# - Chromium als Startbrowser
playwright.config.ts TypeScript 
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  retries: process.env.CI ? 2 : 0,
  use: {
    baseURL: 'http://127.0.0.1:3000',
    trace: 'on-first-retry',
  },
  webServer: {
    command: 'npm run dev',
    url: 'http://127.0.0.1:3000',
    reuseExistingServer: !process.env.CI,
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  ],
});

3. Erster E2E-Test für FlugBoard

Der erste Test sollte einen Kernfluss abdecken: Startseite laden, Suchfeld benutzen, Ergebnisliste validieren.

tests/flight-search.spec.ts TypeScript 
import { test, expect } from '@playwright/test';

test('filtert die Flugliste auf der Startseite', async ({ page }) => {
  await page.goto('/');

  await expect(page.getByRole('heading', { name: /flugboard/i })).toBeVisible();

  await page.getByRole('searchbox', { name: /suche/i }).fill('LH');

  await expect(page.getByText('LH123')).toBeVisible();
  await expect(page.getByText('OS404')).toHaveCount(0);
});
💡
Locators statt CSS-Selektoren

Nutze bevorzugt getByRole, getByLabel und getByText. Das macht Tests robuster gegen Layout-Änderungen.

4. Debugging und Stabilität

Nützliche Befehle Bash 
# Headed-Modus (Browser sichtbar)
npx playwright test --headed

# Nur ein Testfile
npx playwright test tests/flight-search.spec.ts

# UI Modus zum iterativen Debugging
npx playwright test --ui

# HTML Report anzeigen
npx playwright show-report
⚠
Flaky Tests vermeiden

Keine festen Sleeps mit waitForTimeout einbauen. Nutze stattdessen Assertions, die auf sichtbare Zustände warten.

Projektschritt

Projektschritt 3.5

E2E-Teststrecke für Next.js-FlugBoard aufbauen

  1. Playwright initialisieren und Config mit webServer setzen.
  2. Mindestens zwei Flows automatisieren: Suche und Detailnavigation.
  3. Fehlerfall ergänzen (z.B. 404-Seite bei ungültiger Route).
  4. Report lokal auswerten und mindestens einen flaky Schritt stabilisieren.

Häufige Fehler

Fehler: Base URL inkonsistent

Tests laufen lokal, aber in CI nicht, weil unterschiedliche Hosts/Ports genutzt werden.

Fix: Eine zentrale baseURL in der Playwright-Konfiguration setzen.

Fehler: Fragile CSS-Selektoren

Tests brechen bei kleinen Refactorings, weil sie auf Klassenketten basieren.

Fix: Auf semantische Locators wechseln (Role, Label, Text).

Fehler: Zu viele E2E-Szenarien

Jede Kleinigkeit wird als E2E-Test geschrieben. Die Pipeline wird langsam.

Fix: Nur Kernflüsse end-to-end testen; Details in Komponententests abdecken.

Aufgaben

Aufgabe 1 Playwright installieren und starten
  • Initialisiere Playwright mit TypeScript.
  • Prüfe, dass der Browser-Download erfolgreich ist.
  • Führe den generierten Beispieltest einmal aus.
Aufgabe 2 Kernflow: Suche + Navigation
  • Teste Suchfunktion auf der Startseite.
  • Navigiere von einem Eintrag zur Detailansicht.
  • Prüfe den Zurück-Flow zur Liste.
Aufgabe 3 CI-Vorbereitung
  • Setze retries für CI auf einen sinnvollen Wert.
  • Aktiviere Trace bei Retry.
  • Dokumentiere den Testbefehl für Teamkollegen.
Bonus Mobile Viewport
  • Ergänze ein zweites Projekt mit mobilem Viewport.
  • Teste denselben Such-Flow auf kleiner Breite.
