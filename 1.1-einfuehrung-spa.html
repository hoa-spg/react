Lektion 1.1 — Teil 1: React Einführung

Motivation & SPA-Konzepte

React ca. 60 min

Lernziele

  • Verstehen, welche Probleme React löst und warum es entstanden ist
  • Den Unterschied zwischen traditionellen Webseiten und Single-Page-Applications kennen
  • Das Konzept von Komponenten und deklarativem Rendering verstehen
  • React im Vergleich zu Vue, Angular und Svelte einordnen können
  • Den Überblick über das React-Ökosystem (Next.js, React Native) gewinnen

Das Problem — Warum brauchen wir React?

Um das Jahr 2013 sah typische Web-Entwicklung so aus: HTML für Struktur, CSS für Gestaltung, jQuery für Interaktivität. Der Server renderte bei jedem Request eine vollständige HTML-Seite und schickte sie zum Browser. DOM-Manipulation war direkt und imperativ: 



      

        

          dom-manipulation.js
          JavaScript
        

        
document.getElementById('counter').textContent = count;

      


      

        Das funktionierte gut für einfache Seiten. Doch als Web-Apps zunehmend komplexer wurden
        — Gmail, Facebook, Google Maps — offenbarte dieser Ansatz seine Grenzen:
        Wenn sich Daten an einer Stelle ändern, müssen manuell alle davon
        abhängigen DOM-Elemente aktualisiert werden. Bei fünf abhängigen
        Elementen bedeutet das fünf separate DOM-Updates. Das führt zu Bugs,
        inkonsistentem State und schwer wartbarem Code.
      


      
Vorher: Vanilla JS (imperativ)


      

        

          counter-vanilla.js
          JavaScript
        

        
// Zustand und DOM-Manipulation sind manuell verknüpft
let count = 0;
const btn = document.getElementById('btn');
const display = document.getElementById('count');
const statusText = document.getElementById('status');

btn.addEventListener('click', () => {
  count++;
  display.textContent = count;               // DOM Update 1
  statusText.textContent = count > 5         // DOM Update 2
    ? 'Viele Klicks!'
    : 'Noch wenige Klicks';
  if (count > 10) btn.disabled = true;       // DOM Update 3
  document.title = `Geklickt: ${count}`;    // DOM Update 4
  // Je mehr State, desto mehr manuelle DOM-Updates nötig
});

      


      
Nachher: React (deklarativ)


      

        

          Counter.tsx
          TSX
        

        
// React: Beschreibe WIE es aussehen soll, nicht WAS geändert werden soll
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>{count > 5 ? 'Viele Klicks!' : 'Noch wenige Klicks'}</p>
      <button
        onClick={() => setCount(c => c + 1)}
        disabled={count > 10}
      >
        Geklickt: {count}
      </button>
    </div>
  );
  // React berechnet automatisch, was im DOM geändert werden muss
}

      


      

        
ℹ

        

          
Deklarativ vs. Imperativ

          

            Imperativ bedeutet “tue Schritt A, dann B, dann C”.
            Deklarativ bedeutet “das soll das Ergebnis sein”.
            React ist deklarativ — du beschreibst den gewünschten Zustand der UI,
            React kümmert sich um die nötigen Änderungen am DOM.
          

        

      

    


    
    

      
Was ist eine Single-Page-Application?


      
MPA (Multi-Page Application) — traditionell

      
    
        
  • Browser sendet einen Request an den Server
    • 
        
  • Server rendert eine vollständige HTML-Seite und schickt sie zurück
    • 
        
  • Browser lädt die neue Seite vollständig neu
    • 
        
  • Jede Navigation = Seitenneuladen (langsam, Flackern, Zustand geht verloren)
    • 
        
  • Gut für: Blogs, Nachrichtenseiten, einfache Formulare
    • 
      


      
SPA (Single-Page Application)

      
    
        
  • Browser lädt beim ersten Aufruf eine minimale HTML-Seite und JavaScript
    • 
        
  • Navigation passiert clientseitig: JavaScript tauscht den Inhalt aus, ohne die Seite neu zu laden
    • 
        
  • Sehr schnelle Navigation nach dem ersten Laden
    • 
        
  • App-ähnliches Gefühl (kein Flackern, Zustand bleibt erhalten)
    • 
        
  • Gut für: Dashboards, Verwaltungsanwendungen, interaktive Tools
    • 
      


      

        

          MPA vs. SPA — Ablaufdiagramm
          Diagramm
        

        
MPA (Multi-Page Application):
Nutzer klickt Link
    → Browser: GET /produkte → Server: HTML rendern → Browser: Seite neu laden
    → Browser: GET /warenkorb → Server: HTML rendern → Browser: Seite neu laden

SPA (Single-Page Application):
Erster Aufruf:
    → Browser: GET / → Server: index.html + bundle.js → Browser: React startet
Weitere Navigation:
    → Nutzer klickt "Produkte" → React Router: Komponente tauschen → sofort
    → Nutzer klickt "Warenkorb" → React Router: Komponente tauschen → sofort
    (Kein Server-Roundtrip, kein Seitenneuladen)

      


      

        
⚠

        

          
Nachteile von SPAs

          

            SPAs haben auch Nachteile: Das erste Laden dauert länger (JavaScript muss
            geladen werden), SEO ist schwieriger (Suchmaschinen sehen zunächst leeres
            HTML), und der Browser-Zurück-Button muss explizit behandelt werden.
            Next.js (Teil 2 des Kurses) löst viele dieser Probleme.
          

        

      

    


    
    

      
Komponenten — Bausteine der UI


      

        Ohne Komponenten ist eine komplexe UI ein großes, verschachteltes Stück Code —
        schwer zu verstehen, schwer zu ändern, schwer wiederzuverwenden. Komponenten erlauben es,
        die UI in kleine, eigenständige, unabhängig wartbare Teile zu zerlegen.
      


      
Drei Kernprinzipien

      
    
        
  1. 
          Wiederverwendbarkeit: Eine Komponente einmal definieren, überall verwenden
        
    2. 
        
  2. 
          Isolation: Jede Komponente verwaltet ihren eigenen Zustand
        
    3. 
        
  3. 
          Zusammensetzbarkeit: Komplexe UIs aus einfachen Bausteinen aufbauen
        
    4. 
      


      
Beispiel: UI-Zerlegung des FlugBoard-Projekts


      

        

          Komponentenhierarchie FlugBoard
          Struktur
        

        
Gesamte App
├── AirportHeader
│   └── LiveClock
├── SearchBar
├── FilterBar
├── FlightBoard (Abflüge)
│   └── FlightCard (für jeden Flug)
│       └── FlightStatusBadge
└── FlightBoard (Ankünfte)
    └── FlightCard (für jeden Flug)
        └── FlightStatusBadge

      


      

        Jede Komponente ist wie ein eigenes Mini-Programm: Sie bekommt Daten rein
        (Props), verwaltet optional eigenen Zustand (State)
        und gibt JSX zurück. Eine Änderung in FlightStatusBadge
        betrifft alle Orte, wo die Komponente verwendet wird — das ist der Kern
        der Wiederverwendbarkeit.
      


      
Virtual DOM

      

        React hält eine Kopie der UI als JavaScript-Objekt im Arbeitsspeicher
        (Virtual DOM). Wenn sich State ändert, erstellt React eine
        neue virtuelle Repräsentation, vergleicht sie mit der alten
        (Reconciliation / Diffing) und aktualisiert nur die tatsächlich
        geänderten Teile des echten DOM. Das macht komplexe UI-Updates effizient.

Vue.js

      

        Sehr gut für Einsteiger, da die Template-Syntax HTML ähnelt. Gut für kleinere
        Teams. In der DACH-Region und Asien populär. Ähnliche Konzepte wie React
        (komponenten-basiert, reaktiv).
      


      
Angular

      

        Das einzige vollständige Framework — hat alles eingebaut: Router, HTTP-Client,
        Forms. Von Google entwickelt, stark in Unternehmensumgebungen verbreitet. Sehr
        TypeScript-orientiert. Höhere Lernkurve als React oder Vue.
      


      
Svelte

      

        Ein Compiler statt einer Library oder eines Frameworks. Svelte-Code wird zu
        nativem JavaScript kompiliert — kein Virtual DOM, sehr kleine Bundle-Größe
        und sehr schnell zur Laufzeit. Innovativer Ansatz, aber kleineres Ökosystem.
      


      
Warum React lernen?

      
    
        
  1. Größter Marktanteil → mehr Jobmöglichkeiten
    2. 
        
  2. Riesiges Ökosystem: unzählige Bibliotheken, Tutorials, Stack Overflow-Antworten
    3. 
        
  3. Transferierbar: React-Kenntnisse direkt anwendbar für React Native (mobile Apps) und Next.js (Full-Stack)
    4. 
        
  4. JSX ist “just JavaScript” — kein eigenständiges Template-System zu erlernen
    5. 
        
  5. Von Meta eingesetzt bei Facebook, Instagram, WhatsApp Web → battle-tested
    6. 
      


      

        
✓

        

          
Kein Framework ist für alle Situationen das Beste

          

            React eignet sich besonders für große, komplexe Anwendungen mit einem
            aktiven Ökosystem. Für einfache Projekte kann Vue.js oder Svelte die
            bessere Wahl sein. Die Konzepte (Komponenten, reaktiver State) sind aber in allen
            Frameworks ähnlich — wer React kennt, findet sich in den anderen
            schnell zurecht.

Wie funktioniert React technisch? (Überblick)


      
JSX

      

        JSX (JavaScript XML) ist eine Syntaxerweiterung, die es erlaubt,
        HTML-ähnlichen Code in JavaScript zu schreiben. JSX wird von einem Compiler
        (Babel / TypeScript) zu React.createElement()-Aufrufen transformiert.
        Im Browser läuft nur normales JavaScript — kein Browser versteht JSX direkt.
      


      
Virtual DOM

      

        React hält eine Kopie des UI als JavaScript-Objekt (Virtual DOM).
        Bei State-Änderungen erstellt React eine neue virtuelle Repräsentation,
        vergleicht sie mit der alten (Reconciliation / Diffing), und aktualisiert
        nur die veränderten Teile des echten DOM.
      


      
React Fiber

      

        Reacts internes Rendering-System (seit React 16). Es erlaubt React, das Rendering in
        Chunks aufzuteilen und zu pausieren — so bleibt die UI auch bei komplexen Updates
        reaktionsfähig und ruckelfrei.
      


      
Unidirektionaler Datenfluss

      

        Daten fließen in React immer von oben nach unten — von
        Eltern- zu Kind-Komponente via Props. Änderungen fließen durch Event-Handler
        nach oben. Dieser einseitige Datenfluss macht Apps vorhersehbarer und einfacher zu
        debuggen.
      


      

        

          Datenfluss in React
          Diagramm
        

        
     Elternkomponente
      │ Props (Daten fließen ↓)
      ▼
  Kindkomponente ──── Event-Handler (Änderungen fließen ↑)
      │ Props
      ▼
  Enkelkomponente

Häufige Missverständnisse


      

        
„React ist ein Full-Stack-Framework“

        

          React ist ausschließlich eine UI-Library — es rendert Komponenten im Browser.
          Für Full-Stack-Funktionalität (Datenbank, API, Authentication) braucht man
          Next.js oder einen separaten Backend-Server.
        

        
React = UI-Schicht. Next.js oder ein separates Backend = Full-Stack.

      


      

        
„SPA ist immer besser als MPA“

        

          SPAs haben Vorteile bei Interaktivität und Navigation, aber Nachteile beim ersten
          Ladevorgang und bei SEO. Für einen Blog oder eine Nachrichtenseite ist eine klassische
          MPA oft die bessere Wahl.
        

        
Next.js kombiniert beide Ansätze: SSR für SEO, clientseitige Navigation für Performance.

      


      

        
„Virtual DOM ist immer schneller als echter DOM“

        

          Der Virtual DOM ist nicht prinzipiell schneller. Er macht komplexe Updates effizienter,
          kann aber bei sehr einfachen Updates overhead erzeugen. Svelte verzichtet deshalb ganz
          auf den Virtual DOM und kompiliert direkten DOM-Code.
        

        
Virtual DOM = effizienter bei komplexen UIs, nicht universell schneller.

      


      

        
„React lernen heißt React immer einsetzen“

        

          Für einfache Seiten (Blog, Landing Page, Dokumentation) ist React oft Overkill.
          Statische HTML/CSS-Seiten oder einfaches Vanilla JS können die bessere und
          schnellere Lösung sein.
        

        
Das richtige Werkzeug für den richtigen Job — React glänzt bei komplexen, interaktiven UIs.
