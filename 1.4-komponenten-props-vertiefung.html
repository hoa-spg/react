Komponenten & Props

React ca. 90 min

Lernziele

  • Eigene Funktionskomponenten erstellen

  • Komponenten zusammensetzen (Komposition)
  • Children Props verstehen
  • Default Props und optionale Props mit ? nutzen

Was ist eine Komponente?

Eine Komponente ist der wichtigste Baustein in React. Sie ist eine TypeScript-Funktion, die JSX zurückgibt und einen eigenständigen, wiederverwendbaren Teil der Benutzeroberfläche repräsentiert. Komponenten können verschachtelt werden: eine Komponente nutzt andere Komponenten – genau wie HTML-Elemente verschachtelt werden.

Die wichtigste Konvention: Komponenten-Namen beginnen immer mit einem Großbuchstaben (PascalCase).

Einfache Komponente TypeScript 
// Einfachste mögliche Komponente – gibt JSX zurück
const WelcomeMessage = () => {
  return <h1>Willkommen beim FlugBoard!</h1>;
};

// Kurzschreibweise mit implizitem Return:
const WelcomeMessage = () => <h1>Willkommen beim FlugBoard!</h1>;

// Verwendung in einer anderen Komponente:
function App() {
  return (
    <div>
      <WelcomeMessage />  {/* Großbuchstabe = eigene Komponente */}
      <p>Flughafen Wien-Schwechat</p>
    </div>
  );
}
ℹ
Groß- vs. Kleinbuchstabe ist entscheidend

React unterscheidet anhand des ersten Buchstabens: <div> ist ein nativer HTML-Tag, <Div> wäre eine benutzerdefinierte Komponente. Ein Komponentenname mit Kleinbuchstaben wird als HTML-Element behandelt und führt zu unerwartetem Verhalten.

💡
Hinweis zu Klassenkomponenten

Neben Funktionskomponenten gibt es in React auch historische Klassenkomponenten (class ... extends React.Component). Sie verwenden Lifecycle-Methoden wie componentDidMount statt Hooks. In modernem React werden neue Anwendungen fast immer mit Funktionskomponenten und Hooks gebaut. Deshalb verwenden wir in diesem Kurs konsequent den Funktionskomponenten-Ansatz.

Props: Eingabeparameter für Komponenten

Props (kurz für Properties) sind die Eingabeparameter einer Komponente – ähnlich wie Funktionsargumente. Sie fließen immer von oben nach unten (vom Eltern- zum Kindkind-Element). Props sind read-only: Eine Komponente darf ihre eigenen Props niemals verändern.

In TypeScript definieren wir Props mit einem Interface. Das gibt uns vollständige Typsicherheit: falsch geschriebene Prop-Namen oder falsche Typen werden sofort als Fehler markiert.

src/components/FlightStatusBadge.tsx TypeScript 
import './FlightStatusBadge.css';

// Typdefinition für den Flugstatus
type FlightStatus =
  | 'on-time'
  | 'delayed'
  | 'boarding'
  | 'departed'
  | 'landed'
  | 'cancelled';

// Props-Interface: Legt fest, welche Props die Komponente erwartet
interface FlightStatusBadgeProps {
  status: FlightStatus;
}

/**
 * Zeigt den Status eines Fluges als farbiges Badge an.
 * @param status - Der aktuelle Flugstatus
 */
const FlightStatusBadge = ({ status }: FlightStatusBadgeProps) => {
  // Konfigurationsobjekt: Status-Wert -> Label und CSS-Klasse
  const config: Record<FlightStatus, { label: string; className: string }> = {
    'on-time':   { label: 'Pünktlich', className: 'status-on-time' },
    'delayed':   { label: 'Verspätet', className: 'status-delayed' },
    'boarding':  { label: 'Boarding', className: 'status-boarding' },
    'departed':  { label: 'Abgeflogen', className: 'status-departed' },
    'landed':    { label: 'Gelandet', className: 'status-landed' },
    'cancelled': { label: 'Annulliert', className: 'status-cancelled' },
  };

  const { label, className } = config[status];
  return <span className={`status-pill ${className}`}>{label}</span>;
};

export default FlightStatusBadge;

Optionale Props und Default-Werte

In TypeScript markiert man optionale Props mit einem Fragezeichen (?). Im Funktionskopf können direkt Default-Werte angegeben werden. Das ist der idiomatische React+TypeScript-Weg – die früher gebräuchliche defaultProps-Eigenschaft ist veraltet.

Optionale Props mit Defaults TypeScript 
interface AirportHeaderProps {
  airportName: string;           // Pflichtfeld
  iataCode: string;              // Pflichtfeld
  subtitle?: string;             // Optional (mit ?)
  showTime?: boolean;            // Optional, Default: false
}

const AirportHeader = ({
  airportName,
  iataCode,
  subtitle = 'Flugplan aktuell',  // Default-Wert direkt hier
  showTime = false,               // Default-Wert
}: AirportHeaderProps) => {
  return (
    <header>
      <h1>✈ {airportName} ({iataCode})</h1>
      <p>{subtitle}</p>
      {/* Optionaler Zeitstempel */}
      {showTime && <p>{new Date().toLocaleTimeString('de-AT')}</p>}
    </header>
  );
};

// Verwendung – nur Pflichtfelder:
<AirportHeader airportName="Wien-Schwechat" iataCode="VIE" />

// Verwendung – mit optionalen Feldern:
<AirportHeader
  airportName="Wien-Schwechat"
  iataCode="VIE"
  subtitle="Live-Flugplan"
  showTime={true}
/>

FlightCard – Eine Komponente pro Tabellenzeile

Anstatt die Tabelle mit hartkodierten <tr>-Elementen zu füllen, extrahieren wir jede Zeile in eine eigene FlightCard-Komponente. Die Komponente bekommt ein vollständiges Flight-Objekt als Prop.

src/components/FlightCard.tsx TypeScript 
import FlightStatusBadge from './FlightStatusBadge';
import { Flight } from '../types/flight';
import './FlightCard.css';

// Props-Interface: Ein einziges flight-Objekt als Prop
interface FlightCardProps {
  flight: Flight;
}

/**
 * Stellt einen einzelnen Flug als Tabellenzeile dar.
 */
const FlightCard = ({ flight }: FlightCardProps) => {
  // Zeitanzeige: Falls Verspätung vorliegt, beide Zeiten anzeigen
  const timeDisplay =
    flight.expectedTime && flight.expectedTime !== flight.scheduledTime
      ? `${flight.scheduledTime} (${flight.expectedTime})`
      : flight.scheduledTime;

  return (
    <tr className="flight-row">
      <td className="flight-cell flight-cell-number">
        {flight.flightNumber}
      </td>
      <td className="flight-cell flight-cell-airline">
        {flight.airline}
      </td>
      <td className="flight-cell">{flight.airport}</td>
      <td className="flight-cell flight-cell-time">
        {timeDisplay}
      </td>
      <td className="flight-cell">{flight.terminal}</td>
      {/* Nullish Coalescing: falls gate undefined, zeige — */}
      <td className="flight-cell">{flight.gate ?? '—'}</td>
      <td className="flight-cell">
        <FlightStatusBadge status={flight.status} />
      </td>
    </tr>
  );
};

export default FlightCard;

FlightBoard – Komponenten zusammensetzen

FlightBoard ist eine Container-Komponente: Sie erhält ein Array von Flügen und einen Titel als Props und rendert für jeden Flug eine FlightCard. Das .map() wird später in Lektion 1.6 ausführlich erklärt; hier sehen wir es schon im Einsatz.

src/components/FlightBoard.tsx TypeScript 
import FlightCard from './FlightCard';
import { Flight } from '../types/flight';
import './FlightBoard.css';

interface FlightBoardProps {
  flights: Flight[];   // Array von Flügen
  title: string;       // Überschrift der Tabelle
}

/**
 * Tabellenansicht für eine Liste von Flügen.
 */
const FlightBoard = ({ flights, title }: FlightBoardProps) => {
  return (
    <section className="flight-board-section">
      <h2 className="flight-board-title">{title}</h2>
      <table className="flight-board-table">
        <thead>
          <tr>
            <th className="flight-board-heading">Flug</th>
            <th className="flight-board-heading">Airline</th>
            <th className="flight-board-heading">Ziel / Herkunft</th>
            <th className="flight-board-heading">Zeit</th>
            <th className="flight-board-heading">Terminal</th>
            <th className="flight-board-heading">Gate</th>
            <th className="flight-board-heading">Status</th>
          </tr>
        </thead>
        <tbody>
          {flights.map((flight) => (
            // key ist Pflicht beim Rendern von Listen – mehr dazu in L04
            <FlightCard key={flight.id} flight={flight} />
          ))}
        </tbody>
      </table>
    </section>
  );
};

export default FlightBoard;

In App.tsx werden die Flüge nach Typ aufgeteilt und an zwei FlightBoard-Instanzen übergeben:

src/App.tsx TypeScript 
import FlightBoard from './components/FlightBoard';
import { sampleFlights } from './data/flights';

function App() {
  // Flüge nach Typ aufteilen
  const departures = sampleFlights.filter(f => f.type === 'departure');
  const arrivals   = sampleFlights.filter(f => f.type === 'arrival');

  return (
    <div className="app-page">
      <header className="app-header">
        <h1 className="app-title">✈ FlugBoard – Wien International</h1>
        <p className="app-subtitle">Flughafen Wien-Schwechat (VIE)</p>
      </header>

      {/* Gleiche Komponente, unterschiedliche Props */}
      <FlightBoard flights={departures} title="Abflüge" />
      <FlightBoard flights={arrivals}   title="Ankünfte" />
    </div>
  );
}

export default App;

Children Props

Jede Komponente hat automatisch Zugriff auf ein spezielles Prop namens children. Es enthält alles, was zwischen dem öffnenden und schließenden Tag der Komponente steht – ähnlich wie der Inhalt eines HTML-Elements. Der Typ für children ist React.ReactNode.

Children Props Beispiel TypeScript 
import { ReactNode } from 'react';

// Props-Interface mit children
interface SectionProps {
  title: string;
  children: ReactNode;   // Alles was zwischen die Tags kommt
}

// Layout-Komponente, die Kinder-Elemente einbettet
const BoardSection = ({ title, children }: SectionProps) => (
  <section className="board-section">
    <h2 className="board-section-title">{title}</h2>
    {children}
  </section>
);

// Verwendung: Alles zwischen den Tags wird als children übergeben
<BoardSection title="Abflüge">
  <FlightBoard flights={departures} title="Abflüge" />
  <p className="board-section-note">{departures.length} Flüge angezeigt</p>
</BoardSection>

Typdefinitionen in eigene Datei auslagern

Wenn mehrere Komponenten dasselbe Interface verwenden, lagert man Typen in eine eigene Datei aus. Dadurch vermeiden wir Duplikation und haben eine einzige „Source of Truth“ für unser Datenmodell.

src/types/flight.ts TypeScript 
// Zentrales Datenmodell für den FlugBoard-Kurs
// Diese Typen werden in allen Lektionen verwendet

export type FlightType   = 'arrival' | 'departure';
export type FlightStatus =
  | 'on-time'
  | 'delayed'
  | 'boarding'
  | 'departed'
  | 'landed'
  | 'cancelled';

export interface Flight {
  id:            number;
  flightNumber:  string;
  airline:       string;
  type:          FlightType;
  scheduledTime: string;       // Format: "HH:MM"
  expectedTime?: string;       // Optional: nur bei Verspätung gesetzt
  status:        FlightStatus;
  airport:       string;       // Herkunft (arrival) / Ziel (departure)
  terminal:      string;
  gate?:         string;       // Optional: nicht immer bekannt
}

Projektschritt

Projektschritt 1.4

Komponenten extrahieren

Wir zerlegen die monolithische App.tsx aus Lektion 1.2 in wiederverwendbare Komponenten. Am Ende dieser Lektion hat das Projekt folgende Struktur:

Neue Projektstruktur Bash 
src/
├── App.tsx                     ← Nutzt FlightBoard, importiert sampleFlights
├── components/
│   ├── FlightCard.tsx          ← Einzelne Tabellenzeile
│   ├── FlightBoard.tsx         ← Tabelle + Header
│   └── FlightStatusBadge.tsx   ← Status-Badge mit Farben
├── data/
│   └── flights.ts              ← sampleFlights Array (alle 8 Flüge)
└── types/
    └── flight.ts               ← Flight Interface & Typen (exportiert)

Jede Komponente ist in einer eigenen Datei. Typen werden aus src/types/flight.ts importiert – kein Duplizieren von Interfaces! Gleiches gilt fürs Styling: standardmäßig className und eigene CSS-Datei pro Komponente statt statischer Inline-Styles.

✓
Wann eine Komponente auslagern?

Eine gute Faustregel: Lagere eine Komponente aus, wenn sie (a) an mehreren Stellen verwendet wird, (b) zu komplex wird um sie zu überblicken, oder (c) einen klar abgegrenzten Verantwortungsbereich hat. FlightStatusBadge ist ein perfektes Beispiel: klar definiert, wiederverwendbar, eigenständig testbar.

Häufige Fehler

Fehler: Komponenten-Name beginnt mit Kleinbuchstabe

const flightCard = ... – React behandelt <flightCard /> als unbekannten HTML-Tag und gibt eine Warnung aus: "The tag flightCard is unrecognized in this browser." Die Komponente wird nicht korrekt gerendert.

Immer PascalCase verwenden: const FlightCard = ...

Fehler: Props-Typ nicht mit Interface definiert

Ohne TypeScript-Interface für Props hat man keinen Typen-Schutz. Tippfehler in Prop-Namen (flightt statt flight) oder falsche Typen werden erst zur Laufzeit auffallen – oder gar nicht.

Immer ein interface FooProps definieren und als Typ des Parameters angeben.

Fehler: key-Prop beim Rendern von Listen vergessen

Wenn man .map() verwendet und kein key-Prop angibt, erscheint in der Browser-Konsole: "Each child in a list should have a unique key prop." React kann die Liste dann nicht effizient aktualisieren. Mehr dazu in Lektion 1.6.

Beim .map() immer key={flight.id} setzen.

Fehler: export default vergessen

Ohne Export kann die Komponente nicht importiert werden. Der Fehler lautet: "Module has no default export."

Jede Komponentendatei benötigt export default KomponentenName; am Ende.

Aufgaben

Aufgabe 1 FlightStatusBadge erstellen

Erstelle die Komponente FlightStatusBadge in src/components/FlightStatusBadge.tsx mit korrekten TypeScript-Typen.

  • Definiere den Typ FlightStatus als Union Type mit allen 6 Status-Werten
  • Erstelle ein Record<FlightStatus, ...>-Konfigurationsobjekt mit Label und Farbe
  • Teste alle 6 Status-Werte, indem du 6 Badges nebeneinander in App.tsx renderst
  • Stelle sicher, dass TypeScript einen Fehler meldet, wenn ein ungültiger Status übergeben wird
Aufgabe 2 FlightCard und FlightBoard bauen

Erstelle FlightCard als Tabellenzeile und FlightBoard als Tabellen-Container. Trenne die Typdefinitionen in src/types/flight.ts und die Daten in src/data/flights.ts.

  • Exportiere Flight, FlightType und FlightStatus aus types/flight.ts
  • Exportiere sampleFlights mit allen 8 Musterflügen aus data/flights.ts
  • FlightCard bekommt ein einzelnes flight: Flight-Prop
  • FlightBoard bekommt flights: Flight[] und title: string
  • App.tsx filtert nach Typ und zeigt zwei FlightBoard-Instanzen
Aufgabe 3 AirportHeader Komponente

Erstelle eine neue Komponente AirportHeader in src/components/AirportHeader.tsx.

  • Props: airportName: string, iataCode: string, children?: React.ReactNode
  • Die Komponente zeigt einen Seitentitel mit dem Flugzeug-Symbol (✈) und optional Kinder-Elemente darunter
  • Verwende die Komponente in App.tsx und platziere darin einen kurzen Info-Text als children
Bonus InfoBadge für Terminal & Gate

Erstelle eine InfoBadge-Komponente (src/components/InfoBadge.tsx), die Terminal und Gate kombiniert anzeigt.

  • Props: terminal: string, gate?: string
  • Anzeige: "T3 / B12" oder "T2 / —" falls kein Gate vorhanden
  • Verwende die Komponente in FlightCard statt der getrennten Terminal- und Gate-Spalten
  • Das Badge soll einen dezenten Hintergrund und abgerundete Ecken haben
