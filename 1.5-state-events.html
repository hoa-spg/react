Lektion 1.5 — Teil 1: React Einführung

State & Events

React ca. 90 min

Lernziele

  • Den useState-Hook verstehen und anwenden
  • Event-Handler in TypeScript korrekt typisieren
  • Den Unterschied zwischen State und Props verstehen
  • Immutability: State niemals direkt mutieren
  • Re-rendering: wann rendert React neu?
  • State für Arrays und Objekte aktualisieren

Was ist State?

State ist der interne, veränderliche Speicher einer Komponente. Während Props von außen hereinkommen und in der Komponente unverändert bleiben, kann State durch Benutzerinteraktionen oder andere Ereignisse geändert werden. Immer wenn sich State ändert, rendert React die Komponente neu – die Ansicht spiegelt stets den aktuellen State wider.

Der wichtigste Unterschied: Props kommen von den Eltern, State kommt von innen. Eine Komponente kann ihren eigenen State ändern, aber niemals direkt die Props eines Kindes.

useState-Grundlagen TypeScript 
import { useState } from 'react';

// Syntax: const [wert, setWert] = useState<Typ>(initialWert);
// useState gibt ein Tupel zurück: [aktueller Wert, Setter-Funktion]

const [count, setCount]     = useState<number>(0);
const [name, setName]       = useState<string>('');
const [isOpen, setIsOpen]   = useState<boolean>(false);

// TypeScript kann den Typ oft aus dem Initialwert ableiten:
const [count, setCount]   = useState(0);       // Typ: number
const [name, setName]     = useState('');       // Typ: string

// Bei komplexen Typen oder wenn der Initialwert null sein kann:
const [flight, setFlight] = useState<Flight | null>(null);
const [flights, setFlights] = useState<Flight[]>([]);
ℹ
Was ist ein Hook?

Hooks sind spezielle React-Funktionen, die mit use beginnen (z.B. useState, useEffect). Sie dürfen nur in Funktionskomponenten und in Custom Hooks aufgerufen werden – nicht in Schleifen, Bedingungen oder normalen Funktionen. Diese Regel nennt sich die Rules of Hooks.

Event-Handler und TypeScript-Typen

React-Events sind synthetische Events (Wrapper um native Browser-Events). In TypeScript müssen Event-Handler-Funktionen den richtigen Typ für den Event-Parameter haben. Die wichtigsten Typen sind React.MouseEvent, React.ChangeEvent und React.FormEvent.

Event-Handler Typen TypeScript 
import { useState } from 'react';

const BeispielKomponente = () => {
  const [count, setCount]   = useState(0);
  const [text, setText]     = useState('');

  // Einfacher Click-Handler ohne Parameter
  const handleClick = () => {
    setCount(count + 1);
  };

  // Click-Handler mit Event-Parameter (für position, target etc.)
  const handleButtonClick = (e: React.MouseEvent<HTMLButtonElement>) => {
    console.log('Geklickt bei:', e.clientX, e.clientY);
    setCount(prev => prev + 1);
  };

  // Input-Änderung – HTMLInputElement für <input>
  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setText(e.target.value);
  };

  return (
    <div>
      <p>Zähler: {count}</p>

      {/* Direkte Inline-Funktion (gut für einfache Fälle) */}
      <button onClick={() => setCount(0)}>Zurücksetzen</button>

      {/* Referenz auf Handler-Funktion (besser bei Wiederverwendung) */}
      <button onClick={handleClick}>Erhöhen</button>

      {/* ACHTUNG: Nicht so! setCount(1) wird sofort ausgeführt, nicht beim Klick */}
      {/* <button onClick={setCount(1)}>Falsch!</button> */}

      <input value={text} onChange={handleChange} />
    </div>
  );
};

Immutability – State niemals direkt mutieren

Das ist eine der wichtigsten Regeln in React: State darf niemals direkt verändert werden! React erkennt State-Änderungen nur dann, wenn die Referenz des State-Werts sich ändert. Eine direkte Mutation verändert das Objekt im Speicher, aber nicht die Referenz – React bemerkt die Änderung nicht und rendert nicht neu.

Immutability – Richtig vs. Falsch TypeScript 
import { useState } from 'react';
import { sampleFlights } from '../data/flights';
import { Flight, FlightStatus } from '../types/flight';

const App = () => {
  const [flights, setFlights] = useState<Flight[]>(sampleFlights);

  // --- FALSCH: Direkte Mutation ---
  const updateStatusFalsch = (id: number, status: FlightStatus) => {
    flights[0].status = status;  // Direkte Mutation! React bemerkt es nicht!
    setFlights(flights);         // Gleiche Referenz → kein Re-render!
  };

  // --- RICHTIG: Neues Array mit neuem Objekt erstellen ---
  const updateStatus = (id: number, status: FlightStatus) => {
    setFlights(
      flights.map(f =>
        f.id === id
          ? { ...f, status }   // Spread: kopiert alle Felder, überschreibt status
          : f                  // Andere Flüge unverändert
      )
    );
  };

  // Flug hinzufügen – neues Array mit Spread
  const addFlight = (flight: Flight) => {
    setFlights(prev => [...prev, flight]);
  };

  // Flug entfernen – filter erstellt immer ein neues Array
  const removeFlight = (id: number) => {
    setFlights(prev => prev.filter(f => f.id !== id));
  };

  return <div>{/* ... */}</div>;
};
⚠
Funktionaler State-Update bei Abhängigkeiten

Wenn der neue State-Wert vom vorherigen abhängt, verwende die Callback-Form des Setters: setCount(prev => prev + 1) statt setCount(count + 1). Die Callback-Form garantiert, dass immer der aktuellste Wert verwendet wird – besonders wichtig in asynchronen Kontexten.

Flug auswählen – selectedFlight State

Wir fügen unserem FlugBoard eine Auswahlfunktion hinzu: Wenn der Nutzer auf eine Zeile klickt, wird der ausgewählte Flug in einem Detail-Panel angezeigt. Dafür benötigen wir einen selectedFlight-State in App.tsx, der entweder null (kein Flug ausgewählt) oder ein Flight-Objekt enthält.

Die Callback-Funktion onFlightSelect wird von App nach unten an FlightBoard und weiter an FlightCard übergeben. Das nennt sich Lifting State Up – der State lebt in der gemeinsamen Elternkomponente. Styling bleibt wie bisher über className und separate CSS-Dateien (z.B. FlightCard.css, FlightDetail.css).

src/App.tsx – mit selectedFlight State TypeScript 
import { useState } from 'react';
import FlightBoard from './components/FlightBoard';
import FlightDetail from './components/FlightDetail';
import { sampleFlights } from './data/flights';
import { Flight } from './types/flight';

function App() {
  // State für den ausgewählten Flug (null = keiner ausgewählt)
  const [selectedFlight, setSelectedFlight] = useState<Flight | null>(null);

  const departures = sampleFlights.filter(f => f.type === 'departure');
  const arrivals   = sampleFlights.filter(f => f.type === 'arrival');

  return (
    <div className="app-page">
      <header className="app-header">
        <h1 className="app-title">✈ FlugBoard – Wien International</h1>
      </header>

      {/* Detail-Panel nur anzeigen wenn ein Flug ausgewählt ist */}
      {selectedFlight && (
        <FlightDetail
          flight={selectedFlight}
          onClose={() => setSelectedFlight(null)}
        />
      )}

      {/* Callback wird nach unten weitergegeben */}
      <FlightBoard
        flights={departures}
        title="Abflüge"
        onFlightSelect={setSelectedFlight}
      />
      <FlightBoard
        flights={arrivals}
        title="Ankünfte"
        onFlightSelect={setSelectedFlight}
      />
    </div>
  );
}

export default App;
src/components/FlightDetail.tsx TypeScript 
import { Flight } from '../types/flight';
import './FlightDetail.css';

interface FlightDetailProps {
  flight: Flight;
  onClose: () => void;   // Callback: teilt dem Elternteil mit, dass geschlossen werden soll
}

/**
 * Zeigt alle Details eines ausgewählten Fluges an.
 */
const FlightDetail = ({ flight, onClose }: FlightDetailProps) => {
  return (
    <div className="detail-panel">
      {/* Schließen-Button in der oberen rechten Ecke */}
      <button
        onClick={onClose}
        className="detail-close-btn"
      >
        × Schließen
      </button>

      <h3 className="detail-title">
        {flight.flightNumber} – {flight.airline}
      </h3>
      <p><strong>Typ:</strong> {flight.type === 'departure' ? 'Abflug' : 'Ankunft'}</p>
      <p><strong>{flight.type === 'departure' ? 'Ziel' : 'Herkunft'}:</strong> {flight.airport}</p>
      <p><strong>Geplante Zeit:</strong> {flight.scheduledTime}</p>
      {flight.expectedTime && (
        <p><strong>Erwartete Zeit:</strong> {flight.expectedTime}</p>
      )}
      <p><strong>Terminal:</strong> {flight.terminal}</p>
      <p><strong>Gate:</strong> {flight.gate ?? '—'}</p>
    </div>
  );
};

export default FlightDetail;

Projektschritt

Projektschritt 1.5

Flug auswählen & Detail-Panel

Wir machen das FlugBoard interaktiv: Ein Klick auf eine Tabellenzeile öffnet ein Detail-Panel mit allen Informationen zum Flug. Ein weiterer Klick auf „Schließen“ blendet es wieder aus.

Änderungen in dieser Lektion:

  • App.tsx erhält selectedFlight: Flight | null als State
  • Neue Komponente FlightDetail zeigt den ausgewählten Flug an
  • FlightBoard erhält onFlightSelect als Prop und gibt es an FlightCard weiter
  • FlightCard erhält isSelected und onSelect als Props
✓
Lifting State Up

Wenn zwei Komponenten denselben State benötigen, muss der State in deren gemeinsamen Elternteil leben. FlightDetail und FlightBoard benötigen beide den selectedFlight – deshalb lebt er in App. Der ausgewählte Flug wird als Prop nach unten gegeben, Änderungen durch Callbacks nach oben gemeldet.

Häufige Fehler

Fehler: State direkt mutieren

flights[0].status = 'boarding'; – React erkennt diese Änderung nicht, weil die Array-Referenz gleich bleibt. Die UI aktualisiert sich nicht, obwohl der Wert im Speicher geändert wurde. Das führt zu schwer nachvollziehbaren Bugs.

Immer ein neues Objekt/Array erstellen: setFlights(prev => prev.map(f => f.id === id ? { ...f, status } : f))

Fehler: State-Setter direkt im JSX aufrufen

<button onClick={setCount(1)}> – Hier wird setCount(1) sofort beim Rendern ausgeführt, nicht erst beim Klick. Das führt zu einer Endlosschleife: Render → State ändern → Re-render → State ändern → ...

Immer eine Funktion übergeben: onClick={() => setCount(1)}

Fehler: useState außerhalb der Komponente

Hooks müssen im Top-Level einer Funktionskomponente aufgerufen werden – nicht in Schleifen, nicht in Bedingungen, nicht in verschachtelten Funktionen. Sonst verliert React die Zuordnung zwischen Hook und Komponente.

Alle useState-Aufrufe direkt an den Anfang der Komponente schreiben.

Fehler: Veralteter State in Closures (Stale Closure)

setCount(count + 1) kann in asynchronen Kontexten den alten Wert von count verwenden, wenn sich dieser zwischenzeitlich geändert hat.

Verwende die Callback-Form: setCount(prev => prev + 1) – garantiert immer den aktuellsten Wert.

Aufgaben

Aufgabe 1 Zeile hervorheben

Füge in FlightCard einen Click-Handler hinzu. Die ausgewählte Zeile soll sich visuell abheben.

  • Erhält FlightCard ein isSelected: boolean-Prop
  • Wenn isSelected wahr ist: anderer Hintergrund (z.B. rgba(97,218,251,0.08))
  • Linker Rand als visuelle Markierung: borderLeft: '3px solid #61dafb'
  • Vergleich in App.tsx: selectedFlight?.id === flight.id
Aufgabe 2 FlightDetail Komponente

Erstelle die FlightDetail-Komponente und zeige sie in App.tsx an, wenn ein Flug ausgewählt ist.

  • Zeige alle Felder des Flight-Objekts übersichtlich an
  • expectedTime nur anzeigen wenn vorhanden (conditional rendering)
  • Ein „Schließen“-Button setzt selectedFlight auf null
  • Bei type === 'departure': „Ziel“; bei arrival: „Herkunft“
Aufgabe 3 Ansichts-Toggle

Füge in App.tsx einen Toggle-Button hinzu, der zwischen drei Ansichten wechselt.

  • State: filterType: 'all' | 'departure' | 'arrival', Initialwert 'all'
  • Drei Buttons: „Alle“, „Abflüge“, „Ankünfte“
  • Der aktive Button soll visuell hervorgehoben sein
  • Die Tabellen filtern entsprechend: bei 'all' beide Boards zeigen, bei 'departure' nur Abflüge usw.
Bonus Favoriten-Funktion

Implementiere eine Favoriten-Funktion: Ein Stern-Symbol in jeder FlightCard markiert einen Flug als Favorit.
