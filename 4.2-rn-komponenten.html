1 — FlatList – Performante Listen

Eine der häufigsten Aufgaben in mobilen Apps ist das Anzeigen langer Listen – Flüge, Nachrichten, Produkte. In Lektion 1.6 haben wir .map() verwendet. Das funktioniert bei wenigen Einträgen, ist aber bei einer echten Flugliste (100+ Einträge) problematisch: Alle Elemente werden gleichzeitig gerendert, auch wenn sie außerhalb des sichtbaren Bereichs liegen.

ScrollView vs. FlatList

Kriterium ScrollView + .map() FlatList
Alle Elemente rendern Ja (immer) Nein (nur sichtbare)
Speicherverbrauch bei 1000+ Items Sehr hoch Niedrig (virtualisiert)
Pull-to-Refresh Manuell implementieren Eingebaut (onRefresh)
Leerer Zustand (keine Daten) Manuell implementieren Eingebaut (ListEmptyComponent)
Header / Footer Manuell Eingebaut (ListHeaderComponent)
Empfohlen für Kurze, feste Inhalte (< 20 Items) Dynamische Listen jeder Länge

FlatList in der Praxis

components/FlightList.tsx TypeScript 
import { FlatList, View, Text, StyleSheet } from 'react-native';
import { Flight } from '../types/flight';
import { FlightCard } from './FlightCard';

interface FlightListProps {
  flights: Flight[];
  onFlightPress: (flight: Flight) => void;
  isLoading?: boolean;
  onRefresh?: () => void;
  refreshing?: boolean;
}

export function FlightList({
  flights,
  onFlightPress,
  isLoading = false,
  onRefresh,
  refreshing = false,
}: FlightListProps) {
  return (
    <FlatList
      data={flights}

      // keyExtractor: MUSS eine eindeutige String-ID zurückgeben.
      // Nicht key={...} wie bei .map() – das ist ein häufiger Fehler!
      keyExtractor={(item) => item.id.toString()}

      // renderItem: Rendert jedes einzelne List-Element
      renderItem={({ item, index }) => (
        <FlightCard
          flight={item}
          onPress={() => onFlightPress(item)}
          index={index}
        />
      )}

      // Trennlinie zwischen den Elementen
      ItemSeparatorComponent={() => (
        <View style={styles.separator} />
      )}

      // Wird angezeigt, wenn data leer ist
      ListEmptyComponent={() => (
        <View style={styles.emptyContainer}>
          <Text style={styles.emptyIcon}>✈</Text>
          <Text style={styles.emptyTitle}>Keine Flüge gefunden</Text>
          <Text style={styles.emptySubtitle}>
            Versuche eine andere Suche oder aktualisiere die Daten.
          </Text>
        </View>
      )}

      // Wird als Header über der Liste angezeigt (scrollt mit!)
      ListHeaderComponent={() => (
        <View style={styles.headerContainer}>
          <Text style={styles.headerText}>
            Abflüge ({flights.length})
          </Text>
        </View>
      )}

      // Pull-to-Refresh: refreshing steuert den Spinner
      onRefresh={onRefresh}
      refreshing={refreshing}

      // Performance-Optimierungen
      removeClippedSubviews={true}    // Entfernt Off-Screen-Elemente aus dem DOM
      initialNumToRender={15}         // Wie viele Items initial rendern
      maxToRenderPerBatch={10}        // Items pro Render-Batch
      windowSize={10}                 // Render-Fenster in Vielfachen der Bildschirmhöhe

      // Abstand am Ende der Liste (verhindert Tab-Bar-Überlappung)
      contentContainerStyle={[
        styles.listContent,
        flights.length === 0 && styles.listContentEmpty,
      ]}
    />
  );
}

    height: 1,
    backgroundColor: '#21262d',
    marginHorizontal: 16,
  },
  emptyContainer: {
    alignItems: 'center',
    paddingTop: 64,
    paddingHorizontal: 32,
  },
  emptyIcon: {
    fontSize: 48,
    marginBottom: 16,
  },
  emptyTitle: {
    fontSize: 18,
    fontWeight: '600',
    color: '#e6edf3',
    marginBottom: 8,
  },
  emptySubtitle: {
    fontSize: 14,
    color: '#8b949e',
    textAlign: 'center',
    lineHeight: 20,
  },
  headerContainer: {
    paddingHorizontal: 16,
    paddingVertical: 12,
    borderBottomWidth: 1,
    borderBottomColor: '#21262d',
  },
  headerText: {
    fontSize: 13,
    fontWeight: '600',
    color: '#8b949e',
    letterSpacing: 1,
    textTransform: 'uppercase',
  },
  listContent: {

  },

2 — FlightCard – Die native Fluganzeige

Die FlightCard ist das Herzstück der App. Sie zeigt alle relevanten Informationen zu einem Flug an: Flugnummer, Ziel, Gate, Abflugzeit und den farbcodierten Status. Das Status-System verwendet das gleiche STATUS_CONFIG-Pattern wie die Web-Version aus Lektion 4.

3 — TextInput – Die Suchleiste

TextInput ist das React-Native-Äquivalent zu <input> im Web. Es gibt einige wichtige Unterschiede und zusätzliche Props, die auf mobilen Geräten wichtig sind.

components/SearchBar.tsx TypeScript 
import {
  TextInput,
  View,
  Text,
  TouchableOpacity,
  StyleSheet,
} from 'react-native';

interface SearchBarProps {
  value: string;
  onChangeText: (text: string) => void;
  placeholder?: string;
  resultCount?: number;
}

export function SearchBar({
  value,
  onChangeText,
  placeholder = 'Flugnummer oder Ziel...',
  resultCount,
}: SearchBarProps) {
  return (
    <View style={styles.container}>
      {/* Suchfeld-Row: Icon + Input + Clear-Button */}
      <View style={styles.inputRow}>
        <Text style={styles.searchIcon}>🔍</Text>

        <TextInput
          style={styles.input}
          value={value}
          onChangeText={onChangeText}
          placeholder={placeholder}

          // placeholderTextColor MUSS explizit gesetzt werden –
          // der Standardwert ist auf Dark-Theme oft zu hell oder zu dunkel.
          placeholderTextColor="#484f58"

          // Tastatur-Optionen
          autoCorrect={false}           // Keine Autokorrektur (stört bei Flugnummern)
          autoCapitalize="none"         // Keine automatische Großschreibung
          keyboardType="default"
          returnKeyType="search"
          keyboardAppearance="dark"     // Dunkle Tastatur auf iOS

          // iOS: Zeigt ein "×"-Symbol zum Löschen im Input-Feld
          clearButtonMode="while-editing"

          // Barrierefreiheit
          accessibilityLabel="Flug suchen"
          accessibilityHint="Flugnummer oder Zielflughafen eingeben"
        />

        {/* Eigener Clear-Button für Android (clearButtonMode nur iOS) */}
        {value.length > 0 && (
          <TouchableOpacity
            style={styles.clearButton}
            onPress={() => onChangeText('')}
            activeOpacity={0.7}
            accessibilityLabel="Suche löschen"
          >
            <Text style={styles.clearIcon}>✖</Text>
          </TouchableOpacity>
        )}
      </View>

      {/* Ergebnis-Zähler */}
      {value.length > 0 && resultCount !== undefined && (
        <Text style={styles.resultCount}>
          {resultCount} {resultCount === 1 ? 'Ergebnis' : 'Ergebnisse'}
        </Text>
      )}
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    paddingHorizontal: 16,
    paddingVertical: 10,
    backgroundColor: '#0d1117',
    borderBottomWidth: 1,
    borderBottomColor: '#21262d',
  },
  inputRow: {
    flexDirection: 'row',
    alignItems: 'center',
    backgroundColor: '#161b22',
    borderWidth: 1,
    borderColor: '#30363d',
    borderRadius: 8,
    paddingHorizontal: 12,
    height: 44,
  },
  searchIcon: {
    fontSize: 16,
    marginRight: 8,
    color: '#8b949e',

  clearButton: {

Gesteuerter Input – useState + TextInput

import { useState, useMemo } from 'react';
import { FLIGHTS } from '../data/flights';

export function DepartureListScreen() {
  const [searchQuery, setSearchQuery] = useState('');

  // useMemo: Filterliste nur neu berechnen, wenn sich searchQuery oder Daten ändern
  const filteredFlights = useMemo(() => {
    const query = searchQuery.toLowerCase().trim();
    if (!query) return FLIGHTS;
    return FLIGHTS.filter(
      (f) =>
        f.flightNumber.toLowerCase().includes(query) ||
        f.destination.toLowerCase().includes(query) ||
        f.airline.toLowerCase().includes(query)
    );
  }, [searchQuery]);

  return (
    <>
      <SearchBar
        value={searchQuery}
        onChangeText={setSearchQuery}
        resultCount={filteredFlights.length}
      />
      <FlightList
        flights={filteredFlights}
        onFlightPress={(flight) => console.log(flight)}
      />
    </>
  );
}

4 — Flexbox in React Native

React Native verwendet Flexbox als einziges Layout-System – es gibt kein CSS Grid, keine Float-Layouts, keine absoluten Pixel-Positionen (außer mit position: 'absolute'). Das Gute: Wer Flexbox vom Web kennt, hat die Grundlage bereits. Es gibt aber einige wichtige Unterschiede.

Die wichtigsten Unterschiede zum Web

Eigenschaft Web (CSS) React Native
flexDirection row (Standard) column (Standard!)
alignContent stretch flex-start
flexShrink 1 0
gap Vollständig unterstützt Ab RN 0.71+ unterstützt
Elterngröße Implizit vom Browser Muss explizit mit flex: 1 oder fixen Werten gesetzt werden

Flex-Verteilung – Dreispalten-Layout

Mit flex: N verteilt man den verfügbaren Platz anteilig. Das ist das Kernprinzip hinter der FlightCard: drei Spalten, die sich den Platz in einem 2:3:2-Verhältnis teilen.

flexbox-layout.tsx TypeScript 
// Dreispalten-Layout: links 2/7, mitte 3/7, rechts 2/7
<View style={{ flexDirection: 'row' }}>

    <Text>Links (2/7)</Text>
  </View>
  <View style={{ flex: 3, backgroundColor: '#16213e' }}>
    <Text>Mitte (3/7)</Text>
  </View>
  <View style={{ flex: 2, backgroundColor: '#0f3460' }}>
    <Text>Rechts (2/7)</Text>
  </View>
</View>

// Vollständiges FlightCard-Layout-Schema:
// flexDirection: 'row' (horizontale Anordnung)
// └── leftColumn   (flex: 2) – Flugnummer + Airline
// └── centerColumn (flex: 3) – Ziel + Gate
// └── rightColumn  (flex: 2) – Zeit + Status

// Wichtig: Ohne flex: 1 auf dem übergeordneten Container
// hat die Row keine definierte Breite!
const layoutStyles = StyleSheet.create({
  screen: {
    flex: 1,                      // Gesamten Bildschirm einnehmen
    backgroundColor: '#0d1117',
  },
  row: {
    flexDirection: 'row',
    alignItems: 'center',         // Vertikal zentrieren
    gap: 8,                       // Abstand zwischen Spalten (RN 0.71+)
  },
  col: {
    flex: 1,                      // Gleich verteilt
  },
  colWide: {
    flex: 2,                      // Doppelt so breit
  },
});

5 — ActivityIndicator und SafeAreaView

SafeAreaView – Notch und Dynamic Island

Moderne Smartphones haben Aussparungen im Display: den klassischen Notch (iPhone X), die Dynamic Island (iPhone 14 Pro+) oder runde Ecken. SafeAreaView stellt sicher, dass der Inhalt der App in den sicheren Bereich verschoben wird und nichts hinter diesen Hardware-Elementen verschwindet.

screens/DepartureListScreen.tsx TypeScript 
import {
  SafeAreaView,
  View,
  Text,
  ActivityIndicator,
  StyleSheet,
} from 'react-native';
import { useState } from 'react';

export function DepartureListScreen() {
  const [isLoading, setIsLoading] = useState(false);
  const [refreshing, setRefreshing] = useState(false);

  const handleRefresh = async () => {
    setRefreshing(true);
    await new Promise((resolve) => setTimeout(resolve, 1500)); // Simuliert API-Call
    setRefreshing(false);
  };

  return (
    // SafeAreaView statt View als Root-Container!
    // Respektiert iOS Notch, Dynamic Island, Home-Indicator
    <SafeAreaView style={styles.safeArea}>

      {/* Header-Bereich */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>✈ Abflüge</Text>
        <Text style={styles.headerSubtitle}>Wien-Schwechat (VIE)</Text>
      </View>

      {/* Suchleiste */}
      <SearchBar
        value={searchQuery}
        onChangeText={setSearchQuery}
        resultCount={filteredFlights.length}
      />

      {/* Ladeanimation: Zeige ActivityIndicator statt Liste während dem Laden */}
      {isLoading ? (
        <View style={styles.loadingContainer}>
          <ActivityIndicator
            size="large"          // 'small' oder 'large'
            color="#61dafb"       // Spinner-Farbe
          />
          <Text style={styles.loadingText}>Flüge werden geladen...</Text>
        </View>
      ) : (
        <FlightList
          flights={filteredFlights}
          onFlightPress={handleFlightPress}
          onRefresh={handleRefresh}
          refreshing={refreshing}
        />
      )}
    </SafeAreaView>
  );
}

  },
  header: {

SafeAreaView nur für den äußersten Container

Verwende SafeAreaView nur als Root-Container jedes Screens – nicht für jeden einzelnen View innerhalb der App. Mehrfach verschachtelte SafeAreaViews können doppelte Padding-Werte erzeugen. Bei Screens mit React Navigation wird SafeAreaView oft durch die react-native-safe-area-context-Bibliothek ersetzt, die mehr Kontrolle bietet.

6 — useEffect & fetch in React Native

Eine der großen Stärken von React Native: fetch, useEffect, useState und alle Custom Hooks aus Lektion 2.2 und 2.5 funktionieren exakt identisch wie im Web. Kein neues API zu lernen – das gesamte Wissen überträgt sich.

⚠
Achtung: localhost funktioniert nicht!

In Expo bezieht sich localhost auf das Telefon selbst, nicht auf den Entwicklungsrechner. Verwende stattdessen die lokale IP-Adresse deines Computers (z.B. 192.168.1.42). Die IP wird beim Start von npx expo start im Terminal angezeigt. Alternativ: Constants.expoConfig?.hostUri aus dem expo-constants-Paket gibt die IP automatisch zurück.

hooks/useFetchFlights.ts TypeScript 
import { useState, useEffect, useCallback } from 'react';
import { Flight } from '../types/flight';

// Dieser Custom Hook ist IDENTISCH zur Web-Version aus Lektion 9!
// React Native unterstützt alle React-Hooks ohne Änderungen.

// ⚠️ Lokale IP statt localhost:
// Expo zeigt beim Start die IP im Terminal an.
// Alternativ: Constants.expoConfig?.hostUri aus expo-constants
const API_BASE_URL = 'http://192.168.1.42:3000';

interface FetchFlightsResult {
  flights: Flight[];
  isLoading: boolean;
  error: string | null;
  refetch: () => void;
}

export function useFetchFlights(type: 'departures' | 'arrivals'): FetchFlightsResult {
  const [flights, setFlights] = useState<Flight[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);
  const [fetchKey, setFetchKey] = useState(0);

  const refetch = useCallback(() => setFetchKey((k) => k + 1), []);

  useEffect(() => {
    // AbortController: identisch zum Web (L06/L09)
    const controller = new AbortController();
    setIsLoading(true);
    setError(null);

    const fetchData = async () => {
      try {
        const response = await fetch(
          `${API_BASE_URL}/api/flights?type=${type}`,
          { signal: controller.signal }
        );

        if (!response.ok) {
          throw new Error(`HTTP ${response.status}: ${response.statusText}`);
        }

        const data: Flight[] = await response.json();
        setFlights(data);
      } catch (err) {
        if (err instanceof Error && err.name === 'AbortError') return;
        setError(err instanceof Error ? err.message : 'Unbekannter Fehler');
      } finally {
        setIsLoading(false);
      }
    };

    fetchData();

    // Cleanup: fetch abbrechen wenn die Komponente unmountet
    return () => controller.abort();
  }, [type, fetchKey]);

  return { flights, isLoading, error, refetch };
}

    setRefreshing(true);
    refetch();
    // Warte kurz, damit der Spinner sichtbar ist
    await new Promise((r) => setTimeout(r, 500));
    setRefreshing(false);
  }, [refetch]);

  const filteredFlights = useMemo(
    () => flights.filter(
      (f) =>
        f.flightNumber.toLowerCase().includes(searchQuery.toLowerCase()) ||
        f.destination.toLowerCase().includes(searchQuery.toLowerCase())
    ),
    [flights, searchQuery]
  );

  if (error) {
    return (
      <SafeAreaView style={styles.safeArea}>
        <View style={styles.errorContainer}>
          <Text style={styles.errorIcon}>⚠</Text>
          <Text style={styles.errorTitle}>Fehler beim Laden</Text>
          <Text style={styles.errorMessage}>{error}</Text>
          <TouchableOpacity style={styles.retryButton} onPress={refetch}>
            <Text style={styles.retryText}>Erneut versuchen</Text>
          </TouchableOpacity>
        </View>
      </SafeAreaView>
    );
  }

  return (
    <SafeAreaView style={styles.safeArea}>
      <SearchBar value={searchQuery} onChangeText={setSearchQuery} />
      <FlightList
        flights={filteredFlights}
        isLoading={isLoading}
        onFlightPress={(f) => console.log(f)}
        onRefresh={handleRefresh}
        refreshing={refreshing}
      />
    </SafeAreaView>
  );
}

Häufige Fehler

Fehler: ScrollView für lange Listen verwendet

Bei langen Listen (50+ Einträge) kommt es mit ScrollView + .map() zu spürbaren Performance-Problemen: die App scrollt ruckelig, der Speicherverbrauch steigt stark an, und auf älteren Geräten kann die App einfrieren. Das liegt daran, dass ScrollView alle Kindelemente sofort rendert und im Speicher hält, auch wenn sie außerhalb des sichtbaren Bereichs liegen.

Fix: Für dynamische Listen immer FlatList (oder SectionList für gruppierte Listen) verwenden. ScrollView nur für Screens mit wenigen, fixen Inhalten (z.B. Detail-Screens, Einstellungen, Formulare).

Fehler: localhost im fetch-URL

fetch('http://localhost:3000/api/flights') schlägt in Expo mit einem Netzwerkfehler fehl, weil localhost auf dem Telefon das Telefon selbst meint – nicht den Entwicklungsrechner. Der API-Server läuft aber auf dem Computer.

Fix: Ersetze localhost durch die lokale IP-Adresse des Computers (z.B. 192.168.1.42). Die IP wird im Terminal beim Start von npx expo start angezeigt. Alternativ: Constants.expoConfig?.hostUri?.split(':')[0] aus expo-constants gibt die IP automatisch zurück.

Fehler: key prop statt keyExtractor in FlatList

Anders als bei .map() im Web funktioniert das Hinzufügen einer key-Prop zum renderItem-Element in FlatList nicht korrekt. React Native gibt eine Warnung aus: „VirtualizedList: Each item in the list should have a unique key prop“.

Fix: Das keyExtractor-Prop der FlatList selbst verwenden: keyExtractor={(item) => item.id.toString()}. Nicht key={item.id} auf der renderItem-Komponente.

Fehler: Inline-Style-Objekte in renderItem

Inline-Style-Objekte wie style={{ backgroundColor: '#fff', padding: 12 }} werden bei jedem Render neu erstellt. Das ist in einem normalen Komponent unkritisch, aber in renderItem einer FlatList bedeutet es: Bei jedem Scroll-Frame wird für jede sichtbare Zeile ein neues Objekt erstellt. Bei 20 sichtbaren Einträgen und 60 FPS sind das 1200 neue Objekte pro Sekunde.

Fix: Immer StyleSheet.create() außerhalb der Komponente verwenden. StyleSheet.create() cached die Style-Referenzen und verhindert unnötige Neuerstellungen. Dynamische Werte (z.B. statusabhängige Farben) können als Array mit dem statischen Style kombiniert werden: style={[styles.badge, { backgroundColor: color }]}
