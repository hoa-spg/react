1 — Flexbox in React Native

In React Native ist Flexbox das einzige Layout-System – jede View ist ein Flex-Container. Wer Flexbox aus dem Web kennt, hat die Grundlage schon. Einige Standardwerte sind aber anders:

EigenschaftWeb (CSS)React Native
flexDirectionrowcolumn
flexShrink10
alignContentstretchflex-start
flexKurzform für grow/shrink/basiseine Zahl: Anteil am freien Platz

Mit flex: N verteilt man den Platz anteilig. Drei Spalten mit flex: 2, 3 und 2 bekommen 2/7, 3/7 und 2/7 der Breite:

Spalten mit flex TypeScript 
// Drei Spalten im Verhältnis 2 : 3 : 2 – wie in der FlightCard
<View style={{ flexDirection: 'row', alignItems: 'center' }}>
  <View style={{ flex: 2 }}><Text>Flugnummer</Text></View>
  <View style={{ flex: 3 }}><Text>Ziel und Zeit</Text></View>
  <View style={{ flex: 2 }}><Text>Status</Text></View>
</View>

2 — StatusBadge und FlightCard

In Lektion 4.1 stand die Karte direkt in App.tsx. Jetzt lagern wir sie wie im Web-Kurs in Komponenten aus. Zuerst das Status-Abzeichen: Ein Objekt ordnet jedem Status Text und Farben zu, die Farben kommen per Style-Array (Lektion 4.1) dazu.

src/components/StatusBadge.tsx TypeScript 
import { View, Text, StyleSheet } from 'react-native';
import { FlightStatus } from '../types/flight';

const STATUS_CONFIG: Record<FlightStatus, { label: string; color: string; bg: string }> = {
  'on-time':   { label: 'Pünktlich',  color: '#3fb950', bg: '#1a3a1a' },
  'delayed':   { label: 'Verspätet', color: '#d29922', bg: '#3a2a0a' },
  'boarding':  { label: 'Boarding',   color: '#61dafb', bg: '#0a2a3a' },
  'departed':  { label: 'Gestartet',  color: '#8b949e', bg: '#21262d' },
  'landed':    { label: 'Gelandet',   color: '#8b949e', bg: '#21262d' },
  'cancelled': { label: 'Gestrichen', color: '#f85149', bg: '#3a0a0a' },
};

interface StatusBadgeProps { status: FlightStatus; }

const StatusBadge = ({ status }: StatusBadgeProps) => {
  const cfg = STATUS_CONFIG[status];
  return (
    <View style={[styles.badge, { backgroundColor: cfg.bg }]}>
      <Text style={[styles.text, { color: cfg.color }]}>{cfg.label}</Text>
    </View>
  );
};

const styles = StyleSheet.create({
  badge: { paddingHorizontal: 8, paddingVertical: 3, borderRadius: 4 },
  text: { fontSize: 11, fontWeight: '600' },
});

export default StatusBadge;

Die FlightCard zeigt einen Flug in drei Spalten (Abschnitt 1) und ist als Ganzes antippbar. Neu sind:

  • numberOfLines={1}: Zu langer Text wird nach einer Zeile mit „…“ abgeschnitten.
  • textDecorationLine: 'line-through': durchgestrichener Text für gestrichene Flüge.
  • isSelected: Die ausgewählte Karte bekommt einen hellen Rand links.

3 — FlatList – performante Listen

In Lektion 4.1 haben wir die Flüge mit map() in einer ScrollView angezeigt. Das rendert alle Elemente auf einmal – bei 8 Flügen kein Problem, bei 1000 schon. FlatList rendert nur die Elemente, die gerade sichtbar sind (plus ein paar darüber und darunter), und bringt typische Listenfunktionen gleich mit.

  • data: das Array, renderItem: Funktion, die für ein Element (item) die Komponente liefert.
  • keyExtractor: liefert den eindeutigen Schlüssel als String – statt key wie bei map().
  • ListHeaderComponent und ListEmptyComponent: Inhalt über der Liste bzw. bei leerer Liste.
  • onRefresh und refreshing: Pull-to-Refresh – die Liste nach unten ziehen ruft onRefresh auf, solange refreshing wahr ist, dreht sich ein Spinner.
  • ActivityIndicator: der native Lade-Spinner.
src/components/FlightList.tsx TypeScript 
import { FlatList, View, Text, StyleSheet, ActivityIndicator } from 'react-native';
import { Flight } from '../types/flight';
import FlightCard from './FlightCard';

interface FlightListProps {
  flights: Flight[];
  title: string;
  onFlightPress: (flight: Flight) => void;
  selectedFlightId?: number;
  isLoading?: boolean;
  onRefresh?: () => void;
  refreshing?: boolean;
}

const FlightList = ({
  flights,
  title,
  onFlightPress,
  selectedFlightId,
  isLoading = false,
  onRefresh,
  refreshing = false,
}: FlightListProps) => (
  <FlatList
    // Während des Ladens eine leere Liste – dann zeigt ListEmptyComponent den Spinner
    data={isLoading ? [] : flights}
    keyExtractor={item => item.id.toString()}
    renderItem={({ item }) => (
      <FlightCard
        flight={item}
        onPress={() => onFlightPress(item)}
        isSelected={item.id === selectedFlightId}
      />
    )}
    ListHeaderComponent={
      <View style={styles.listHeader}>
        <Text style={styles.listTitle}>{title} ({flights.length})</Text>
      </View>
    }
    ListEmptyComponent={
      <View style={styles.empty}>
        {isLoading ? (
          <>
            <ActivityIndicator size="large" color="#61dafb" />
            <Text style={styles.emptyText}>Flugdaten werden geladen...</Text>
          </>
        ) : (
          <>
            <Text style={styles.emptyIcon}>✈</Text>
            <Text style={styles.emptyText}>Keine Flüge gefunden</Text>
          </>
        )}
      </View>
    }
    onRefresh={onRefresh}
    refreshing={refreshing}
    style={styles.list}
  />
);

const styles = StyleSheet.create({
  list: { flex: 1 },
  listHeader: {
    backgroundColor: '#161b22',
    padding: 14,
    borderBottomWidth: 1,
    borderBottomColor: '#30363d',
  },
  listTitle: { fontSize: 16, fontWeight: '600', color: '#61dafb' },
  empty: { padding: 48, alignItems: 'center' },
  emptyIcon: { fontSize: 32, marginBottom: 12 },
  emptyText: { color: '#8b949e', fontSize: 15, marginTop: 12 },
});

export default FlightList;

4 — TextInput – die Suchleiste

TextInput ist das Gegenstück zu input. Statt onChange mit event.target.value gibt es onChangeText, das direkt den neuen Text liefert. Wie im Web steuern wir das Feld über value und State (gesteuertes Eingabefeld).

src/components/SearchBar.tsx TypeScript 
import { View, TextInput, TouchableOpacity, Text, StyleSheet } from 'react-native';

interface SearchBarProps {
  value: string;
  onChangeText: (text: string) => void;
  placeholder?: string;
}

const SearchBar = ({
  value,
  onChangeText,
  placeholder = 'Flug oder Ziel suchen...',
}: SearchBarProps) => (
  <View style={styles.container}>
    <TextInput
      style={styles.input}
      value={value}
      onChangeText={onChangeText}
      placeholder={placeholder}
      placeholderTextColor="#8b949e"
      clearButtonMode="while-editing"
      autoCorrect={false}
      autoCapitalize="none"
      returnKeyType="search"
    />
    {value.length > 0 && (
      <TouchableOpacity onPress={() => onChangeText('')} style={styles.clearButton}>
        <Text style={styles.clearText}>✕</Text>
      </TouchableOpacity>
    )}
  </View>
);

const styles = StyleSheet.create({
  container: {
    flexDirection: 'row',
    alignItems: 'center',
    margin: 12,
    backgroundColor: '#21262d',
    borderRadius: 8,
    borderWidth: 1,
    borderColor: '#30363d',
  },
  input: {
    flex: 1,
    color: '#e6edf3',
    fontSize: 15,
    paddingHorizontal: 14,
    paddingVertical: 10,
  },
  clearButton: { paddingRight: 12 },
  clearText: { color: '#8b949e', fontSize: 16 },
});

export default SearchBar;
  • placeholderTextColor: Farbe des Platzhalters – auf dunklem Hintergrund nötig.
  • autoCorrect und autoCapitalize: Autokorrektur und Großschreibung der Tastatur ausschalten.
  • returnKeyType="search": Die Eingabetaste der Bildschirmtastatur zeigt „Suchen“.
  • Das ✕ erscheint nur bei Text und leert das Feld über onChangeText('').

5 — Alles zusammen: Suche, Filter und Laden

App.tsx hält den State und setzt die Komponenten zusammen — das Prinzip kennst du aus Teil 1 und 2:

  • searchQuery und typeFilter steuern Suche und Reiter („Alle“, „Abflüge“, „Ankünfte“). useMemo berechnet die gefilterte Liste nur neu, wenn sich einer der beiden Werte ändert.
  • isLoading simuliert mit useEffect und setTimeout eine Ladezeit von einer Sekunde – so sieht man den Spinner aus Abschnitt 3.
  • refreshing und handleRefresh simulieren das Aktualisieren per Pull-to-Refresh.
App.tsx TypeScript 
import { useState, useMemo, useEffect } from 'react';
import { View, Text, TouchableOpacity, StyleSheet } from 'react-native';
import { SafeAreaProvider, SafeAreaView } from 'react-native-safe-area-context';
import { StatusBar } from 'expo-status-bar';
import { sampleFlights } from './src/data/flights';
import { Flight } from './src/types/flight';
import FlightList from './src/components/FlightList';
import SearchBar from './src/components/SearchBar';

type TypeFilter = 'all' | 'departure' | 'arrival';

export default function App() {
  const [searchQuery, setSearchQuery] = useState('');
  const [typeFilter, setTypeFilter]   = useState<TypeFilter>('all');
  const [selectedFlight, setSelectedFlight] = useState<Flight | null>(null);
  const [refreshing, setRefreshing]   = useState(false);
  const [isLoading, setIsLoading]     = useState(true);

  // Ladezeit simulieren: erst nach 1 Sekunde gelten die Daten als geladen
  useEffect(() => {
    const timeoutId = setTimeout(() => {
      setIsLoading(false);
    }, 1000);
    return () => clearTimeout(timeoutId);
  }, []);

  const filteredFlights = useMemo(() => {
    const q = searchQuery.toLowerCase();
    return sampleFlights
      .filter(f => {
        if (typeFilter !== 'all' && f.type !== typeFilter) return false;
        if (
          q &&
          !f.flightNumber.toLowerCase().includes(q) &&
          !f.airport.toLowerCase().includes(q) &&
          !f.airline.toLowerCase().includes(q)
        ) return false;
        return true;
      })
      .sort((a, b) => a.scheduledTime.localeCompare(b.scheduledTime));
  }, [searchQuery, typeFilter]);

  // Pull-to-Refresh: Spinner für 1 Sekunde anzeigen
  const handleRefresh = () => {
    setRefreshing(true);
    setTimeout(() => setRefreshing(false), 1000);
  };

  const TAB_FILTERS: { key: TypeFilter; label: string }[] = [
    { key: 'all',       label: 'Alle' },
    { key: 'departure', label: '↑ Abflüge' },
    { key: 'arrival',   label: '↓ Ankünfte' },
  ];

  const listTitle =
    typeFilter === 'all'
      ? 'Alle Flüge'
      : typeFilter === 'departure'
      ? 'Abflüge'
      : 'Ankünfte';

  return (
    <SafeAreaProvider>
      <SafeAreaView style={styles.safeArea}>
        <StatusBar style="light" />

        {/* Header */}
        <View style={styles.header}>
          <Text style={styles.headerTitle}>✈ FlugBoard 4.2</Text>
          <Text style={styles.headerSubtitle}>Flughafen Wien-Schwechat</Text>
        </View>

        {/* Search */}
        <SearchBar value={searchQuery} onChangeText={setSearchQuery} />

        {/* Type filter tabs */}
        <View style={styles.tabs}>
          {TAB_FILTERS.map(tab => (
            <TouchableOpacity
              key={tab.key}
              style={[styles.tab, typeFilter === tab.key && styles.tabActive]}
              onPress={() => setTypeFilter(tab.key)}
            >
              <Text style={[styles.tabText, typeFilter === tab.key && styles.tabTextActive]}>
                {tab.label}
              </Text>
            </TouchableOpacity>
          ))}
        </View>

        {/* Flight list */}
        <FlightList
          flights={filteredFlights}
          title={listTitle}
          onFlightPress={setSelectedFlight}
          selectedFlightId={selectedFlight?.id}
          isLoading={isLoading}
          onRefresh={handleRefresh}
          refreshing={refreshing}
        />
      </SafeAreaView>
    </SafeAreaProvider>
  );
}

const styles = StyleSheet.create({
  safeArea: { flex: 1, backgroundColor: '#0d1117' },
  header: {
    backgroundColor: '#161b22',
    paddingHorizontal: 20,
    paddingVertical: 14,
    borderBottomWidth: 1,
    borderBottomColor: '#30363d',
  },
  headerTitle: { fontSize: 22, fontWeight: 'bold', color: '#61dafb' },
  headerSubtitle: { fontSize: 12, color: '#8b949e', marginTop: 2 },
  tabs: {
    flexDirection: 'row',
    backgroundColor: '#161b22',
    borderBottomWidth: 1,
    borderBottomColor: '#30363d',
  },
  tab: { flex: 1, paddingVertical: 10, alignItems: 'center' },
  tabActive: { borderBottomWidth: 2, borderBottomColor: '#61dafb' },
  tabText: { color: '#8b949e', fontSize: 13, fontWeight: '500' },
  tabTextActive: { color: '#61dafb', fontWeight: '700' },
});

Häufige Fehler

Fehler: ScrollView für lange Listen verwendet

Bei langen Listen (50+ Einträge) kommt es mit ScrollView + .map() zu spürbaren Performance-Problemen: die App scrollt ruckelig, der Speicherverbrauch steigt stark an, und auf älteren Geräten kann die App einfrieren. Das liegt daran, dass ScrollView alle Kindelemente sofort rendert und im Speicher hält, auch wenn sie außerhalb des sichtbaren Bereichs liegen.

Fix: Für dynamische Listen immer FlatList (oder SectionList für gruppierte Listen) verwenden. ScrollView nur für Screens mit wenigen, fixen Inhalten (z.B. Detail-Screens, Einstellungen, Formulare).

Fehler: localhost im fetch-URL (Bonusaufgabe)

fetch('http://localhost:3000/api/flights') schlägt in Expo mit einem Netzwerkfehler fehl, weil localhost auf dem Telefon das Telefon selbst meint – nicht den Entwicklungsrechner. Der API-Server läuft aber auf dem Computer.

Fix: Ersetze localhost durch die lokale IP-Adresse des Computers (z.B. 192.168.1.42). Die IP wird im Terminal beim Start von npx expo start angezeigt. Alternativ: Constants.expoConfig?.hostUri?.split(':')[0] aus expo-constants gibt die IP automatisch zurück.

Fehler: key prop statt keyExtractor in FlatList

Anders als bei .map() im Web funktioniert das Hinzufügen einer key-Prop zum renderItem-Element in FlatList nicht korrekt. React Native gibt eine Warnung aus: „VirtualizedList: Each item in the list should have a unique key prop“.

Fix: Das keyExtractor-Prop der FlatList selbst verwenden: keyExtractor={(item) => item.id.toString()}. Nicht key={item.id} auf der renderItem-Komponente.

Fehler: Inline-Style-Objekte in renderItem

Inline-Style-Objekte wie style={{ backgroundColor: '#fff', padding: 12 }} werden bei jedem Render neu erstellt. Das ist in einem normalen Komponent unkritisch, aber in renderItem einer FlatList bedeutet es: Bei jedem Scroll-Frame wird für jede sichtbare Zeile ein neues Objekt erstellt. Bei 20 sichtbaren Einträgen und 60 FPS sind das 1200 neue Objekte pro Sekunde.

Fix: Immer StyleSheet.create() außerhalb der Komponente verwenden. StyleSheet.create() cached die Style-Referenzen und verhindert unnötige Neuerstellungen. Dynamische Werte (z.B. statusabhängige Farben) können als Array mit dem statischen Style kombiniert werden: style={[styles.badge, { backgroundColor: color }]}

5 Fragen · zum Aufklappen klicken

Frage 1 Welche flexDirection hat eine View in React Native standardmäßig?

Erklärung: Jede View ist ein Flex-Container, aber die Hauptachse verläuft standardmäßig von oben nach unten. Auch flexShrink ist anders (0 statt 1).

Frage 2 Drei Spalten haben flex: 2, flex: 3 und flex: 2. Welchen Anteil bekommt die mittlere?

Erklärung: flex: N verteilt den Platz anteilig: 2 + 3 + 2 = 7, die mittlere bekommt 3/7.

Frage 3 Warum verwendet man für lange Listen FlatList statt ScrollView mit map()?

Erklärung: Bei vielen Einträgen ruckelt eine ScrollView und braucht viel Speicher.

Frage 4 Welche Aufgabe hat keyExtractor bei der FlatList?

Erklärung: Z. B. keyExtractor={(item) => item.id.toString()}.

Frage 5 Wie bekommt man bei einem TextInput den neuen Text?

Erklärung: Wie im Web steuert man das Feld als Controlled Component über value und State.
