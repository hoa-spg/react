Listen & Conditional Rendering

React ca. 75 min

Lernziele

  • Listen mit .map() rendern
  • Den key-Prop korrekt verwenden und verstehen warum er wichtig ist
  • Elemente bedingt rendern mit &&, Ternary und frühem Return
  • Status-Badges mit bedingtem Styling
  • .filter() und .sort() für Listenmanipulation
  • Leere Zustände (Empty States) anzeigen

Listen mit .map() rendern

In React rendert man Listen, indem man ein Array mit der .map()-Methode in ein Array von JSX-Elementen umwandelt. React kann Arrays von JSX-Elementen direkt rendern. Das key-Prop ist dabei Pflicht – es hilft React, die Elemente bei Änderungen effizient zu identifizieren.

Listen rendern – Grundlagen TypeScript 
// Einfaches Beispiel: Array von Strings
const staedte = ['Wien', 'Berlin', 'Paris'];

const Stadtliste = () => (
  <ul>
    {staedte.map((stadt) => (
      <li key={stadt}>{stadt}</li>
    ))}
  </ul>
);

// Mit Objekten: Immer eine eindeutige ID als key verwenden!
const FlightList = ({ flights }: { flights: Flight[] }) => (
  <tbody>
    {flights.map((flight) => (
      <FlightCard key={flight.id} flight={flight} />
    ))}
  </tbody>
);

// SCHLECHT: Index als key (nur wenn Liste sich nie ändert!)
{flights.map((flight, index) => (
  <FlightCard key={index} flight={flight} />  // Vermeiden bei dynamischen Listen
))}
⚠
Warum ist key so wichtig?

Beim Diffing-Algorithmus vergleicht React alte und neue Listen anhand der key-Props. Mit einem stabilen, eindeutigen key (z.B. ID aus der Datenbank) kann React genau feststellen: welches Element wurde hinzugefügt, entfernt oder verschoben? Ohne key oder mit dem Index als key bei dynamischen Listen kann React falsche DOM-Updates durchführen und internen State von Komponenten durcheinanderbringen.

Der key-Prop im Detail

Das folgende Diagramm verdeutlicht das Problem mit dem Index als key:

key-Prop: Index vs. ID TypeScript 
// Ausgangsliste:
// [OS123 (id:1), LH456 (id:2), BA234 (id:4)]
//  key=0           key=1           key=2           (mit Index als key)
//  key=1           key=2           key=4           (mit ID als key)

// Nach Löschen von LH456 (id:2):
// [OS123 (id:1), BA234 (id:4)]

// MIT INDEX ALS KEY (falsch):
// React sieht: key=0 gleich, key=1 ANDERS (jetzt BA234 statt LH456)
// React denkt: key=1 wurde geändert, key=2 wurde entfernt
// Problem: BA234 erbt State/Fokus von LH456!

// MIT ID ALS KEY (richtig):
// React sieht: key=1 gleich, key=2 wurde entfernt, key=4 gleich
// React weiß: LH456 wurde entfernt, alle anderen bleiben unverändert
// Korrekt: BA234 hat seinen eigenen State

// Fazit: Bei statischen Listen (Reihenfolge ändert sich nie) ist Index ok.
//        Bei dynamischen Listen (hinzufügen, löschen, sortieren) immer eine stabile ID nutzen!
ℹ
key ist kein normales Prop

key wird von React intern verwendet und ist in der Komponente selbst nicht zugänglich. Wenn du die ID innerhalb der Komponente benötigst, übergib sie zusätzlich als normales Prop: <FlightCard key={flight.id} id={flight.id} flight={flight} />

Conditional Rendering – Drei Patterns

React rendert bedingt, indem JavaScript-Ausdrücke direkt in JSX verwendet werden. Es gibt drei gängige Patterns – jedes hat seine Berechtigung:

Pattern 1: && Operator TypeScript 
// Wenn die Bedingung wahr ist, wird der rechte Teil gerendert.
// Wenn falsch, wird nichts gerendert (undefined/false wird von React ignoriert).

{flight.status === 'delayed' && (
  <span className="status-delayed">
    Verspätet: {flight.expectedTime} Uhr
  </span>
)}

{flight.gate && (
  <span>Gate: {flight.gate}</span>
)}

// ACHTUNG: Zahlen! 0 wird als "0" gerendert, nicht als nichts!
// FALSCH:
{flights.length && <span>{flights.length} Flüge</span>}
// Wenn flights.length === 0, wird "0" im DOM angezeigt!

// RICHTIG:
{flights.length > 0 && <span>{flights.length} Flüge</span>}
Pattern 2: Ternary Operator TypeScript 
// Bedingung ? WennWahr : WennFalsch
// Gut wenn es zwei alternative Darstellungen gibt.

{flight.gate ? (
  <span>Gate: {flight.gate}</span>
) : (
  <span className="text-muted">Kein Gate zugewiesen</span>
)}

// Mit CSS-Klassen statt Inline-Styles (Inline nur für dynamische Laufzeitwerte):
<td className={flight.status === 'cancelled' ? 'flight-number is-cancelled' : 'flight-number'}>
  {flight.flightNumber}
</td>

// Für den Zeitstempel:
<td>
  {flight.expectedTime && flight.expectedTime !== flight.scheduledTime
    ? `${flight.scheduledTime} \u2192 ${flight.expectedTime}`
    : flight.scheduledTime
  }
</td>
Pattern 3: Früher Return TypeScript 
// Für komplexere Logik: vor dem Haupt-JSX zurückkehren.
// Gut lesbar und vermeidet tief verschachtelte Bedingungen.

const FlightRow = ({ flight }: { flight: Flight }) => {
  // Annullierte Flüge bekommen eine spezielle Darstellung
  if (flight.status === 'cancelled') {
    return (
      <tr className="flight-row is-cancelled">
        <td colSpan={7} className="flight-cell flight-cancelled-note">
          {flight.flightNumber} – {flight.airline} – Annulliert
        </td>
      </tr>
    );
  }

  // Normaler Fall: vollständige Zeile
  return (
    <tr>
      {/* ... alle Spalten ... */}
    </tr>
  );
};

FlightStatusBadge – Vollständige Version

Mit dem Wissen über Conditional Rendering und TypeScript-Records bauen wir die FlightStatusBadge-Komponente nun vollständig aus. Ein zentrales Konfigurations-Objekt (Record<FlightStatus, StatusConfig>) macht den Code wartbar und typsicher.

src/components/FlightStatusBadge.tsx TypeScript 
import { FlightStatus } from '../types/flight';
import './FlightStatusBadge.css';

// Konfiguration für jeden Status
interface StatusConfig {
  label: string;
  className: string;
}

// Record sicherstellen: alle 6 Status-Werte MÜSSEN abgedeckt sein
const STATUS_CONFIG: Record<FlightStatus, StatusConfig> = {
  'on-time':   { label: 'Pünktlich', className: 'status-on-time' },
  'delayed':   { label: 'Verspätet', className: 'status-delayed' },
  'boarding':  { label: 'Boarding', className: 'status-boarding' },
  'departed':  { label: 'Abgeflogen', className: 'status-departed' },
  'landed':    { label: 'Gelandet', className: 'status-landed' },
  'cancelled': { label: 'Annulliert', className: 'status-cancelled' },
};

interface FlightStatusBadgeProps {
  status: FlightStatus;
}

const FlightStatusBadge = ({ status }: FlightStatusBadgeProps) => {
  const { label, className } = STATUS_CONFIG[status];
  return <span className={`status-pill ${className}`}>{label}</span>;
};

export default FlightStatusBadge;

Filter und Sortierung

JavaScript-Array-Methoden wie .filter() und .sort() eignen sich perfekt für die Transformation von Flugdaten vor dem Rendern. Wichtig: .sort() mutiert das Original-Array! Deshalb immer zuerst eine Kopie mit dem Spread-Operator erstellen.

Filter und Sortierung in FlightBoard TypeScript 
import { useState } from 'react';
import { Flight, FlightStatus } from '../types/flight';
import FlightCard from './FlightCard';

type StatusFilter = 'all' | FlightStatus;

interface FlightBoardProps {
  flights: Flight[];
  title: string;
}

const FlightBoard = ({ flights, title }: FlightBoardProps) => {
  const [statusFilter, setStatusFilter] = useState<StatusFilter>('all');

  // Verarbeitung: erst filtern, dann sortieren
  const processedFlights = [...flights]        // Kopie! .sort() mutiert das Original
    .filter(f => statusFilter === 'all' || f.status === statusFilter)
    .sort((a, b) => a.scheduledTime.localeCompare(b.scheduledTime));
    // Stringvergleich funktioniert für "HH:MM"-Format korrekt

  return (
    <section className="flight-board-section">
      <div className="status-filter-row">
        {(['all', 'on-time', 'delayed', 'boarding', 'cancelled'] as StatusFilter[]).map(f => (
          <button
            key={f}
            onClick={() => setStatusFilter(f)}
            className={statusFilter === f ? 'status-filter-btn is-active' : 'status-filter-btn'}
          >
            {f === 'all' ? 'Alle' : f}
          </button>
        ))}
      </div>

      <table className="flight-board-table">
        <tbody>
          {processedFlights.length === 0 ? (
            <tr>
              <td colSpan={7} className="flight-board-empty-cell">
                Keine Flüge in dieser Kategorie gefunden.
              </td>
            </tr>
          ) : (
            processedFlights.map(f => <FlightCard key={f.id} flight={f} />)
          )}
        </tbody>
      </table>
    </section>
  );
};

Empty States

Wenn eine Liste leer ist – z.B. weil kein Flug den aktiven Filter erfüllt – sollte die App eine hilfreiche Nachricht anzeigen statt einer leeren Tabelle. Das nennt sich Empty State. Ein guter Empty State erklärt warum die Liste leer ist und bietet Möglichkeiten zur Abhilfe.

Empty State Komponente TypeScript 
import './EmptyState.css';

interface EmptyStateProps {
  message?: string;
  onReset?: () => void;
}

/**
 * Zeigt einen leeren Zustand an, wenn keine Daten vorhanden sind.
 */
const EmptyState = ({
  message = 'Keine Flüge gefunden.',
  onReset,
}: EmptyStateProps) => (
  <div className="empty-state">
    <div className="empty-state-icon">✈</div>
    <p className="empty-state-message">{message}</p>
    {onReset && (
      <button onClick={onReset} className="empty-state-reset-btn">
        Filter zurücksetzen
      </button>
    )}
  </div>
);

Häufige Fehler

Fehler: key-Prop fehlt bei .map()

React gibt in der Browser-Konsole eine Warnung aus: "Each child in a list should have a unique ‘key’ prop." Ohne key fällt React auf langsame, fehleranfällige Heuristiken zurück.

Immer key={element.id} beim .map() setzen – TypeScript prüft das nicht automatisch.

Fehler: Index als key bei dynamischen Listen

key={index} ist nur sicher wenn die Liste statisch ist. Sobald Elemente hinzugefügt, gelöscht oder umsortiert werden, führt der Index-als-Key zu falschen Updates und kann internen Komponenten-State korrumpieren.

Bei dynamischen Listen immer eine stabile, eindeutige ID aus den Daten verwenden.

Fehler: && mit dem Wert 0

{flights.length && <span>...</span>} rendert den Wert 0 ins DOM, wenn flights.length === 0 ist. JavaScript wertet 0 && anything als 0 aus (kein leerer Wert!), und React rendert Zahlen direkt.

Expliziten Vergleich verwenden: {flights.length > 0 && ...} oder Ternary: {flights.length ? ... : null}

Fehler: Original-Array mit .sort() mutieren

flights.sort(...) sortiert das Array in-place – das bedeutet, das ursprüngliche Props-Array wird verändert. Das ist eine unerlaubte Mutation und kann zu unerwartetem Verhalten führen.

Vor .sort() immer eine Kopie erstellen: [...flights].sort(...)
