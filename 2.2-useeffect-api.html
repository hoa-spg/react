Was ist useEffect?

useEffect ist der Hook für Seiteneffekte (engl. Side Effects) in React-Komponenten. Ein Seiteneffekt ist alles, was über das reine Berechnen und Rendern von JSX hinausgeht: Daten vom Server laden, Timer setzen, Event-Listener registrieren, den Dokumenttitel ändern oder direkt auf das DOM zugreifen.

useEffect läuft nach dem Rendern der Komponente. React rendert zuerst die Komponente, aktualisiert das DOM, und führt dann die Effect-Funktion aus.

useEffect – Drei Varianten TypeScript 
import { useState, useEffect } from 'react';

const BeispielKomponente = () => {
  const [count, setCount] = useState(0);

  // --- Variante 1: Kein Abhängigkeiten-Array ---
  // Läuft nach JEDEM Render (sehr selten gewünscht)
  useEffect(() => {
    console.log('Komponente wurde gerendert, count =', count);
  });

  // --- Variante 2: Leeres Abhängigkeiten-Array ---
  // Läuft NUR beim ersten Render (Mount)
  // Typisch für: initiale Daten laden, globale Event-Listener
  useEffect(() => {
    console.log('Komponente wurde gemountet');
    // Hier: Daten vom Server laden
  }, []);

  // --- Variante 3: Array mit Abhängigkeiten ---
  // Läuft beim Mount UND immer wenn sich count ändert
  useEffect(() => {
    console.log('count hat sich geändert:', count);
    document.title = `FlugBoard (${count} Flüge)`;
  }, [count]); // count ist die Abhängigkeit

  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
};
ℹ
Mount, Update, Unmount

Jede Komponente durchläuft drei Phasen: Mount (erste Anzeige im DOM), Update (Re-render bei State- oder Prop-Änderung) und Unmount (Entfernen aus dem DOM). useEffect läuft je nach Abhängigkeiten-Array nach Mount und/oder Update. Die Cleanup-Funktion läuft vor dem nächsten Effect-Aufruf und beim Unmount.

Das Abhängigkeiten-Array

Das zweite Argument von useEffect ist das Abhängigkeiten-Array. React vergleicht die Werte bei jedem Render mit den vorherigen Werten. Hat sich mindestens ein Wert geändert, wird der Effect erneut ausgeführt.

Abhängigkeiten korrekt angeben TypeScript 
const [searchQuery, setSearchQuery] = useState('');
const [page, setPage]               = useState(1);

// RICHTIG: Alle im Effect verwendeten Variablen im Array angeben
useEffect(() => {
  console.log('Suche nach:', searchQuery, 'auf Seite:', page);
  // fetch(`/api/flights?q=${searchQuery}&page=${page}`)...
}, [searchQuery, page]);  // Beide Variablen sind Abhängigkeiten

// FALSCH: Abhängigkeit vergessen (stale closure!)
useEffect(() => {
  // searchQuery wird hier verwendet, aber fehlt im Array!
  // Der Effect liest immer den Initialwert von searchQuery (leerer String)
  console.log(searchQuery);
}, []);  // searchQuery fehlt!

// FALSCH: Objekte/Funktionen direkt im Array
// Objekte werden bei jedem Render neu erstellt (neue Referenz)
// → Effect läuft nach jedem Render!
useEffect(() => {
  // ...
}, [{ key: 'value' }]);  // Neues Objekt bei jedem Render!

// RICHTIG: Primitive Werte oder stabile Referenzen im Array
useEffect(() => {
  // ...
}, [flight.id, flight.status]);  // Primitive: sicher!
⚠
ESLint-Plugin für Hooks

Das NPM-Paket eslint-plugin-react-hooks prüft automatisch, ob alle im Effect verwendeten Variablen im Abhängigkeiten-Array stehen. Vite-Projekte mit React enthalten dieses Plugin oft bereits. Die Regel react-hooks/exhaustive-deps ist dabei besonders hilfreich um stale closures zu vermeiden.

Cleanup-Funktionen

Viele Seiteneffekte müssen „aufgeräumt“ werden, wenn die Komponente unmountet oder bevor der Effect erneut läuft. Typische Fälle: Timer stoppen, Event-Listener entfernen, laufende Netzwerkanfragen abbrechen. Die Cleanup-Funktion wird durch den Rückgabewert von useEffect definiert.

Cleanup mit setInterval TypeScript 
import { useState, useEffect } from 'react';

const LiveClock = () => {
  const [currentTime, setCurrentTime] = useState(
    new Date().toLocaleTimeString('de-AT')
  );

  useEffect(() => {
    // Effect starten: Uhrzeit jede Sekunde aktualisieren
    const intervalId = setInterval(() => {
      setCurrentTime(new Date().toLocaleTimeString('de-AT'));
    }, 1000);

    // Cleanup-Funktion: wird aufgerufen
    // (a) bevor die Komponente unmountet
    // (b) bevor der Effect erneut läuft (falls Abhängigkeiten sich ändern)
    return () => {
      clearInterval(intervalId);
      console.log('Interval wurde gestoppt');
    };
  }, []); // Nur beim Mount starten

  return <span>{currentTime}</span>;
};
Cleanup bei Event-Listener TypeScript 
useEffect(() => {
  // Tastaturkürzel global registrieren
  const handleKeyDown = (e: KeyboardEvent) => {
    if (e.key === 'Escape') {

backend/main.ts TypeScript 
// Hono und CORS-Middleware aus dem npm-Registry importieren
import { Hono } from 'npm:hono';
import { cors } from 'npm:hono/cors';
import { flights } from './data.ts';

const app = new Hono();

// CORS aktivieren: erlaubt Anfragen vom Frontend (localhost:5173)
// Ohne CORS: Browser blockiert Anfragen von unterschiedlichen Origins
app.use('*', cors({
  origin: 'http://localhost:5173',
}));

// GET /api/flights – alle Flüge, optional gefiltert
app.get('/api/flights', (c) => {
  const type   = c.req.query('type');    // z.B. ?type=departure
  const status = c.req.query('status');  // z.B. ?status=delayed

  let result = [...flights];

  if (type)   result = result.filter(f => f.type === type);
  if (status) result = result.filter(f => f.status === status);

  return c.json(result);
});

// GET /api/flights/:id – einzelner Flug nach ID
app.get('/api/flights/:id', (c) => {
  const id     = Number(c.req.param('id'));
  const flight = flights.find(f => f.id === id);

  if (!flight) {
    return c.json({ error: 'Flug nicht gefunden' }, 404);
  }

  return c.json(flight);
});

// Server starten auf Port 8000
Deno.serve({ port: 8000 }, app.fetch);
console.log('FlugBoard API läuft auf http://localhost:8000');

Warum CORS?

Browser verbieten aus Sicherheitsgründen Anfragen von einer Origin (z.B. http://localhost:5173) an eine andere Origin (z.B. http://localhost:8000). Das nennt sich Same-Origin Policy. CORS (Cross-Origin Resource Sharing) ist der Mechanismus, mit dem der Server dem Browser explizit erlaubt, Anfragen von anderen Origins anzunehmen.

Daten laden mit useEffect und fetch

Das typische Pattern für Datenabruf in React: drei State-Variablen (data, isLoading, error) und ein useEffect mit leerem Abhängigkeiten-Array, der beim Mount ausgeführt wird. Achtung: useEffect kann keine asynchrone Funktion direkt sein – deshalb definieren wir eine innere async-Funktion und rufen sie sofort auf.

src/App.tsx – Daten vom Backend laden TypeScript 
import { useState, useEffect } from 'react';
import { Flight } from './types/flight';
import FlightBoard from './components/FlightBoard';

const API_URL = 'http://localhost:8000';

function App() {
  const [flights, setFlights]     = useState<Flight[]>([]);
  const [isLoading, setIsLoading] = useState<boolean>(true);
  const [error, setError]         = useState<string | null>(null);

  useEffect(() => {
    // ACHTUNG: useEffect-Callback darf nicht async sein!
    // Lösung: innere async-Funktion definieren und sofort aufrufen
    const fetchFlights = async () => {
      try {
        setIsLoading(true);
        setError(null);

        const response = await fetch(`${API_URL}/api/flights`);

        // HTTP-Fehler (z.B. 404, 500) werfen keinen Fehler – prüfen!
        if (!response.ok) {
          throw new Error(`HTTP-Fehler ${response.status}: ${response.statusText}`);
        }

        const data: Flight[] = await response.json();
        setFlights(data);
      } catch (err) {
        // Fehler in State speichern zur Anzeige für den Nutzer
        setError(err instanceof Error ? err.message : 'Unbekannter Fehler');
      } finally {
        // finally: wird immer ausgeführt, auch bei Fehler
        setIsLoading(false);
      }
    };

    fetchFlights();
  }, []); // Nur beim ersten Render ausführen

  // Fehler-Zustand
  if (error) {
    return (
      <div className="status-screen status-screen-error">
        <p className="error-text">Fehler beim Laden: {error}</p>
        <button
          onClick={() => window.location.reload()}
          className="retry-btn"
        >
          Neu laden
        </button>
      </div>
    );
  }

  // Normaler Zustand
  return (
    <div className="app-page">
      <h1 className="app-title">✈ FlugBoard</h1>
      {isLoading ? (
        <div className="board-loading board-loading--muted">
          <div className="status-icon">✈</div>
          <p>Flugdaten werden geladen...</p>
        </div>
      ) : (
        <>
          <FlightBoard
            flights={flights.filter(f => f.type === 'departure')}
            title="Abflüge"
          />
          <FlightBoard
            flights={flights.filter(f => f.type === 'arrival')}
            title="Ankünfte"
          />
        </>
      )}
    </div>
  );
}

export default App;

Hinweis zu axios

In diesem Kurs verwenden wir bewusst die native fetch-API, weil sie ohne zusätzliche Bibliothek in Browser, Next.js und React Native verfügbar ist.

axios ist trotzdem wichtig zu kennen: Es bietet eine komfortable API, automatische JSON-Transformation und konsistentes Fehlerverhalten. Bei fetch gilt ein HTTP-404/500 nicht automatisch als Exception, bei axios landet das direkt im catch-Block. Außerdem bringt axios Features wie Request-/Response-Interceptors mit, z.B. für zentrale Auth-Header, Logging oder Error-Mapping.

Weitere Vorteile sind globale Defaults (Base-URL, Timeouts), einheitliches Verhalten in älteren Umgebungen und oft etwas weniger Boilerplate bei größeren API-Schichten. Für kleine bis mittlere Frontends reicht fetch aber in der Regel völlig aus, ist Standard-nah und spart eine externe Abhängigkeit. Deshalb lernen wir hier zuerst fetch und können später bei Bedarf gezielt auf axios wechseln.

AbortController – Fetch sauber abbrechen

In React (StrictMode) wird jeder Effect zweimal ausgeführt: einmal gemountet, einmal unmountet, einmal wieder gemountet. Ohne Cleanup könnte ein veralteter Fetch-Request nach dem Unmount noch State aktualisieren – das führt zu einem React-Warning: "Can't perform a React state update on an unmounted component." Die Lösung: AbortController.

Fetch mit AbortController TypeScript 
useEffect(() => {
  // AbortController erstellen
  const controller = new AbortController();

  const fetchFlights = async () => {
    try {
      setIsLoading(true);
      const response = await fetch(`${API_URL}/api/flights`, {
        signal: controller.signal,   // Signal an fetch übergeben
      });

      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      const data: Flight[] = await response.json();
      setFlights(data);
    } catch (err) {
      // AbortError ignorieren – das ist kein echter Fehler, sondern Cleanup
      if (err instanceof Error && err.name === 'AbortError') {
        console.log('Fetch wurde abgebrochen (Cleanup)');
        return;
      }
      setError(err instanceof Error ? err.message : 'Fehler');
    } finally {
      setIsLoading(false);
    }
  };

  fetchFlights();

  // Cleanup: Fetch abbrechen wenn Komponente unmountet oder Effect erneut läuft
  return () => {
    controller.abort();
  };
}, []);

Automatisches Polling

Fluganzeigetafeln müssen regelmäßig aktualisiert werden. Wir können setInterval innerhalb von useEffect verwenden, um die Daten periodisch neu zu laden. Das Cleanup-Muster stellt sicher, dass das Interval gestoppt wird wenn die Komponente nicht mehr angezeigt wird.

Polling alle 30 Sekunden TypeScript 
const [lastUpdated, setLastUpdated] = useState<Date | null>(null);
const [isRefreshing, setIsRefreshing] = useState(false);

// Separate Ladefunktion (wiederverwendbar für manuelles Aktualisieren)
const fetchFlights = async (signal?: AbortSignal) => {
  try {
    setIsRefreshing(true);
    const response = await fetch(`${API_URL}/api/flights`, { signal });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data: Flight[] = await response.json();
    setFlights(data);
    setLastUpdated(new Date());
  } catch (err) {
    if (err instanceof Error && err.name !== 'AbortError') {
      setError(err.message);
    }
  } finally {
    setIsRefreshing(false);
  }
};

useEffect(() => {
  const controller = new AbortController();

  // Sofort beim Mount laden
  fetchFlights(controller.signal);

  // Danach alle 30 Sekunden neu laden
  const intervalId = setInterval(() => {
    fetchFlights(controller.signal);
  }, 30_000);  // 30 Sekunden = 30.000 Millisekunden

  // Cleanup: Interval stoppen und laufenden Fetch abbrechen
  return () => {
    clearInterval(intervalId);
    controller.abort();
  };
}, []);  // Einmalig beim Mount starten

// In JSX: Letztes Update anzeigen
{lastUpdated && (
  <p style={{ color: '#8b949e', fontSize: '0.8rem' }}>
    Zuletzt aktualisiert: {lastUpdated.toLocaleTimeString('de-AT')}
    {isRefreshing && ' (wird aktualisiert...)'}
  </p>
)}

Häufige Fehler

Fehler: Abhängigkeiten vergessen – Stale Closure

Wenn eine Variable im Effect verwendet wird, aber nicht im Abhängigkeiten-Array steht, liest der Effect immer den Wert aus dem ersten Render – eine veraltete Closure. Das ESLint-Plugin react-hooks/exhaustive-deps warnt davor.

Alle im Effect verwendeten State-Variablen und Props ins Abhängigkeiten-Array schreiben.

Fehler: State im Effect ohne Abhängigkeiten – Endlosschleife

useEffect(() => { setCount(count + 1); }) ohne Abhängigkeiten-Array: Effect läuft nach jedem Render → State ändert sich → Re-render → Effect läuft wieder → Endlosschleife. Die App friert ein.

Immer ein Abhängigkeiten-Array angeben. Bei einmaliger Ausführung: [].

Fehler: CORS-Fehler im Browser

"Access to fetch at 'http://localhost:8000' from origin 'http://localhost:5173' has been blocked by CORS policy." – Das Backend gibt keine CORS-Header zurück. Der Browser blockiert die Antwort.

Im Hono-Backend app.use('*', cors()) aktivieren und die erlaubte Origin korrekt konfigurieren.

Fehler: async direkt als useEffect-Callback

useEffect(async () => {...}, []) ist nicht erlaubt. Ein asynchroner useEffect-Callback würde ein Promise zurückgeben, aber React erwartet entweder nichts oder eine Cleanup-Funktion als Rückgabewert.

Innere async-Funktion definieren und sofort aufrufen: const load = async () => {...}; load();
